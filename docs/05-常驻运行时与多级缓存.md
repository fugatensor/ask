# 05. 常驻运行时与多级缓存

返回核心思想：[常驻运行时与缓存](核心思想.md#ask-runtime-cache) · 相关细节：[外部产物与执行接口](04-外部产物与执行接口.md) · [图优化与自有代码生成](03-图优化与自有代码生成.md) · [FugaTensor 多后端执行](../../fugatensor/docs/architecture/04-ASK桥接与多后端执行.md)

ASK 的 `ASK::Runtime` 负责原生计划、设备缓冲区、stream、完成事件与 Graph replay。Python 用户 API、张量描述符解析、外部 Python 对象保活及磁盘编译缓存位于 FugaTensor；ASK 仓库没有 Python 运行时层。

<a id="execution-session"></a>

## 1. 动态驱动加载与常驻 Session

C++ 接口位于 [CUDA.h](../include/ask/Runtime/CUDA.h)，实现位于 `lib/Runtime/CUDA.cpp`。构建期不依赖 CUDA Toolkit 头文件或 `libcudart.so`；创建 `Session` 时才动态加载 `libcuda.so.1`。

`Session::create(device)` 保留目标设备的 primary context 并创建非阻塞 stream。每次驱动操作建立当前线程的 context，运行时不重置设备 primary context。会话对驱动状态加互斥锁，允许多个宿主线程安全提交。

`Session::load` 接收 cubin/PTX 字节、入口、架构和参数宽度，检查目标设备与 kernel 资源限制。同一会话按产物内容和入口复用已加载模块。PTX 在首次加载时由驱动编译；加载已有 cubin 不需要 `llc` / `ptxas`。

C++ 调用示例见[原生会话与计划执行](用户API.md#execution-api)。

<a id="device-tensor-and-cai"></a>

## 2. 原生缓冲区与外部存储

`Session::allocate(nbytes)` 返回自有 `DeviceBuffer`，`importBuffer(pointer, nbytes, readonly)` 借用已有设备内存。空缓冲区有有效句柄但逻辑长度为零。原生层记录设备归属、长度和只读状态，不负责解释上层 Python Tensor。

`DeviceBuffer::copyFromHost(pointer, nbytes)` 和 `copyToHost(pointer, nbytes)` 批量拷贝连续内存；另有返回字节字符串的 `copyToHost()`。长度须完全匹配，拷贝返回前等待会话 stream 完成，不进行 dtype 或字节序转换。

外部内存的所有者必须在 GPU 使用结束前存活。C++ `DeviceBuffer` 不拥有借用的分配，调用方须保留其实际所有者。FugaTensor 在自己的绑定层解析 CUDA Array Interface、检查 shape/dtype/连续性、保留 Python 所有者，并调用 `waitForExternalStream` 建立生产者流依赖。CAI 的 `bf16` 与 DLPack 支持边界由该调用方接口说明。

如果外部生产者之后还要访问同一存储，需要等待 ASK 返回的完成事件或建立等价 stream 依赖；零拷贝本身不消除同步要求。

<a id="async-events"></a>

## 3. 整计划提交、资源保活与复用

`Session::prepareProgram(bufferSizes, inputs, outputs, steps, graph)` 固定缓冲区索引、物理参数、标量字节与启动配置，返回 `PreparedProgram`。调用方在准备前核对张量 shape/dtype 和编译包；原生层验证步骤引用、数据依赖及 kernel ABI。

每次执行只调用一次 `PreparedProgram::submit(inputs, outputs)`，或使用 `run(inputs)` 由运行时分配输出。C++ 先检查所有公开端口的设备、字节数、可写性和别名，再绑定中间缓冲区并提交全部步骤。整个计划记录一个完成事件，事件覆盖全部缓冲区、kernel 和工作区。

- 每个在途调用占用独立工作区。完成后才能复用中间存储，不能覆盖此前仍在执行的任务。
- 已释放且不再用于在途任务的自有分配进入会话缓存；仍由用户持有的结果不被后续调用覆盖。
- 完成事件的原生句柄可以复用，旧 `Event` 对象保留已完成状态，不会被下一次提交重新变为未完成。
- `Event::query` 不等待；`wait`、`Session::synchronize` 和主机拷贝显式等待。会话关闭时先完成在途工作，再清理持有资源。
- 单 kernel 和多 kernel 使用相同计划机制。若实际启动失败前已有步骤排队，先确保其资源安全再传播错误；运行时不提供 GPU 事务回滚。

资源通过显式查询、等待及会话操作回收，没有后台回收线程。原生事件只负责 C++ 资源；FugaTensor 的薄绑定另行保留外部 Python 所有者直到完成。

<a id="cuda-graph"></a>

## 4. CUDA Graph replay

`prepareProgram(..., graph=true)` 使用 CUDA Graph，`false` 使用 C++ 顺序启动。两者共用同一份端口、参数和资源校验，不改变图优化或第三方代码边界。

每个工作区首次执行时创建并实例化 graph；后续复用更新节点的输入输出地址，再调用 `cuGraphLaunch`。在途调用使用不同实例，完成前不会修改此前执行的节点参数。拓扑、kernel、形状、启动配置和冻结标量不变，公开端口地址可以变化。

零步骤别名计划只记录 stream 完成事件，不创建空 graph。驱动缺少所需 Graph API，或实例化、更新、启动失败时直接报错，不静默切换执行路径。

`Session::stats()` 提供 `program_submissions`、`workspace_reuses`、`allocation_reuses`、`event_creations/event_reuses`、`graph_instantiations/graph_launches` 等计数。`launches` 表示计划中提交的 kernel 数，Graph 提交次数另行统计。FugaTensor 的 CUDA JIT 通过自己的原生桥使用 graph 模式。

<a id="two-tier-cache"></a>

## 5. 调用方编译缓存与原生运行时缓存

ASK C++ 库不实现 Python 文件缓存编排。FugaTensor 的私有 `_ask` 接入层维护以下持久缓存，并将验证后的字节和计划交给 ASK：

| 缓存 | 命中时跳过 | 键的主要输入 |
| --- | --- | --- |
| 自有 LLVM IR | 图优化与 CUDA LLVM 降级 | 图文本、形状、编译库身份、目标/选项与编排实现摘要 |
| 自有 cubin | `llc` 与 `ptxas` | LLVM IR、产物契约、工具及环境摘要 |
| 外部产物 | Worker 编译 | 标准化请求、probe 结果、worker/解释器、依赖与环境摘要 |

外部缓存保存 cubin 或原始 PTX，不要求 LLVM IR；查找前探测生产者身份，编译后再次核对依赖。缓存使用锁、临时目录和原子发布，读取时检查清单、长度和 SHA-256。具体实现与失效规则见[FugaTensor 缓存分工](../../fugatensor/docs/architecture/04-ASK桥接与多后端执行.md#cache-hierarchy)及[worker 身份契约](09-外部编译器适配接入规范.md#cache-identity)。

ASK 原生会话中的模块、工作区、显存和事件缓存只影响执行资源复用，不写入磁盘编译包，也不重新调用第三方 worker。
