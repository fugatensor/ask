# 06. 工程结构与测试体系

返回核心思想：[验证方法与演进边界](核心思想.md#ask-testing-roadmap) · 相关细节：[前端接入与构建配置](02-前端接入与构建配置.md) · [ASK IR 与数值语义](01-ASK-IR与数值语义.md) · [外部编译器适配与边界内联](04-外部编译器适配与边界内联.md)

本章梳理 ASK 仓库的目录分工、5 个 CTest 测试集的覆盖边界，以及为什么我们能用少量精炼测试同时覆盖 6 种精度、6×6 类型转换和三条执行后端。

<a id="repo-layout"></a>

## 1. 仓库目录结构

```text
ask/
├── CMakeLists.txt / CMakePresets.json / pyproject.toml
├── cmake/                  # LLVM / nanobind 锁文件、可选适配器白名单与 CMake 包导出模板
├── tools/
│   ├── fetch_deps.py       # 统一拉取与校验锁定版 LLVM/MLIR SDK 和 nanobind 源码
│   └── ask-opt.cpp         # 原生命令行编译驱动
├── include/ask/            # 公共 C++ 头文件（IR、Frontend、Transforms、Lowering、LLIR、Adapters、Runtime）
├── lib/                    # 公共 C++ 实现（ask_core、ask_compilers、ask_runtime）
├── bindings/               # nanobind 进程内 Python 扩展（ask._native：编译器桥接与常驻 CUDA 会话）
├── python/ask/             # Python SDK（IR 构造器、Compiler、双层缓存驱动、运行时封装）
├── adapters/
│   ├── registry.json       # 允许构建的第三方编译器显式名录
│   └── triton/             # Triton 3.7.1 适配器（worker、AST/标记融合、C++ 边界校验与专属测试）
├── examples/               # Python 与独立 C++ 接入示例
├── tests/                  # 单元测试、硬件 GPU 测试、IR 夹具与共享数值参考库
└── docs/                   # 双向互链架构与工程文档
```

> [!NOTE]
> `.deps/`（第三方 SDK 与源码包）、`build/`（CMake 与 wheel 构建目录）和各类缓存均由 `.gitignore` 排除在版本库之外，仅通过 `cmake/*.lock.json`、`adapters/*/dependencies.lock.json` 与 `tools/fetch_deps.py` 保持 100% 可复现。

## 2. 五个 CTest 测试集与运行方式

执行 `ctest --preset core`（4 个测试集）或 `ctest --preset all`（全部 5 个测试集）时，CTest 按职责运行以下目标：

| CTest 名称 | 入口位置 | 覆盖范围 |
| --- | --- | --- |
| `ask-compiler-adapter` | `tests/cpp/test_compiler_adapter.cpp` | C++ `CompilerAdapter` 注册表、显式白名单隔离与未知编译器拒绝。 |
| `ask-boundary-inline` | `tests/cpp/test_boundary_inline.cpp` | C++ 通用 LLVM 值边界内联核心（多参数、多站点、定长向量、非法 helper 与支配违规原子回滚）。 |
| `ask-unit` | `tests/test_*.py`（7 个模块） | 纯 CPU 快速测试集（约 4~5 秒）：SDK 与单步 RNE 常量、`ask` IR 正反例校验与高层图优化、Host CPU 代码生成执行、自有 CUDA 降级与启动契约离线校验、缓存并发/损坏恢复与 CAI 描述符校验、6 种精度极限边界参考值，以及 `fetch_deps.py` 安全解压与 CMake 白名单测试。 |
| `ask-gpu` | `tests/gpu/test_gpu_*.py`（2 个模块） | 真实 NVIDIA GPU 硬件测试（无驱动/无 `ptxas` 时自动优雅跳过）：`test_gpu_native.py` 验证自有 CUDA 全精度、6×6 转换、异构多端口、ABI v2 共享内存、20 次零拷贝热启动与并发流提交；`test_gpu_triton.py`（在启用 `triton` 的构建中）验证 `ASK → Triton → ASK` 硬件融合、FMA 开关隔离、双层缓存命中与跨会话 `__cuda_array_interface__` 串联。 |
| `ask-triton` | `adapters/triton/tests/test_*.py`（4 个模块） | 仅在启用 `triton` 适配器时注册：检验 `worker.py` 导出协议、AST 静态融合合法性判定、Python 策略与旧产物迁移，以及不依赖物理 GPU 的 `ask-opt --fuse-external` 端到端 LLVM 融合与防篡改校验。 |

日常只跑某一组 Python 测试也很简单：

```bash
# 快速运行全部 CPU 单元测试
PYTHONPATH=build/core/python:python:tests ASK_OPT=build/core/bin/ask-opt \
  ASK_BOUNDARY_INLINE_BIN=build/core/ask-boundary-inline-test \
  python3 -m unittest discover -s tests -p "test_*.py" -v

# 单独运行 GPU 硬件测试（core 测自有 CUDA，all 同时测自有 CUDA + Triton 融合）
ctest --preset all -R ask-gpu --output-on-failure
```

注意 `tests/gpu/` 故意不放置 `__init__.py`，这样顶层 `unittest discover -s tests` 只会发现 7 个秒级完成的 CPU 单测模块，把耗时的真实硬件编译清晰留给 `ask-gpu`。

## 3. 共享多精度测试矩阵与独立数值参考

为了防止测试代码膨胀成成千上万行复制粘贴的样板，同时又不漏掉低精度舍入和大整数高位截断问题，`tests/support/` 提供了两块共用基石：

1. **独立精确数值参考（`tests/support/pointwise.py`）**：
   - 不用 `float32` 或 NumPy 去“近似比对”，而是直接用 Python 任意精度整数实现 IEEE-754 单步最近偶数舍入（RNE）、次正规数（subnormal）sticky bit、`fma` 单次舍入对比、32/64 位二补数回绕以及饱和 `cast_reference`。
   - 测试样本专门覆盖 `2**60 + k`（暴露 `float64` 53 位尾数丢失）、`f16`/`bf16` 半 ULP 偶数舍入边界、`-0.0`、`±inf`、`NaN` 以及非整块尾元素（如 `size = 129`）。
2. **正交去重矩阵规划器（`plan_matrix`）**：
   - 同一套图拓扑定义（多维形状、多标记站点、`F` 开启/关闭浮点收缩、混合精度 `f32` 中间累加等）在 Host CPU、自有 CUDA 和 Triton 融合测试间直接复用，按 dtype 与图拓扑正交去重，以最小子进程开销覆盖完整的类型和融合边界。
