## 1. 目录职责

```text
ask/
├── include/ask/           # 编译门面、MLIR/LLVM 与原生 Runtime 公共接口
├── lib/
│   ├── IR/               # ask dialect 与操作校验
│   ├── Frontend/         # 准备、能力报告、图切分及编译门面
│   ├── Transforms/       # 折叠、DCE、自有逐元素融合
│   ├── Lowering/         # 自有 Host/CUDA LLVM 降级
│   ├── LLIR/             # LLVM 导入、清理与数值辅助
│   └── Runtime/          # CUDA 计划、缓冲区、事件及 Graph replay
├── schemas/              # 执行计划与外部请求/响应 JSON 契约
├── cmake/                # LLVM 锁、组件导出与安装配置
├── tools/                # ask-opt、依赖获取与工程检查
├── tests/ir/             # CLI 与前端测试使用的 MLIR 输入
├── tests/cpp/            # Compiler/Core/Runtime 断言与独立 SDK 消费测试
└── docs/                 # 接口、设计与工程说明
```

ASK 提供 C++ SDK；Python 用户接口和 nanobind 绑定由 FugaTensor 提供。FugaTensor 的 `cpp/` 绑定直接链接 ASK；图转换、通用 worker 调用、磁盘缓存和编译包校验位于 `src/fugatensor/_ask/`，第三方专属 worker 也由调用方维护。

`.deps/`、`build/`、`dist/`、虚拟环境和缓存不进入版本库；保留 `cmake/*.lock.json` 与依赖获取脚本。

## 2. 原生 CTest

`ctest --preset core --output-on-failure` 默认运行 CPU 原生检查；硬件测试须显式启用。测试使用断言检验行为，不作为用户示例。接口用法单独写在[用户 API 文档](用户API.md)中。

| CTest 名称 | 入口 | 覆盖范围 |
| --- | --- | --- |
| `ask-core` | `tests/cpp/frontend.cpp` | Core 的静态图准备、形状与优化。 |
| `ask-compiler` | `tests/cpp/compiler.cpp` | 标准 C++ 编译门面、Host/CUDA 代码生成、非法输入拒绝、数值字面量和独立并发上下文。 |
| `ask-runtime` | `tests/cpp/runtime.cpp` | 物理 GPU 上的多步骤 PTX 执行、变动输入、工作区与 Graph 实例复用；仅 `ASK_TEST_CUDA=ON` 时注册。 |

```bash
cmake --preset core
cmake --build --preset core
ctest --preset core --output-on-failure

# 有兼容 GPU 的环境中额外执行。
cmake --preset core -DASK_TEST_CUDA=ON
cmake --build --preset core
ctest --preset core -R '^ask-runtime$' --output-on-failure
```

默认关闭 GPU 测试不代表设备执行已验证。启用后需要真实驱动与设备，失败必须报告，不以缺少环境作为成功跳过。

## 3. FugaTensor 接入与端到端验证

推荐以 [FugaTensor](../../fugatensor/README.md) 作为 ASK 的完整接入示例。它从 [Tensor API](../../fugatensor/docs/API/README.md) 自动组图，在独立 Fuga IR 中求导，再经[原生绑定与执行层](../../fugatensor/docs/architecture/ASK桥接与多后端执行.md)提交 ASK 编译和调度。

端到端测试验证这一接入路径的图语义、产物缓存、CPU/CUDA 数值、外部 kernel 和多步骤计划。基础 API 从算子注册表生成组合，与精度和求导阶数正交交叉；运行范围与筛选方式见 [FugaTensor 测试矩阵](../../fugatensor/docs/测试.md)。

独立数值参考使用 Python 任意精度整数覆盖单步 RNE、次正规数、整数回绕、饱和转换、大整数、负零、无穷、NaN 和非整块尾元素。新增数值组合优先复用该参考和 `plan_matrix`，不要复制一套逐元素预期值实现。外部算法公式由生产者测试，ASK 侧着重核验 ABI、资源寿命与步骤连接。

## 4. SDK 分发验证

原生分发检查应包含：配置构建、默认 CTest、安装到独立前缀，以及从安装目录消费 Compiler、Runtime、Core 三类组件。Compiler/Runtime 消费工程不应要求 LLVM/MLIR 开发 SDK；Core 必须使用与 ASK 实际构建版本匹配的 LLVM/MLIR SDK。

```bash
cmake --install build/core --prefix /path/to/ask-sdk
cmake -S tests/cpp -B /path/to/runtime-consumer -G Ninja \
  -DCMAKE_PREFIX_PATH=/path/to/ask-sdk -DASK_TEST_COMPONENT=Runtime
cmake --build /path/to/runtime-consumer
```

`ASK_TEST_COMPONENT` 可选 `Compiler`（默认）、`Runtime` 或 `Core`。Runtime 的构建检查不需要 GPU，执行该测试才需要设备；Core 需另外提供匹配的 LLVM SDK。FugaTensor wheel 的绑定、共享库打包与隔离安装由调用方验证；ASK 交付 C++ SDK。实际通过状态以相应 CPU、GPU 和独立安装运行记录为准。
