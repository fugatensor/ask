# 常驻运行时与多级缓存

`ASK::Runtime` 管理执行计划、设备缓冲区、stream、完成事件和 Graph replay。FugaTensor 负责 Python API、张量描述符、外部 Python 对象的寿命及磁盘编译缓存。

<a id="execution-session"></a>

## 1. 动态驱动加载与常驻 Session

C++ 接口位于 [CUDA.h](../include/ask/Runtime/CUDA.h)，实现位于 `lib/Runtime/CUDA.cpp`。创建 `Session` 时动态加载驱动库 `libcuda.so.1`。

`Session::create(device)` 保留目标设备原有的 primary context，并创建非阻塞 stream。每次驱动操作设置当前线程的 context；会话用互斥锁保护驱动状态，支持多个宿主线程提交。

`Session::load` 接收 cubin/PTX 字节、入口、架构和参数宽度，检查目标设备与 kernel 资源限制。同一会话按产物内容和入口复用模块。PTX 首次加载时由驱动编译，cubin 则直接加载。

C++ 调用示例见[原生会话与计划执行](用户API.md#execution-api)。

<a id="device-tensor-and-cai"></a>

## 2. 原生缓冲区与外部存储

`Session::allocate(nbytes)` 返回自有 `DeviceBuffer`，`importBuffer(pointer, nbytes, readonly)` 借用已有设备内存。缓冲区记录设备、字节数和只读状态；空缓冲区也有有效句柄，长度为零。

`DeviceBuffer::copyFromHost(pointer, nbytes)` 和 `copyToHost(pointer, nbytes)` 批量拷贝连续内存；另有返回字节字符串的 `copyToHost()`。拷贝按原始字节进行，长度须完全匹配，返回前等待会话 stream 完成。

借用外部内存时，调用方须保留实际存储所有者，直到 GPU 使用结束。FugaTensor 的绑定层负责解析 CUDA Array Interface、检查 shape/dtype/连续性、保留 Python 所有者，并调用 `waitForExternalStream` 等待生产者 stream。交换接口见 [FugaTensor 张量与数据交换](../../fugatensor/docs/API/张量与数据交换.md)。

外部生产者再次访问同一存储前，须等待 ASK 的完成事件或建立等价 stream 依赖。

<a id="async-events"></a>

## 3. 整计划提交、资源保活与复用

`Session::prepareProgram(bufferSizes, inputs, outputs, steps, graph)` 固定缓冲区索引、物理参数、标量字节与启动配置，返回 `PreparedProgram`。调用方在准备前核对张量 shape/dtype 和编译包；原生层验证步骤引用与 kernel ABI，[ASK PASS](规则证明与计划校验.md#plan-proof) 直接检查读端口、公开输出及内部槽位映射；相同计划复用进程内的成功校验缓存。cuBLASLt 描述、算法和实际 scratch 容量在准备时固定，scratch 加入同一份槽位校验；每步的执行函数在此时选定，提交循环直接调用。

每次执行调用 `PreparedProgram::submit(inputs, outputs)`，或使用 `run(inputs)` 由运行时分配输出。准备阶段生成待分配输出和端口别名约束表；`run` 校验输入后，只为独立的输出分配存储，重复输出和输入别名复用原缓冲区。`submit` 校验调用方给定的端口，两条入口共用已绑定计划的提交实现。公开端口的设备、字节数、可写性和别名在提交边界校验，随后更新地址并执行全部步骤。整个计划记录一个完成事件，事件覆盖全部缓冲区、kernel 和工作区。

- 每个在途调用占用独立工作区；同一工作区中生存期分离的内部缓冲区共享物理槽位，工作区在完成后复用。
- 工作区首次创建时分配参数存储，写入冻结标量、null 和内部地址，并建立 CUDA 启动描述。后续提交复用这些存储和描述。
- 自有分配释放后，待相关任务完成便进入会话缓存；用户仍持有的结果继续占用原存储。
- 完成事件的原生句柄可复用，旧 `Event` 对象保持已完成状态。
- `Event::query` 立即返回状态；`wait`、`Session::synchronize` 和主机拷贝等待完成。关闭会话时先完成在途工作，再清理资源。
- 单 kernel 和多 kernel 使用同一计划机制。启动失败时，运行时等待已排队的步骤结束再传播错误；设备写入不回滚。

查询、等待及会话操作会回收已完成的资源。事件保留 C++ 对象，FugaTensor 的绑定另行保留外部 Python 所有者直到完成。

<a id="cuda-graph"></a>

## 4. CUDA Graph replay

`prepareProgram(..., graph=true)` 使用 CUDA Graph，`false` 使用 C++ 顺序启动。两种模式共用端口、参数和资源检查。

准备 Graph 时，ASK 从每个步骤的 `inputs` / `outputs` 推导生产者依赖。独立分支由 CUDA 按依赖关系调度；槽位只有在旧生产者及其全部读取步骤都先于新生产者完成时才复用。准备阶段静态校验拓扑、数据可用性和槽位访问顺序，然后冻结节点前驱。普通 stream 模式按步骤顺序复用已结束的生存期。

每个工作区首次执行时创建并实例化 graph；复用时更新节点的输入输出地址，再调用 `cuGraphLaunch`。在途调用各用独立实例，完成后才能修改节点参数。拓扑、kernel、形状、启动配置和冻结标量固定，公开端口地址可变化。cuBLASLt 调用捕获为子图；地址改变时重新捕获该子图并更新可执行图，地址相同则直接重放。

零步骤别名计划只记录 stream 完成事件。驱动缺少所需 Graph API，或实例化、更新、启动失败时抛出异常。

`Session::stats()` 提供 `program_submissions`、`workspace_reuses`、`allocation_reuses`、`event_creations/event_reuses`、`graph_instantiations/graph_launches` 等计数。`launches` 表示提交的计划步骤数（库步骤内部可能包含多个 CUDA kernel），Graph 提交次数另行统计。FugaTensor 的 CUDA JIT 通过自己的原生桥使用 graph 模式。`matmul_preparations` 记录库算法准备次数；`resident_device_bytes` / `peak_resident_device_bytes` 记录 ASK 实际分配的当前/峰值显存，包含分配池，外部借用和驱动/库内部存储由其所有者统计。

`graph_nodes` / `graph_edges` 累计已实例化 Graph 的顶层节点和依赖边，cuBLASLt 子图计为一个顶层节点。`prepared_internal_slots` / `prepared_internal_bytes` 累计成功准备计划中单份内部工作区的槽数和容量，包含库 scratch；实际驻留量随在途工作区及分配池变化。

矩阵乘法的 Graph replay、TF32、提交延迟和内存数据见 [FugaTensor 矩阵乘法与提交优化](../../fugatensor/docs/矩阵乘法与提交优化.md#layers)。

## 5. 调用方编译缓存与原生运行时缓存

FugaTensor 的 `_ask` 接入层维护以下磁盘缓存，校验产物后将字节和计划交给 ASK：

| 缓存 | 命中时跳过 | 键的主要输入 |
| --- | --- | --- |
| 自有 LLVM IR | 图优化与 CUDA LLVM 降级 | 图文本、形状、编译库身份、目标/选项与编排实现摘要 |
| 自有 cubin | `llc` 与 `ptxas` | LLVM IR、产物描述、工具及环境摘要 |
| 外部产物 | Worker 编译 | 标准化请求、probe 结果、worker/解释器、依赖与环境摘要 |

外部缓存保存 cubin 或原始 PTX，查找前探测生产者，编译后再次核对依赖。缓存使用锁、临时目录和原子发布，读取时检查清单、长度和 SHA-256。失效规则见[FugaTensor 缓存分工](../../fugatensor/docs/architecture/ASK桥接与多后端执行.md#cache-hierarchy)及[worker 缓存身份](外部编译器适配接入规范.md#cache-identity)。

ASK 在计划准备时缓存成功校验，会话缓存驻留模块、工作区、显存和事件。校验缓存的键和容量见[成功校验缓存](规则证明与计划校验.md#proof-cache)。
