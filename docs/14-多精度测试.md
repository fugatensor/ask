图只定义一次，测试时替换 dtype。输入数据和预期结果也跟着 dtype 变化，但不重新抄写一份算子链或 Triton DSL。这样增加一种精度时，会自动经过已有的形状、边界、融合和缓存检查。

## 2. 怎样增加一张图或一种精度

`build_module(dtype=..., external=True)` 构造 ASK P → Triton F → ASK Q。`external=False` 把中间计算也生成为 ASK 算子，供 host 路径使用。输入类型、外部签名与语义声明都从存储 dtype 得到。`compute_dtype` 决定显式 cast 后的计算类型，`roundtrip_dtype` 在计算前插入一次目标类型往返，`arch` 写入外部编译目标；这些参数改变实际 ASK IR / DSL。bool 用例显式转成 i32 再计算，不执行 bool 加乘。

`GraphCase` 只保存形状、常量、BLOCK、warp 数等参数。基础矩阵包含单元素、尾部掩码、多维形状、多站点、较长表达式和溢出；浮点类型还经过小数、特殊值和舍入测试。整数不参加仅有浮点含义的用例。

例如同一张 `ask-rounding` 图在 f32、f16 和 bf16 下使用各自的一个 ULP 构造乘加。图中的乘法、加法没有复制；只有数值尺度变化。`F-contract-enabled` 和 `F-contract-disabled` 也共用图，只改变原编译器的固定选项。

增加图形配置时，向 `GRAPH_CASES` 加一项。增加精度时，先接通生产代码中的类型链，再补测试格式参数和输入边界值，已有图不需要复制。确实需要新算子结构时，在图构造器里定义一次，再让各 dtype 使用它。

新增类型和转换仍放在这一个构图器中。`DTYPES=("bool", "i32", "i64", "f32", "f16", "bf16")` 配合 `cast-bool`、`cast-i32`、`cast-i64`、`cast-f32`、`cast-f16`、`cast-bf16`，组成 6×6 转换矩阵。输入输出保持存储 dtype，中间按 `roundtrip_dtype` 转换再转回；host 专门转换测试和常量折叠测试另外直接核对目标类型的结果。

`mixed-accumulate` 使用同一个逐元素链：f16 的 `x=1+2^-10` 经过 `(x+1024)-1024`，bf16 的 `x=1+2^-7` 经过 `(x+128)-128`。低精度运算丢掉这个 ULP，显式 f32 中间值保留它。`mixed-special` 和 `mixed-F-contract-*` 再覆盖特殊值与外部 F 的 FMA 开关。这里没有新增归约实现，测试的是已声明的逐元素计算精度。

## 3. 预期结果不能跟着实现一起错

参考计算不调用 ASK 的数值编码器，也不读取生成的 LLVM 或 PTX 来决定答案。有限数先转换成精确有理数，再按目标格式做最近偶数舍入。每个 ASK 加乘后都舍入；只有 F 明确允许乘加收缩时，才对乘加整体舍入一次。

比较要求有限结果相等，并另外比较零的符号；这些格式的有限数都能被 Python binary64 精确表示，因此这相当于检查目标格式的值位。NaN 比较类别，不要求 payload。无穷、非正规数和溢出都有专门样本，不用放宽误差阈值掩盖错误。

`cast_reference` 另外实现向零截断、整数饱和、NaN→0、非零转 bool、符号扩展和截低位。i64 样本包含边界和大于 binary64 精确整数范围的值，不能先转成 Python float。参考函数另有固定答案的测试，例如 f16 的 `65520` 舍入到无穷、最小非正规数的一半舍入到零，以及 FMA 得到非零残差而分步乘加得到零。生产编码器还独立检查全部 f16 / bf16 位模式和直接舍入边界。

## 4. 怎样运行

在启用 Triton 的构建及兼容 GPU 上，用新的缓存和输出目录运行：

```bash
PYTHONPATH=python python3 examples/triton_fused_gpu.py \
  --ask-opt build/triton/bin/ask-opt \
  --triton-python /path/to/triton/python \
  --triton-worker adapters/triton/worker.py \
  --llc .deps/llvm-1f126a6d-ubuntu-x64-1/bin/llc \
  --ptxas /path/to/triton/backends/nvidia/bin/ptxas \
  --cache-dir build/new-precision-cache \
  --output-dir build/new-precision-results \
  --dtypes bool i32 i64 f32 f16 bf16
```

`--cases tail multiple-sites ask-rounding` 选择图，`--dtypes f16 bf16` 选择精度；其余参数不变。只测转换时可选 `--cases cast-bool cast-i32 cast-i64 cast-f32 cast-f16 cast-bf16`；混合精度可选 `--cases mixed-accumulate mixed-special mixed-F-contract-enabled mixed-F-contract-disabled`。`--arch 86` 改编译目标，默认 80；目标要求及设备检查见[第 15 章](15-类型转换与混合精度.md#5-编译目标和实际硬件分别检查)。`--extended` 加上大形状、更多启动配置和单因素缓存失效用例。旧的 `--float` / `--low-precision` 仍可使用。

运行前先列出有效组合和跳过原因；全部组合都不适用时直接报错。计划还按实际生成的 ASK 图去重：例如 f32 存储再指定 f32 计算，可能与已有配置生成完全相同的图。相同图使用相同 dtype / 形状派生的输入，重复项注明由哪项覆盖，避免把正确的缓存命中误判为失败。每个有效组合执行冷缓存和热缓存两次。冷编译生成 cubin，热编译命中可执行缓存后复用 cubin；两次都在 GPU 上运行，检查输出、dtype、ShapeSnapshot、入口、缓存状态及二进制摘要。`validation.json` 保存计划数量、完成数量、跳过记录、按 dtype 的比较数量及每次运行记录。完成数量必须等于计划，不能把少跑或零次执行算作通过。

bf16 不支持的设备走单独的拒绝测试：模拟 compute capability 7.5，确认抛出明确错误，而且没有创建 context、加载模块、分配设备内存或 launch。实际支持 bf16 的 GPU 负责数值验证；两种测试不能互相替代。host 根据本机 CPU feature 选择执行或明确拒绝；也检查只在中间值使用 bf16 的图。本机缺少 BF16 feature，支持分支的能力判定有测试，实际 bf16 host 执行仍需兼容 CPU 验证。

本轮在 RTX 3080 上完成六类型基础矩阵：22 个配置 × 6 种 dtype 得到 132 个候选组合，排除 27 个类型不适用组合及 1 个相同图重复项，实际执行 104 个唯一组合的冷、热两次，共 208 次，比较 19652 个结果。按 dtype 分批运行与一次选择全部 dtype 使用同一份图、数据和数值参考；汇总时还核对原始记录，防止同名记录覆盖或漏跑。

另外使用 `--arch 86 --dtypes bool i32 i64 f32 f16 bf16 --cases same-shape changed-compute-type shape-2x3x17 wide-block mixed-underflow cast-bf16` 完成 58 次专项执行，比较 9190 个结果。`changed-compute-type` 检查同一存储精度改为 f32 计算时形成新缓存条目；i64 样本包含会被中间 f32 / binary64 转换抹掉的低位，用来验证直接舍入。两组共 266 次融合执行、28842 个结果全部通过，缓存命中和未命中各 133 次。普通 F 内部 bf16 的另外 29 个 GPU 边界值及拒绝路径见[第 12 章](12-GPU融合与IR缓存.md#6-如何复现数值验证)。

## 常驻运行时验证

[第 16 章](16-Python绑定与常驻运行时.md)使用同一个 `pointwise` 图构造器、dtype 规则和数值参考，再检查资源复用与异步顺序：

```bash
PYTHONPATH=build/triton/python:python:tests python3 -m support.runtime_validation \
  --ask-opt build/triton/bin/ask-opt \
  --triton-python /path/to/triton/python \
  --triton-worker adapters/triton/worker.py \
  --llc .deps/llvm-1f126a6d-ubuntu-x64-1/bin/llc \
  --ptxas /path/to/ptxas \
  --cache-dir build/resident-cache \
  --output-dir build/resident-results --arch 86
```

使用新的缓存与输出目录，`--arch` 要匹配设备。默认覆盖六种存储类型、多维形状和 f32 中间计算。每张图先做冷/热编译，核对两级磁盘缓存；然后重复加载以检查模块命中，复用同一对设备张量执行八次。提交期间不得增加分配、模块加载或同步计数。最后等待事件并对照独立参考值，支持 CUDA Array Interface 的类型还在两个 Session 的不同 stream 间零拷贝传递结果。
