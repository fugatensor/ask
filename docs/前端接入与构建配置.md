# 前端接入与构建配置

返回核心思想：[构建与进程内绑定](核心思想.md#ask-frontend-build) · 相关细节：[用户 API](用户API.md) · [ASK IR 与数值语义](ASK-IR与数值语义.md) · [工程结构与测试体系](工程结构与测试体系.md)

ASK 是 C++ 编译器与运行时 SDK，提供 `ASK::Compiler`、`ASK::Runtime`、`ASK::Core` 和命令行工具 `ask-opt`。ASK 不构建 Python 扩展或 Python 包。FugaTensor 自行维护 Python API 和薄原生绑定，直接链接 ASK 的共享库。

<a id="build-workflow"></a>

## 1. 依赖获取、构建与安装

构建需要 C++17 编译器、CMake 3.28+、Ninja 和同一安装中的 LLVM/MLIR 23.1.x 稳定版。`cmake/llvm.lock.json` 记录默认 Linux x86-64 SDK 的发行版 23.1.4、来源与归档摘要；其它平台尚无随仓 SDK 记录和 CI 验证。Python 只用于可选的依赖获取和工程检查脚本，不是 CMake、编译库或运行时的依赖。

```bash
python3 tools/fetch_deps.py
cmake --preset core
cmake --build --preset core
ctest --preset core --output-on-failure
cmake --install build/core --prefix /path/to/ask-install
```

获取脚本支持 `--only llvm`，检查 SHA-256、归档路径和软链，并在 `.deps/<dir>/.ask-sdk.json` 保存收据。CMake 根据依赖记录自动发现 `.deps/` 中的 SDK；其它受支持的同系列稳定版可通过 `-DLLVM_DIR` / `-DMLIR_DIR` 指定。LLVM 和 MLIR 须使用同一版本、同一安装，不要求 `VCSRevision.h` 或 Triton 的 LLVM 提交。安装布局与 FugaTensor 的独立构建见[安装说明](安装.md)。

<a id="compiler-selection"></a>

## 2. 核心配置与外部编译器

`core` 预设包含自有 CPU/CUDA 降级与设备运行时，不依赖 Triton、PyTorch 或 NumPy。`ASK_TARGET_BACKENDS=host` 启用 Host 对象代码生成，`none` 关闭此能力，不关闭 CUDA LLVM 降级。

默认 CTest 运行无 GPU 依赖的原生编译与 Core 测试。物理 GPU 验证需显式配置 `-DASK_TEST_CUDA=ON`，其运行时测试使用驱动加载 PTX，不需要 Triton；缺少驱动或 GPU 会失败，不当作通过。

第三方编译器的 worker、Python 环境与产物缓存由调用方管理。ASK 校验 `ask.external` 契约、生成分区计划，并调度已加载的 cubin/PTX。编译器 ID 不进入构建白名单，Triton 专属代码位于 FugaTensor。协议见[外部产物接口](外部产物与执行接口.md)。

## 3. 不依赖 LLVM 头文件的编译与执行接口

```cmake
find_package(ASK 0.1.0 EXACT CONFIG REQUIRED COMPONENTS Compiler Runtime)
target_link_libraries(my_framework PRIVATE ASK::Compiler ASK::Runtime)
```

`ASK::Compiler` 的公开头文件是 `ask/Frontend/CompilerAPI.h`，使用 `std::string` 和 `std::pair` 传入 ASK MLIR、返回 IR 与 JSON 报告。`prepareJSON`、`partitionJSON`、`codegenJSON` 直接进入原生编译器；一次代码生成在同一 MLIR context 内完成解析、优化与降级。每次调用拥有独立 context，错误通过 `std::runtime_error` 返回，不需要启动 `ask-opt`。

`ASK::Runtime` 的公开头文件是 `ask/Runtime/CUDA.h`，提供 `Session`、`PreparedProgram`、`DeviceBuffer`、`Kernel` 和 `Event`。它管理普通顺序提交与 CUDA Graph replay，构建期不要求 CUDA SDK。仅消费 Compiler/Runtime 组件无需安装 LLVM/MLIR 头文件，也不初始化 Python。调用示例见[用户 API](用户API.md)。

<a id="cpp-sdk"></a>

## 4. 直接操作 MLIR 的 Core 接口

需要自定义 MLIR 构图或变换的宿主链接 `ASK::Core`，并提供与 ASK 实际构建版本匹配的 LLVM/MLIR SDK：

```cmake
find_package(ASK CONFIG REQUIRED COMPONENTS Core)
target_link_libraries(my_frontend PRIVATE ASK::Core)
```

`ask/Frontend/Compiler.h` 提供 `prepareSource`、`partitionSource` 和 `codegenSource`，返回含 LLVM JSON 对象的 `PreparedSource`。已有 MLIR 模块可直接调用 `prepareModule` / `optimizeModule`；这两个接口会修改模块，需要事务行为时由调用方克隆后提交。静态形状、准备流程与优化行为由[Core 测试](../tests/cpp/frontend.cpp)验证。

报告使用 `ask::reportJSON(result.report, result.floatPaths)` 序列化，保留外部配置中的浮点词法类型与负零。`floatPaths` 仅为内部序列化信息，不进入 worker 协议。Compiler facade 和 CLI 共用这个入口。

<a id="cli-driver"></a>

## 5. `ask-opt` 命令行参数

| 参数 | 用途 |
| --- | --- |
| `--capabilities` | 输出构建版本、目标后端、类型和主机 bf16 能力 |
| `--prepare` | 校验、静态形状推导、提取并擦除溯源标记 |
| `--optimize` | 准备后执行常量折叠、DCE 和自有逐元素融合分组 |
| `--no-constant-fold` / `--no-dce` / `--no-fusion` | 关闭对应的图优化 |
| `--partition` | 生成自有/外部步骤、逻辑缓冲区、依赖和 `step_sources`；支持 `--no-optimize` |
| `--emit-llvm` / `--emit-object` | 生成 Host LLVM 文本或对象文件；对象文件必须通过 `-o` 指定路径 |
| `--emit-cuda-llvm` | 配合 `--cuda-arch`、`--cuda-block-size`、`--cuda-ptx-version` 生成 CUDA LLVM 文本 |
| `--check-llir` / `--optimize-llir` | 验证或清理原生 LLVM IR |
| `--report-json FILE` | 将准备、分区或 ABI 报告写入文件 |

CLI 是独立工具入口；FugaTensor 默认编译与执行直接调用共享库。LLVM 到 PTX/cubin 的 `llc` / `ptxas` 仍由调用方编排。

<a id="version-contract"></a>

## 6. 版本、共享库与安装契约

| 字段 | 来源与边界 |
| --- | --- |
| ASK 发布版本 | 根目录 `VERSION`，当前 `0.1.0`；CMake、共享库版本与 capabilities 共用 |
| C++ 包兼容性 | `ASKConfigVersion.cmake` 使用 `ExactVersion`，尚未承诺跨版本或跨 C++ 工具链 ABI 稳定 |
| Core 依赖 | 显式消费 Core 时，LLVM/MLIR 须匹配 ASK 实际构建版本，且来自同一安装；Compiler/Runtime 不检查 LLVM SDK |
| 构建身份 | `build_id` 记录构建目录、ASK 与 LLVM 构建信息和 Host 开关；capabilities 报告实际 LLVM 版本，不代表源码摘要 |
| 数据协议 | ASK IR/执行计划为 v1，外部 worker/规范化 CUDA invocation 为 v2，版本分别演进 |

安装产物包括 `libask_compiler.so`、`libask_runtime.so`、`libask_core.a`、公开头文件、CMake targets、`ask-opt` 和 LLVM 默认依赖记录。消费方应在编译缓存中记录实际代码生成库的摘要；`ask::compilerLibraryPath()` 返回已加载的 Compiler 共享库路径。仅比较发布版本或 `build_id` 不能识别同版本重新编译的实现。

共享库保留 C++ 标准库 ABI，适合使用兼容工具链构建的框架直接链接。Python 绑定属于 FugaTensor，不是 ASK 安装产物的一部分。持续验证见[CI 与安装验收](工程结构与测试体系.md#continuous-integration)。
