# 04. 外部产物与执行接口

返回核心思想：[外部产物与执行接口](核心思想.md#external-execution) · 相关细节：[外部算子声明](01-ASK-IR与数值语义.md#external-declaration) · [Worker 协议](09-外部编译器适配接入规范.md#worker-protocol) · [图切分与调度](08-图切分与多Kernel执行计划.md)

ASK 将每个 `ask.external` 保留为独立 kernel。上层提供的 worker 使用第三方编译器生成 cubin 或 PTX，ASK 校验端口和启动描述后，将它与自有 kernel 纳入同一执行计划。第三方代码不需要导出与 ASK 版本匹配的 LLVM IR。

<a id="external-execution"></a>

## 1. 图边界与职责

高层 `ask.semantics` 定义输入输出类型及形状规则，`ask.implementation` 保存源码、编译配置和逻辑端口绑定。`prepare` 只检查图并生成标准化请求；`partition` 在外部节点两侧切分，自有区域继续执行常量折叠、DCE 和逐元素融合。

例如 `P: t = x + 1 → F: 外部 kernel → Q: y = u + 3` 形成 `owned → external → owned` 三个步骤。`t`、`u` 写入设备缓冲区，并把指针交给下一步骤；整个调用中间不经过主机拷贝。外部节点与自有节点之间没有代码融合，多个外部节点也分别启动。

第三方 DSL 解析、版本约束、编译选项与资源提取由调用方的 worker 负责。ASK 维护通用进程协议、产物缓存、图切分和 CUDA 调度。FugaTensor 的 Triton 实现在 [`src/fugatensor/_triton_worker.py`](../../fugatensor/src/fugatensor/_triton_worker.py)，不参与 ASK 构建。

<a id="binary-artifact"></a>

## 2. 可执行产物与端口

Worker 返回两类产物：`cubin` 使用 base64 编码二进制，`ptx` 使用文本。响应只需描述入口、目标架构、生产者、`launch`、按物理顺序排列的 `arguments` 和 `required_element_types`；字段定义见 [协议 v2](09-外部编译器适配接入规范.md#artifact-contract)。

ASK 根据已验证请求中的 `signature`、`source_bindings`、`port_shapes` 推导 `port_map`，再生成统一的 invocation v2。适配器不重复构造张量 ABI，也不提供 Python 编译对象、设备句柄或主机路径。产物经过摘要校验后由 `CUDAKernel.prepare(session)` 加载；PTX 在加载时交给 CUDA 驱动 JIT。

执行边界是静态、连续行主序张量，支持六种 ASK 元素类型和多输出。每个 kernel 使用 1–64 个物理参数，指针绑定 `input:N`、`output:N` 或显式 `null`，标量按声明的整数或浮点 ABI 类型传值；标量类型不扩展 ASK 的张量类型集合。加载时根据实际 kernel 的参数偏移、大小与数量核对混合 ABI。类型和值的表示见 [请求协议](09-外部编译器适配接入规范.md#worker-protocol)。

当前没有非空 scratch 分配、描述符或协作/集群启动契约。动态共享内存由 `launch.shared_bytes` 声明，提交前核对实际 kernel 的资源限制。

外部产物保留第三方编译器自己的数值策略。ASK 自有计算仍遵守独立舍入和饱和转换规则；两者通过显式端口 dtype 连接。

## 3. 显式配置 Worker

```python
from ask import Compiler, CompilerEnvironment

compilers = {"example": CompilerEnvironment(
    python="/path/to/compiler-env/bin/python",
    worker="/path/to/example_worker.py",
)}
program = Compiler().compile_cuda(
    module, compilers=compilers,
    cache_dir="/path/to/cache", output_dir="/path/to/new-output",
    llc="/path/to/llvm/bin/llc", ptxas="/path/to/cuda/bin/ptxas",
)
```

映射键对应 `ask.implementation.compiler`。ASK 不扫描 Python entrypoints，也不在构建时登记编译器 ID。原生可执行 worker 可省略 `python`。只含外部步骤的图不需要 ASK 的 `llc` / `ptxas`；混合图中的自有 CUDA 步骤仍需要这两个工具。

未配置 worker、请求不合法、编译失败、损坏产物和启动契约不匹配均报错。缓存身份和失败行为见 [Worker 接入规范](09-外部编译器适配接入规范.md)。

可运行示例 [external_ptx.py](../examples/external_ptx.py) 用同一脚本中的薄 worker 交付 PTX，并执行 `ASK → PTX → ASK` 三步图；worker 分支只依赖 Python 标准库。
