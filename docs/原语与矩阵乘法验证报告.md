# 原语、融合与矩阵乘法验证报告

本次增加 10 个正交原语和矩阵乘法，并打通 Fuga 的类型推导、自动微分、编译包和原生执行。逐元素计算保持融合，CUDA 矩阵乘法使用 NVIDIA cuBLASLt。CPU 张量和代码生成使用 `bool/i32/i64/f32/f16` 五种类型，BF16 使用 CUDA。

<a id="implementation"></a>

## 实现与边界

| 职责 | ASK 原语 | Fuga 用户接口 |
| --- | --- | --- |
| 维度映射 | `broadcast_in_dim`、`transpose` | `broadcast_in_dim`、`broadcast_to`、`transpose`、`.T` |
| 归约 | `reduce_sum`、`reduce_max` | `sum`、`amax`，支持轴和 `keepdims` |
| 条件选择 | `compare`、`select` | 比较运算、`compare`、`where` |
| 浮点计算 | `div`、`exp`、`log`、`sqrt` | `/`、`exp`、`log`、`sqrt` |
| 矩阵乘法 | `matmul` | `matmul`、`@`，支持批次和末两轴转置 |

Fuga 的 JVP/VJP 继续生成同一套原语，条件输入保持不可微；max 的相等极值平分梯度，NaN 行传播 NaN。类型转换和广播均显式表达。sum 按输入类型逐步累计，需要 f32 累加时先 cast；matmul 使用 f32 累加。

CPU 使用五类型白名单：ASK 在图优化前校验，Fuga 在 CPU 存储分配或导入时校验。Host 实现、公开编译选项和构建配置均已清理 BF16 专用路径。GPU `from_buffer` 通过通用字节校验后直接上传，工厂函数使用标量编码填充设备缓冲区；这些路径独立于 CPU 张量存储。BF16 权重加载到 CUDA。

Host/CUDA 共用索引表达式降级。连续逐元素链的中间值留在 SSA 寄存器，广播和转置映射读取下标。真实归约的结果再次扩展时提前计算并复用；空轴和单元素归约继续参与融合。CUDA `mul → matmul → add` 形成三个步骤，两侧逐元素区域各自融合。

cuBLASLt 的描述、算法和实际 scratch 大小在 `prepareProgram` 固定，scratch 加入 ASK PASS/Rin 的同一份槽位证明。成功证明仍按完整计划缓存；每步执行函数提前选定。提交循环执行准备好的步骤，动态公开缓冲区的检查集中在提交入口。

库步骤在 Graph 模式中捕获为子图。地址相同直接 replay，地址变化时重新捕获并更新子图；在途工作区保持独立。`workspaceLimit` 默认 4 MiB，实际分配以算法要求为准；串行库步骤的 scratch 可共享槽位。

cuBLASLt 仅进入 Runtime 的私有实现，公开头文件保持标准 C++17。启用提供者时构建消费 CUDA 头文件，执行时动态加载库；`ASK_ENABLE_CUBLASLT=OFF` 的基础 Runtime 构建已验证。Compiler/Runtime 安装消费不读取 LLVM 开发 SDK；Core 使用匹配的 LLVM/MLIR。Rin 提供通用头文件证明器，库步骤的领域事实由 ASK 构造。

f32 matmul 使用 `CUBLAS_COMPUTE_32F_PEDANTIC`；低精度输入使用 f32 累加，并限制 split-K 中间归约类型为 f32。选算法与 scratch 的依据见 [NVIDIA cuBLASLt 文档](https://docs.nvidia.com/cuda/cublas/index.html#cublasltmatmul)。exp/log 的 CUDA 编译链接 libdevice，Fuga 缓存记录 `llvm-link` 和 libdevice 摘要。

## 逐元素融合实测

环境：WSL/Linux、GCC 14.2、Release、LLVM/MLIR 23.1.4、RTX 3080、驱动 615.65.06。cuBLASLt 来自系统 CUDA Toolkit 13.3.1；自有 kernel 使用已配置的 ptxas 12.9.86 和同包 libdevice。测量代码独立于生产代码；运行窗口与 GPU 数值测试分开。

同一条 f32 链 `add → mul → div → sqrt → exp`，比较融合单 kernel 与五个独立 kernel 的原生计划。输入输出预驻留，25 次预热、51 个样本；耗时从 `submit` 开始，到完成事件等待结束。五步计划使用两个可复用临时槽。

| 元素数 | 普通计划：5 kernel / μs | 融合：1 kernel / μs | 临时显存：独立 → 融合 |
| ---: | ---: | ---: | ---: |
| 256 | 84.86 | 45.55 | 2 KiB → 0 |
| 4,096 | 86.25 | 46.35 | 32 KiB → 0 |
| 65,536 | 88.02 | 46.61 | 512 KiB → 0 |
| 1,048,576 | 120.21 | 57.75 | 8 MiB → 0 |

以上为中位数。普通提交本身约从 42–47 μs 降至 13 μs；百万元素的端到端耗时下降约 52.0%。Graph 模式下，百万元素从 110.23 降至 57.65 μs，CPU 提交均约 12 μs；65,536 元素为 43.64 → 42.75 μs，小图变化接近调度波动范围。CPU 同链百万元素从 7,846.48 降至 7,524.41 μs，收益约 4.1%，超越函数仍占主要成本。

独立数值参考、槽位字节和启动计数用于核对实现。每对场景交替采样；完整 CPU/CUDA 数据及 P95 见[融合测量表](assets/逐元素融合测量.csv)。这里测量的是提交至完成时间。

## CPU 归约复用

复核发现，整图 Host 降级曾把归约嵌入广播输出循环，导致重复读取输入。修复后，完整归约在循环外保留为 SSA，部分归约先写入静态规划的临时空间。

Xeon E5-2696 v4，f32，原生 C++ 直接调用生成函数，10 次预热、21 对交替样本；采用相同 HostObject 选项和 `cc -shared -lm`。下列收益针对消除重复归约的两个实例：

| 图 | 修复前 / μs | 修复后 / μs | 输入加载次数：前 → 后 | 新增临时空间 |
| --- | ---: | ---: | ---: | ---: |
| 4096 元素完整 sum，再 splat 为 4096 元素 | 18,374.73 | 6.08 | 16,777,216 → 4,096 | 0 |
| `[64,256]` 按轴 1 sum，再 broadcast 回原形状 | 4,289.31 | 26.51 | 4,194,304 → 16,384 | 256 B |

[CPU 归约测量表](assets/CPU归约复用测量.csv)保存上述摘要。另有 338 组独立 CPU 数值核验，覆盖 dtype、形状、归约轴和后续表达式，以及混合类型的临时空间对齐。空输出停止追踪数值依赖；工作区容量为零时不生成分配或失败分支。

## 矩阵乘法与组件开销

直接 cuBLASLt 与 ASK 使用相同数据类型、计算精度、自然对齐约束、工作区上限和启发式选择。按 f32/f16 × 128/512/1024 方阵 × stream/Graph × 固定/交替地址生成 24 组配对场景，每个样本交替测量两条路径。准备阶段 31 对样本，热提交预热 15 次后测 101 对，设备时间另测 51 对。

设备计时在 stream 前放置 gate，等全部命令排队后释放，以 CUDA events 排除主机排队空洞。主机提交与提交至完成另外测量。ASK 的 `resident_device_bytes` 统计实际自有分配，包含分配池；驱动和库内部存储由其所有者管理。

固定地址 Graph 的中位数如下，单位为 μs；完整 24 组场景及 P95 见[测量表](assets/矩阵乘法测量.csv)。

| dtype / N | CPU 提交：直接 / ASK | 设备时间：直接 / ASK | 提交至完成：直接 / ASK |
| --- | ---: | ---: | ---: |
| f32 / 128 | 9.81 / 13.10 | 8.90 / 8.19 | 51.06 / 51.19 |
| f32 / 512 | 9.65 / 12.44 | 26.62 / 26.62 | 59.18 / 70.27 |
| f32 / 1024 | 9.94 / 13.35 | 126.98 / 126.98 | 159.52 / 168.17 |
| f16 / 128 | 9.90 / 12.98 | 6.98 / 6.14 | 41.04 / 46.43 |
| f16 / 512 | 9.85 / 12.67 | 20.48 / 20.48 | 52.51 / 62.51 |
| f16 / 1024 | 9.58 / 12.52 | 72.70 / 72.70 | 104.34 / 114.48 |

相对直接调用的 CPU 提交增量，跨场景的配对中位数为：普通 stream **4.87 μs**、固定地址 Graph **3.17 μs**、变址 Graph **4.73 μs**。热准备约为直接调用 2.38–2.54 μs、ASK 5.84–6.58 μs。移除成功检查时的临时消息字符串后，额外提交开销的配对中位数减少约 0.73 μs；运行时仍检查实际公开缓冲区。

本轮 ASK 固定地址 Graph 提交约 12.44–13.35 μs，交替地址约 29.48–42.38 μs。后者包含库子图重新捕获及更新，保持地址可减少这项工作。设备执行时间与直接 cuBLASLt 接近，ASK 的主要额外成本在宿主准备和调度。

所有配对场景的自有显存及峰值相同。基准为地址交替预分配两套 A/B/C，f16 512 方阵占 3 MiB 端口存储，另有实际 4 MiB scratch，共 7 MiB；其余五种 dtype/尺寸的选定算法使用零 scratch。两次串行 matmul 复用同一 scratch 槽；`workspaceLimit=0` 选出的零工作区方案也已独立验证。

## Fuga 调用链

分层测量分别调用原生绑定的 `submit`、已准备对象的 `submit_many`，以及用户 `a @ b`、`evaluate` 和完成等待。每层预热 20 次，保留 101 个样本，输入预驻留；用户层还包括组图、缓存查找、结果分配和 Python 对象管理。

固定地址 Graph 的“提交 / 提交至完成”中位数如下，单位为 μs。用户层通过自动分配输出运行，包含相应的 Graph 地址更新。

| dtype / N | 原生绑定 | Python 准备对象 | 用户 `a @ b` + `evaluate` |
| --- | ---: | ---: | ---: |
| f32 / 128 | 16.66 / 52.53 | 38.15 / 68.75 | 186.54 / 200.68 |
| f32 / 512 | 16.24 / 69.33 | 37.41 / 86.84 | 189.96 / 221.22 |
| f16 / 128 | 16.29 / 49.84 | 37.23 / 68.60 | 183.54 / 214.04 |
| f16 / 512 | 16.36 / 64.16 | 37.28 / 83.38 | 192.69 / 223.28 |

这组纯库图的 ASK 分区中位数约 0.76–0.81 ms，Fuga 编译包构建约 1.91–3.54 ms；已有会话中 Python `prepare` 约 127–135 μs，包含计划校验、Python 描述转换和原生准备。热用户调用约 0.20–0.22 ms。层间差值包含各层承担的资源工作；[分层测量表](assets/Fuga调用分层测量.csv)保留 stream、Graph、变址和 P95。

冷启动另用六个独立进程，每种配置三次。下表为耗时中位数，单位为 ms；总和先在每次运行内求和，再取中位数。计时覆盖导入、Engine、context、输入上传、组图编译准备和首次设备完成，排除测量探针、测试数据生成及结果读回。

| 配置 | 导入 | Engine | context / stream | 输入上传 | 编译、准备、首次执行 | 分段总和 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| f32 / 128 | 82.86 | 1.02 | 313.16 | 8.41 | 212.58 | 615.13 |
| f16 / 512 | 86.72 | 1.04 | 322.43 | 8.64 | 473.90 | 879.13 |

同一驱动接口在会话建好后、首次运行完成后读取显存：f32 128 的设备占用净增 **4 MiB**，其中 ASK 自有当前/峰值均为 **192 KiB**；f16 512 净增 **14 MiB**，ASK 自有当前/峰值均为 **5.5 MiB**（三份端口 1.5 MiB、scratch 4 MiB）。驱动净增还包含库/Graph 的存储和分配粒度；三个独立进程得到相同净增。[冷启动测量表](assets/Fuga冷启动测量.csv)保存六次分段结果。

既有算子组合矩阵覆盖 CPU 1,900 / CUDA 2,350 配置、7,300 / 10,450 个前向与导数输出。新增几何矩阵为 CPU 30 / CUDA 36 配置，遍历轴子集和排列；matmul 为 CPU 160 / CUDA 240 配置，交叉 dtype、shape、batch 与 transpose。CPU 数值矩阵与 Host 能力列表使用五种类型，BF16 数值验证使用 CUDA。

原生库测试还覆盖零维情况、变址 Graph、在途输出保持、自然对齐的偏移导入、owned/library 混合步骤、0/4 MiB scratch 和低精度中间溢出后抵消。永久编译测试检查融合单核、临时缓冲区数量、归约物化、公开标量、空输出和单元素归约。

最终 SDK 位于 `build/sdk`，FugaTensor 已用它重建；安装后的 Compiler/Runtime 与 SDK 的 SHA-256 逐字节一致。ASK 实现及最终契约提交为 `8a6d5b6`，前序提交分别记录原语、Runtime、分区接入、归约复用和 CPU 类型边界。FugaTensor 最终提交为 `ea33f41`。

新增 API 文档按最小调用、形状规则和可折叠参数细节展开。工程文档同步三种步骤、可选依赖、libdevice、精度、Graph 更新和显存统计范围。临时验证、基准代码和临时消费者在完成后删除，测量摘要随报告保留，构建产物留在忽略目录。
