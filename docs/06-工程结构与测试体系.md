## 1. 目录职责

```text
ask/
├── include/ask/           # Frontend、IR、Transforms、Lowering、LLIR、Runtime 公共接口
├── lib/
│   ├── IR/               # ask dialect 与操作校验
│   ├── Frontend/         # 准备、能力报告、图切分
│   ├── Transforms/       # 常量折叠、DCE、自有逐元素融合分组
│   ├── Lowering/         # 自有 Host/CUDA LLVM 降级
│   ├── LLIR/             # 原生 LLVM 导入、清理与数值辅助
│   └── Runtime/          # 常驻 CUDA Driver 运行时
├── bindings/             # nanobind 编译器与运行时绑定
├── python/ask/           # SDK、通用 worker 协议、编译包、执行与缓存
├── schemas/              # 执行计划与外部请求/响应 JSON 契约
├── cmake/                # LLVM/nanobind 锁与安装配置
├── tools/                # ask-opt、依赖获取、元数据与分发检查
├── tests/                # CPU 单测、GPU 测试及共享数值参考
├── examples/             # Python 前端与独立 C++ 消费示例
└── docs/                 # 设计与工程说明
```

第三方编译器专属 worker 不在 ASK 仓库。FugaTensor 的 Triton worker、依赖锁与专属测试由 FugaTensor 维护。ASK 的 `python/ask/adapters.py` 只处理通用子进程协议，不按编译器 ID 分支。

`.deps/`、`build/`、`dist/`、虚拟环境和缓存不进入版本库；保留 `cmake/*.lock.json` 与 `tools/fetch_deps.py`。

<a id="ctest-targets"></a>

## 2. 两个 CTest 测试集

`ctest --preset core --output-on-failure` 运行以下目标：

| CTest 名称 | 入口 | 覆盖范围 |
| --- | --- | --- |
| `ask-unit` | `tests/test_*.py` | SDK、类型与形状、数值编码、高层优化、自有 Host 执行和 CUDA 离线代码生成、通用 worker 协议、产物缓存、图切分、执行计划与编译包校验。 |
| `ask-gpu` | `tests/gpu/test_gpu_*.py` | 真实设备数值、显式转换、异构端口、cubin/PTX 加载、常驻会话、CAI 互操作与多 kernel 调度。 |

```bash
PYTHONPATH=build/core/python:python:tests ASK_OPT=build/core/bin/ask-opt \
  python3 -m unittest discover -s tests -p "test_*.py" -v

ctest --preset core -R ask-gpu --output-on-failure
```

`tests/gpu/` 不放 `__init__.py`，使顶层 unittest discover 只发现纯 CPU 测试。设备测试因工具或驱动缺失而跳过时，不能计作硬件验证成功。

<a id="matrix-and-reference"></a>

## 3. 多精度矩阵与数值参考

`tests/support/pointwise.py` 用 Python 任意精度整数计算 IEEE-754 单步 RNE、次正规数、32/64 位整数回绕与饱和转换。样本覆盖大整数、半 ULP 舍入边界、`-0.0`、无穷、NaN 和非整块尾元素。

`plan_matrix` 复用图拓扑、形状与类型组合，供自有 Host/CUDA 后端比较。新增多精度验证优先扩展该参考和矩阵，避免在零散测试中重复实现预期结果。外部 kernel 的算法数值由调用方测试，ASK 侧验证其执行契约与数据连接。

<a id="continuous-integration"></a>

## 4. CI 与分发验证

[GitHub Actions](../.github/workflows/ci.yml)定义 Linux x86-64 核心构建、CPU 测试与分发检查。LLVM 归档按锁文件校验后解压，不将 SDK 放入源码包或 wheel。

[run_ci_tests.py](../tools/run_ci_tests.py)检查 CPU 测试的 JUnit 报告；缺少测试集、未发现 Python 测试、失败或内部跳过均不能当作通过。CI 的 CPU 结果不代表 CUDA 驱动、设备执行或零拷贝已验证；硬件环境中另行运行：

```bash
ASK_REQUIRE_CUDA_DEVICE=1 ctest --preset core -R '^ask-gpu$' --output-on-failure
```

分发验证先生成 sdist，再从 sdist 构建 wheel。[check_metadata.py](../tools/check_metadata.py)检查源码和包元数据；[smoke_wheel.py](../tools/smoke_wheel.py)在隔离环境核对 Python、原生扩展与 CLI 的版本和能力，并编译、链接、执行 CPU 图。CMake 安装消费通过独立构建 [C++ 示例](../examples/cpp/frontend.cpp)验证。

这些文件定义检查方式，实际成功状态以对应运行记录为准。支持平台和包版本规则见 [版本契约](02-前端接入与构建配置.md#version-contract)。
