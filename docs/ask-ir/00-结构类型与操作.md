# ASK IR：先把计算本身写清楚

[本目录](README.md) · [顶层 A 层设计](../核心思想.md#ask-a) · [A 层处理流程](../01-A层高级IR与区域规划.md)

本篇选定 ASK IR 的具体结构。它采用 MLIR `ask` dialect，保存高层计算的语义；B/C 层继续使用原生 LLVM IR。以下操作名和属性是 ASK 的拟议规范，不是 MLIR 已有操作，也不表示已有可执行的解析器。

<a id="structure"></a>

## 1. 一个模块怎样组成

上层框架负责生成基础 ASK IR，再调用 ASK 的图编译入口。框架可以使用自己的内部 IR，但转换到 ASK IR 的前端属于框架侧；ASK 接手时，操作、数据连接和第三方编译边界已经用 ASK IR 表达。基础 IR 不要求已有执行分区、物理布局或完整的推导结果，这些由 ASK 后续补全。

用 MLIR 的 `builtin.module` 容纳图函数、算子语义引用和实现引用。每个图函数使用 `func.func`，首版限制为单个基本块，以 `func.return` 结束；首版图函数之间不再调用。操作按依赖排列，定义先于使用。图级数据相关分支和循环不进入 ASK IR；降级后产生的元素循环和掩码属于实现细节。

选择单块 SSA 区域，是为了让数据、类型和效果检查有明确的次序。这里的“计算图”不表示采用 MLIR 的 Graph Region 语义；本设计使用有支配关系的 SSACFG 区域。[MLIR 区域与 SSA](https://mlir.llvm.org/docs/LangRef/#regions)

模块保存 `ask.schema_version`、语义注册表快照、数值规则和输入约束。算子引用解析到该快照中的版本，不能在一次编译中查到不同定义。`SemanticModule` 就是这份 ASK IR 加上稳定身份、使用关系和约束表；`RegionPlan` 是分析它后得到的执行计划，不是第二份计算图。

一个操作的输入、结果、属性和引用共同确定它的含义。结果类型可以带尚未求出的维度，但只能作为构造与推导中的临时状态。进入 B 层前，必须通过[静态形状检查](02-形状推导与约束.md)。

## 2. 张量类型不包含线程布局

| 类型 | 表达什么 | 首版限制 |
|---|---|---|
| `tensor<10xi32>`、`tensor<2x5xf32>` | 有 rank、元素类型和逻辑尺寸的不可变张量 | 降级前所有维度具体，允许零长度 |
| `tensor<i32>` | rank 为零、含一个元素的张量 | 与长度一的向量区分 |
| `i1`、`i32`、`f32` 等 | 标量值 | 实际可用元素类型由操作和后端共同检查 |
| `index` | 形状和索引计算中的整数 | 转到目标整数位宽时检查可表示性 |
| `!ask.token` | 有状态或未知效果操作之间的顺序 | 首版使用一条串行效果链 |

元素宽度属于类型，符号解释和溢出规则属于操作。例如 `i32` 加法采用 `overflow="wrap"` 时，结果保留低 32 位；不能在降级时加上 `nsw` 或 `nuw`。浮点精度、舍入与求值顺序沿用模块和操作的数值约定，优化不能自行放宽。

当前已实现的元素类型是 i32 和 f32。f32 常量在构图时舍入到 IEEE binary32；`ask.add`、`ask.mul` 每步按最近偶数舍入，不允许重排或把两步乘加收缩成一次 FMA。NaN、无穷、带符号零和非正规数沿用普通 IEEE 运算语义，不承诺 NaN 的 payload。不同 dtype 必须显式转换；当前尚无 cast 操作，所以混合类型会报错。类型怎样传到外部签名、LLVM 和运行缓冲区，见[框架接入](../10-上层框架接入.md#dtype-path)。

`tensor<10xi32>` 不说明十个元素由几个线程处理，也不保证内存连续。外部输入的偏移、stride、对齐和存储域保存在输入视图约定中；分配与别名由后续 `BufferBinding` 描述。`tensor<2x5xi32>` 与 `tensor<10xi32>` 元素数相同，形状仍不同。

首版不接受未知 rank。类型里的每个 `?` 都是一个尚未求出的维度，不代表它与另一处 `?` 相等。若要表达相等，由形状约束记录；不往张量类型里塞线程编号、warp 大小或厂商布局标签。

可变存储也不能伪装成不可变张量。首版张量接口禁止 F 原地修改输入张量；这类实现必须先有符合语义的复制方案，否则拒绝绑定。如果连输入是否可能被写都未知，也不能绑定到这个只读张量接口。以后增加显式 buffer 读写接口时，再用存储效果和 token 表达更新，不能让同一张量 SSA 值在调用前后指向不同内容。额外状态效果可以未知并保守排序，数据端口的读写约定仍须明确。

## 3. SSA 引用、逻辑值和存储分别编号

| 名称 | 身份范围 | 例子 |
|---|---|---|
| `OpId` | 当前语义图中的操作 | P、F、Q |
| `SSARef` | 某个块参数或操作结果的定义位置 | `%t` 与标记返回的 `%tm` 是两个定义 |
| `ValueId` | 高层逻辑值 | `%t` 与透传 `%tm` 都代表 `v_t` |
| `PortId` | 某个操作的数据输入或输出位置 | `P.out`、`F.in` 都连接 `v_t` |
| `BufferId` | 降级后存储或外部绑定 | 存放 `v_t` 的 `b_t` |

普通计算产生新 `ValueId`。`ask.mark` 只产生新的 SSA 引用，通过 `traceIdentity` 关系继续引用同一逻辑值。`reshape` 虽然可能不复制存储，却产生不同形状的逻辑值，所以要有新的 `ValueId`。不能因为地址相同就合并逻辑值。

SSARef 在当前 IR revision 内定位对象；稳定 ID 由 ASK 分配，不能取 LLVM/MLIR 打印出的 `%0`。写入文件时保存模块摘要及可解析的定位记录；克隆、删除或替换操作后更新引用。语义等价改写需要显式记录旧值到新值的对应，来源相同本身不构成等价证明。

版本分两种：`semantic_revision` 对应逻辑计算、端口、类型/形状约束及本次特化；`ir_revision` 对应具体 IR 结构。纯 marker 插入或删除只改变后者，更新 SSARef 与追踪表即可复用原形状快照。计算、尺寸约定或特化发生变化时才需要新的语义版本，并重新核对形状；不能改写旧快照来适配新输入。

使用表统计真正读取、返回或写出逻辑值的操作。遍历到 `ask.mark` 时沿它的结果继续找消费者，不能把标记当成一个必须保留存储的消费者。只剩标记而没有真实使用的纯计算，仍可被删除。

## 4. 先定义少量操作，避免依赖隐式规则

| 操作 | 语义与关键检查 |
|---|---|
| `ask.constant` | 首版产生有类型的标量常量；字面量必须可按该类型解释 |
| `ask.splat` | 将一个标量复制到显式给定的张量形状 |
| `ask.add`、`ask.mul` | 标量对标量，或同元素类型、同形状张量逐元素计算；没有隐式广播 |
| `ask.broadcast` | 按明确的输入轴到输出轴对应扩展张量；每个映射维必须相等或输入为 1 |
| `ask.reshape` | 保持元素顺序和元素数，改成指定形状；不承诺零拷贝 |
| `ask.transpose` | 按合法的轴排列改变索引对应；是否只改 view 由降级决定 |
| `ask.slice` | 按 `offsets/sizes/strides` 取子张量；首版参数静态且 stride 为正，访问不得越界 |
| `ask.reduce` | 沿明确的轴按注册的归约规则计算；说明初值、累加类型、次序与 `keepdims` |
| `ask.external` | 按已注册语义产生结果，实现由单独的引用选择 |
| `ask.mark` | 原样返回输入，只记录追踪位置 |

例如 `tensor<10xi32> + i32` 不是合法的 `ask.add`，应先 `ask.splat`，再相加。这样 shape inference 和 lowering 使用同一条显式规则。零元素张量允许存在；归约空域是否有结果取决于该归约的初值或单位元，不能任意返回零。

上述是语义集合，不要求第一个原型同时支持所有操作的代码生成。首个可执行子集为 constant、splat、整数 add/mul、external 和 mark，足以实现 P/F/Q。其余操作可以先验证类型和推导形状；没有实现对应降级时，编译必须报告具体操作不受支持。

后续自有算子可以增加专用操作，或通过拟议的 `ask.apply` 引用同一语义注册表。两者都要提供下面的接口。`ask.apply` 是扩展预留，不进入首个可执行子集；陌生操作不能自动获得“逐元素”或“无副作用”性质。

## 5. 在 ASK IR 中标出第三方区域，同时提交它的 DSL

上层框架遇到 Triton 等第三方编译器负责的计算时，使用 `ask.external` 标出这个编译边界，并附上该编译器的 DSL。ASK 不需要从这段 DSL 重新发现整张图：输入输出已在 ASK IR 中连好，DSL 只定义这个外部区域的实现。

```mlir
%u = "ask.external"(%t) {
  semantics = @scale2_i32_v1,
  implementation = @triton_scale2
} : (tensor<10xi32>) -> tensor<10xi32>
```

这里的符号需要在模块的注册表绑定中声明；示例省略声明格式。`@scale2_i32_v1` 说明逐元素乘二、i32 回绕、输出与输入同形、只读输入且无额外状态效果。`@triton_scale2` 说明如何导出本次固定配置的实现。A 层可以在尚未导出 LLVM IR 时检查此操作。

框架提交的实现记录 `ImplementationReference` 至少关联以下内容。DSL 可以随请求提交，或引用能按摘要解析的已有源码包；不能只给一个编译器名字却不给实现。

| 字段 | 本例中由上层提供的内容 |
|---|---|
| `compiler_id` | `triton`，用于选择已注册导出器 |
| `DSLSource` | DSL 的 language、source_ref、digest、entry 与 deps；本例入口为 `scale2` |
| `source_bindings` | 源参数 `t` 对应 `F.in`，源参数 `u` 对应 `F.out` 的目标存储 |
| `constants` | 本次特化的 N 和 DSL 所需的其他编译期常量 |
| `fixed_options` | 已选定的编译配置，不为追踪或融合重新搜索 |
| 启动约定 | 固定 grid 规则等调用信息，交给对应目标的调用描述处理 |

`source_bindings` 描述 DSL 源接口。导出器编译 DSL 后返回的 `port_map` 描述实际 LLVM ABI，两者不能混用：源参数 N 可能是 `constexpr`，编译后根本没有对应参数。形状推导先使用语义规则与输入特化；B 层再将 DSLSource 传入 `export(request)`，最后核对真实产物。

`ask.external` 表示会执行的计算，即使关闭追踪也必须存在相应语义和实现引用。`ask.mark` 则是可删除的纯追踪操作；在它的属性里写一个编译器名字，不能替代外部区域声明。框架提交的 ASK IR、语义定义和 DSL 必须指向同一组端口与版本。

形状规则属于语义注册，不由当前实现临时猜测。B 层拿到 `LLIRArtifact` 后，使用 `port_map` 核对逻辑输入输出如何对应实际参数。语义上的一个输出张量可以对应 LLVM 中被写入的指针参数，而不是函数返回值。隐藏 scratch 参数由调用说明提供，不能冒充高层张量端口。

签名检查不能证明任意二进制符合语义。实现注册方必须保证声明与实现一致，实际正确性测试验证结果；形状声明与实际特化矛盾时拒绝绑定。只有 LLVM 文件、没有高层语义的导入仍可走低层入口，不必制造 `ask.external`。

纯计算形态的 external 没有额外 token。F 会修改外部状态，或效果未知时，使用有序形态：

```mlir
%u, %s1 = "ask.external"(%t, %s0) {
  semantics = @stateful_scale2_v1,
  implementation = @fixed_impl
} : (tensor<10xi32>, !ask.token) -> (tensor<10xi32>, !ask.token)
```

每个有序图函数接收一个 token，按上层程序顺序串起有状态操作，最后返回最后一个 token；没有副作用时不需要它。首版不允许效果链分叉、丢弃或凭空制造 token。形状推导只看数据端口，token 不参与维度推导，也不进入外部 kernel 的物理参数。

token 表达依赖，不是同步指令。降级将它写入执行计划，运行时通过完成事件满足依赖。纯操作仍要服从数据依赖与别名检查。未知效果按保守读写资源建模，不可只加 token 就把操作标成 `Pure`；有状态操作的副作用与不可任意推测执行性质，也要通过 MLIR 的效果接口报告。[MLIR 效果与推测执行](https://mlir.llvm.org/docs/Rationale/SideEffectsAndSpeculation/)

## 6. 一个新操作要向编译器回答什么

形状、效果和降级不能靠每个 Pass 各写一串算子名称判断。ASK 为操作定义以下职责，其中方法名为设计伪代码：

```text
verifySignature(operand_types, result_types, attributes)
inferShape(operand_shapes, attributes, constants) -> shapes + constraints
describeEffects(operands, attributes) -> effects + speculation_conditions
lower(request, frozen_shapes, bindings) -> implementation + updated_bindings
```

`verifySignature` 检查 rank、类型、端口和属性是否构成合法调用。`inferShape` 是纯函数，只读形状、属性及已知编译期常量，不执行张量计算、不调用设备、不搜索 F 的实现。`describeEffects` 说明可观察行为和必要条件。`lower` 可以不支持当前目标，但不能篡改前三项定义的语义。

ASK 自有操作可以接入 MLIR 的 `InferTypeOpInterface` / `InferShapedTypeOpInterface`；external 则转发给注册语义中的规则。MLIR 提供接口入口，跨操作的约束求解、注册表版本和 ASK 的冻结条件仍由 ASK 实现。[MLIR 形状推导接口](https://mlir.llvm.org/docs/ShapeInference/)

marker 的上述答案特别简单：输入输出类型一致；形状相等；无效果；降级前保存有效追踪记录并清除操作。它不提供 F 的算法，也不告诉优化器“这里一定可以融合”。详细规则见[标记算子](01-标记算子与追踪.md)。

## 7. 不同检查发生在不同位置

构造完成先检查 SSA、符号、类型和效果链；形状推导再检查维度关系；进入降级前要求形状具体并冻结快照；绑定实现时核对物理参数和目标；修改 LLVM 后运行相应 verifier。任何一个阶段通过，都不能代替后面的检查。

改写 ASK IR 时要同时更新 ValueId/SSARef 对应、使用表和形状依赖。改变算子属性或输入会使受影响形状重新求解；只插入或清除合法 identity 标记，不改变逻辑形状，但必须维护 SSA 引用和追踪记录。所有这些记录都绑定版本，不能靠复制旧属性宣布改写后仍然有效。

完整的形状规则见[形状推导](02-形状推导与约束.md)，形状如何随代码下沉见[降级](03-降级与信息保留.md)，一份带标记的完整图见[示例](04-示例与验证.md)。
