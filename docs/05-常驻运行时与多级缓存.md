## 1. 动态驱动加载与常驻 `ExecutionSession`

C++ 运行时库 `ask_runtime`（`include/ask/Runtime/CUDA.h`、`lib/Runtime/CUDA.cpp`、`bindings/runtime.cpp`）构建期不依赖 CUDA Toolkit 头文件或 `libcudart.so`：

- **按需 `dlopen("libcuda.so.1")`**：仅在创建 `ExecutionSession` 或调用 GPU 执行接口时动态解析 CUDA Driver API 符号；无 NVIDIA 驱动的机器仍可正常完成 IR 准备、优化与 NVPTX LLVM IR 生成。
- **Primary Context 与非阻塞 Stream**：每个 `ExecutionSession(device=0)` 持有目标显卡的 primary context（`cuDevicePrimaryCtxRetain`）及一条非阻塞 CUDA stream（`CU_STREAM_NON_BLOCKING`）。
- **模块驻留与硬件能力校验**：`kernel.prepare(session)` 将 `cubin` 加载为驻留 `CUmodule` / `CUfunction`（同一 `session` 内按 `cubin` 摘要去重复用，计入 `session.stats["module_hits"]`）。加载前核对当前显卡的计算能力是否满足目标 `arch`、动态共享内存上限及 `required_element_types`（如低于 `sm_80` 时拒绝加载含 `bf16` 的模块）。

```python
from ask import ExecutionSession

with ExecutionSession(device=0) as session:
    exe = kernel.prepare(session)
    x = session.from_host(values, shape=(2, 8), dtype="f32")
    y = session.tensor((2, 8), "f32")
    for _ in range(100):
        done = exe.submit(x, y)
    done.wait()
    host_out = y.to_host()
```

## 2. `DeviceTensor` 与 `__cuda_array_interface__` 零拷贝互操作

`ExecutionSession` 管理两类设备缓冲区，统一封装为 `DeviceTensor`：

1. **自有显存张量**：通过 `session.tensor(shape, dtype)` 或 `session.from_host(values, shape=..., dtype=...)` 在会话 stream 上分配和拷入；支持空张量（`nbytes == 0`）与 0-D 标量。`DeviceTensor` 暴露 `__cuda_array_interface__` v3（携带会话 `stream` 指针），可直接传给外部库。
2. **外部零拷贝借用（`session.from_cuda_array(obj)`）**：消费外部框架或另一 `ExecutionSession` 暴露的 `__cuda_array_interface__`（v2/v3）：
   - 校验 `typestr`（`|b1`、`<i4`、`<i8`、`<f4`、`<f2` 及 `bf16` 描述）、连续行主序 `strides`、可写属性（作为输出端口时）以及设备归属。
   - **跨流同步**：若生产者描述符带有不同于当前会话的 `stream` 句柄，提交前在生产者 stream 上记录 `CUevent` 并在当前会话 stream 上调用 `cuStreamWaitEvent`。
   - **宿主对象保活**：借用的 `DeviceTensor` 持有外部 Python 对象引用；异步提交 kernel 后，后台队列保留该引用直到对应完成 `CUevent` 结束，防止外部显存在 GPU 执行期间被提前回收。

<a id="async-events"></a>

## 3. 热路径校验、别名防护与异步 `Event`

调用 `exe.submit(in_tensor, out_tensor)` 或多端口 `exe.submit_many(inputs, outputs)` 时：

- **提交前校验**：C++ 绑定层核对各端口的所属 `session`、元素类型、形状字节数以及输入与输出显存区间不重叠（aliasing）；校验失败不增加 `session.stats["launches"]`。
- **并发提交**：会话内部对驱动状态加互斥锁，阻塞等待期间释放 Python GIL，支持多线程向同一 `ExecutionSession` 提交任务或读取 `session.stats`。
- **显式同步**：`submit` / `submit_many` 立即返回 `Event`；调用 `event.wait()`、`session.synchronize()` 或 `tensor.to_host()` 时才同步等待 GPU 完成。关闭会话（`session.close()` 或退出 `with` 块）会同步在途任务并释放缓存模块与事件池。

`CUDAKernel.run(values)` 保留为单输入单输出、同 shape/dtype 的同步列表测试入口；上层框架运行时（如 [FugaTensor 的 `Engine`](../../fugatensor/docs/architecture/04-ASK桥接与多后端执行.md#engine-lifecycle)）使用常驻 `ExecutionSession` 与 `submit_many`。

## 4. IR 与可执行产物双层持久缓存

`Compiler.compile_cuda(..., cache_dir=...)`（`python/ask/gpu.py`）对编译链路提供两层磁盘缓存：

| 缓存层级 | 命中时跳过的阶段 | 缓存键（SHA-256）输入 | 状态字段 |
| --- | --- | --- | --- |
| **IR Cache** | 外部适配器 worker 编译、边界校验、LLVM 内联与 `--optimize-llir` | 规范化后的 ASK IR、目标架构与开关、ASK 构建指纹、已启用适配器的安装与策略指纹 | `kernel.cache["status"]` / `kernel.report["ir_cache"]` |
| **Executable Cache** | `llc`（LLVM IR → PTX）与 `ptxas`（PTX → `cubin`） | 最终 LLVM IR 全文、代码生成参数（`arch`、`ptx_version`、`fp_contract`）、`llc` 与 `ptxas` 二进制指纹 | `kernel.codegen["executable_cache"]` / `kernel.report["executable_cache"]` |

缓存写入采用临时文件加原子 `replace`，读取时校验 `cubin_sha256` 与元数据完整性。上层清空内存函数表或重启进程后仍可直接命中磁盘缓存；升级 LLVM SDK、`ptxas`、Triton 或重新编译 ASK 后，工具链指纹变化会使旧缓存自动失效。
