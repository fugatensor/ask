# ASK Standalone Installation

Build and install the ASK C++ SDK and `ask-opt` via CMake; callers link the required libraries on a per-component basis.

<a id="requirements"></a>

## 1. Build and Consumption Dependencies

Build targets Linux x86-64, requiring C++17, CMake 3.28+, Ninja, and a matching LLVM/MLIR 23.1.x SDK from the same installation. Dependency scripts use the Python 3 standard library, download LLVM/MLIR 23.1.4, and build OpenBLAS 0.3.33 using a C compiler and Make. Execution plan validation builds alongside ASK's C++ source code.

| Use Case | Required Components |
| --- | --- |
| Building ASK from source | C++ toolchain, CMake/Ninja, zlib/zstd/libxml2 development libraries, and a stable LLVM/MLIR 23.1.x release from the same installation. |
| Consuming `ASK::Compiler` | Installed ASK SDK. Interfaces use C++17 named options, result structs, and versioned JSON fields. |
| Consuming `ASK::Runtime` | Installed ASK SDK; GPU execution requires NVIDIA driver and device. |
| Consuming `ASK::Core` | Installed ASK SDK, LLVM/MLIR development files matching ASK's actual build version, and zlib/zstd/libxml2 development libraries used by that LLVM SDK. |
| Compiling native CUDA graphs | Caller passes LLVM IR generated by ASK to matching `llc` and CUDA `ptxas`. |
| Executing external cubin/PTX | Caller provides binary, entry point, and ABI; PTX is JIT-compiled upon driver loading. |
| Turning Host `.o` into dynamic libraries | Caller provides system linker and links libraries provided by the SDK according to the Host ABI's `link_libraries`. |

Debian/Ubuntu system dependencies are as follows. Please also ensure `cmake --version` is 3.28 or later:

```bash
sudo apt-get install build-essential ninja-build zlib1g-dev libzstd-dev libxml2-dev
```

## 2. Building and Installing the SDK

```bash
cd /path/to/ask-source
python3 tools/fetch_deps.py
cmake --preset core
cmake --build --preset core
ctest --preset core --output-on-failure
cmake --install build/core --prefix /path/to/ask-sdk
```

The script verifies archive SHA-256 checksums and places the LLVM/MLIR SDK and native OpenBLAS SDK into `.deps/` for automatic CMake discovery. `--only llvm` / `--only openblas` prepares a single component; `--jobs 4` controls OpenBLAS build parallelism. OpenBLAS uses LP64, single-threading, concurrent invocation locks, and dynamic CPU dispatch, exporting symbols with an `ask_` prefix. When specifying alternative dependencies and build directories:

```bash
python3 /path/to/ask-source/tools/fetch_deps.py --destination /path/to/ask-deps
llvm_sdk=/path/to/ask-deps/LLVM-23.1.4-Linux-X64
cmake -S /path/to/ask-source -B /path/to/ask-build -G Ninja \
  -DCMAKE_BUILD_TYPE=Release \
  -DLLVM_DIR="$llvm_sdk/lib/cmake/llvm" \
  -DMLIR_DIR="$llvm_sdk/lib/cmake/mlir" \
  -DASK_OPENBLAS_ROOT=/path/to/ask-deps/openblas-0.3.33
cmake --build /path/to/ask-build
cmake --install /path/to/ask-build --prefix /path/to/ask-sdk
```

When packaging compiler and runtime components, their respective shared libraries, public headers, and CMake configurations can be installed separately:

```bash
cmake --install build/core --prefix /path/to/ask-sdk --component Compiler
cmake --install build/core --prefix /path/to/ask-sdk --component Runtime
```

The complete installation directory contains `bin/ask-opt`, `include/ask/`, shared libraries, Core static libraries, and `lib/cmake/ASK/`. LLVM/MLIR and OpenBLAS versions, sources, and SHA-256 checksums are stored in `cmake/llvm.lock.json` and `cmake/openblas.lock.json`, respectively. The Host compilation component carries `libask_openblas.so.0`, the OpenBLAS lock file, and `share/licenses/ask/OpenBLAS/LICENSE`. When selecting another stable 23.1.x release, LLVM and MLIR must originate from the same installation; the build report records the actual version.

## 3. Consuming Installed C++ Interfaces

```cmake
find_package(ASK CONFIG REQUIRED COMPONENTS Compiler Runtime)
target_link_libraries(my_framework PRIVATE ASK::Compiler ASK::Runtime)
```

Pass `-DCMAKE_PREFIX_PATH=/path/to/ask-sdk` when configuring caller projects. When Host f32 objects reference SGEMM, CMake callers link `ASK::HostBLAS`; dynamic JIT callers obtain actual library paths via `host_link_libraries` in capabilities. Executing existing artifacts requires only `Runtime`. When manipulating MLIR directly, select `Core` and add the matching LLVM SDK to the search path. If system dependencies for LLVM are installed in a custom directory, include that prefix in `CMAKE_PREFIX_PATH` as well.

SDK consumption tests for Runtime can be built independently:

```bash
cmake -S /path/to/ask-source/tests/cpp \
  -B /path/to/runtime-consumer -G Ninja \
  -DCMAKE_PREFIX_PATH=/path/to/ask-sdk -DASK_TEST_COMPONENT=Runtime
cmake --build /path/to/runtime-consumer
ctest --test-dir /path/to/runtime-consumer --output-on-failure
```

This test checks PTX execution and resource reuse, requiring a compatible NVIDIA GPU at runtime. Changing `ASK_TEST_COMPONENT` to `Compiler` or `Core` tests the other two component classes. For interfaces, see [User API](api.md); for test scope, see [Testing Suite](testing.md#ctest-targets).

<a id="cuda-and-adapters"></a>

## 4. CUDA Tooling and Third-Party Compilers

For native CUDA computation, ASK generates LLVM IR; the caller executes `llc` / `ptxas` and caches artifacts. ASK Runtime loads the driver via `libcuda.so.1`. exp/log also uses matching `llvm-link` and the CUDA Toolkit's `nvvm/libdevice/libdevice.10.bc`.

CUDA matmul uses cuBLASLt. `ASK_ENABLE_CUBLASLT=ON` (default) enables it when `cublasLt.h` is found; CMake searches `CUDA_PATH`, `CUDA_HOME`, and `/usr/local/cuda/include`, or `ASK_CUBLASLT_INCLUDE_DIR` can be explicitly specified. At runtime, `libcublasLt.so.13`, `.12`, or the unversioned name is dynamically loaded, and the library directory must reside in the dynamic loader's search path. `ASK_ENABLE_CUBLASLT=OFF` builds a base Runtime, which raises an error when preparing non-empty matmuls. Public headers for Compiler/Runtime use standard C++ types.

Third-party kernels are compiled by the caller's worker; ASK receives cubin/PTX and launch metadata according to the [protocol](../../schemas/). FugaTensor provides a Triton worker; for environment configuration, see [FugaTensor Installation](../../../fugatensor/docs/en/install.md).

<a id="framework-install"></a>

## 5. Integrating with FugaTensor

Install the ASK SDK first, then pass it to the FugaTensor build via `CMAKE_PREFIX_PATH`. FugaTensor's nanobind extension links against `ASK::Compiler` and `ASK::Runtime`, and the wheel bundles these two shared libraries, the Host OpenBLAS library, and their licenses.

FugaTensor's `pure` / `all` options determine whether pip installs Triton. For installation commands and CUDA tool configuration, see [FugaTensor Installation](../../../fugatensor/docs/en/install.md#installation-variants).
