# ASK 独立安装

返回文档目录：[ASK 文档](README.md) · 返回核心思想：[构建与绑定](核心思想.md#ask-frontend-build) · 相关细节：[构建参数与版本契约](02-前端接入与构建配置.md#version-contract)

ASK 交付 C++ SDK 与 `ask-opt`，不提供 Python 包。编译库、运行时库和头文件通过 CMake 安装；调用方可以使用任意语言包装这套原生接口。源码目录与安装目录不需要相邻。

<a id="requirements"></a>

## 1. 构建与消费依赖

默认依赖面向 Linux x86-64，使用 LLVM/MLIR 23.1.4 稳定发行版。构建需要 C++17、CMake 3.28+、Ninja 和同一安装中的 LLVM/MLIR 23.1.x SDK。Python 仅用于标准库依赖获取脚本，不参与 ASK 库或 CLI 的编译、加载与执行。

| 用途 | 需要的组件 |
| --- | --- |
| 从源码构建 ASK | C++ 工具链、CMake/Ninja、zlib/zstd/libxml2 开发库，以及同一安装中的 LLVM/MLIR 23.1.x 稳定版。 |
| 消费 `ASK::Compiler` | 已安装 ASK SDK；公共接口使用标准 C++ 字符串及 JSON 文本，不要求 LLVM 头文件。 |
| 消费 `ASK::Runtime` | 已安装 ASK SDK；GPU 执行另需 NVIDIA 驱动与设备，不要求 CUDA Toolkit 头文件。 |
| 消费 `ASK::Core` | 已安装 ASK SDK，以及与 ASK 实际构建版本匹配的 LLVM/MLIR 开发文件。 |
| 编译自有 CUDA 图 | 调用方将 ASK 生成的 LLVM IR 交给匹配的 `llc` 和 CUDA `ptxas`。 |
| 执行外部 cubin/PTX | 调用方提供二进制、入口及 ABI；PTX 在驱动加载时 JIT。 |
| 将 Host `.o` 变成动态库 | 调用方提供系统链接器，例如 `cc -shared`。 |

Debian/Ubuntu 的系统构建依赖可这样安装；另须确保 `cmake --version` 为 3.28 或更新版本：

```bash
sudo apt-get install build-essential ninja-build zlib1g-dev libzstd-dev libxml2-dev
```

<a id="source-install"></a>

## 2. 构建并安装 SDK

```bash
cd /path/to/ask-source
python3 tools/fetch_deps.py
cmake --preset core
cmake --build --preset core
ctest --preset core --output-on-failure
cmake --install build/core --prefix /path/to/ask-sdk
```

脚本校验归档摘要，将 LLVM/MLIR 放到源码的 `.deps/`；CMake 按锁文件自动发现。依赖也可以放在独立目录：

```bash
python3 /path/to/ask-source/tools/fetch_deps.py --destination /path/to/ask-deps
llvm_sdk=/path/to/ask-deps/LLVM-23.1.4-Linux-X64
cmake -S /path/to/ask-source -B /path/to/ask-build -G Ninja \
  -DCMAKE_BUILD_TYPE=Release \
  -DLLVM_DIR="$llvm_sdk/lib/cmake/llvm" \
  -DMLIR_DIR="$llvm_sdk/lib/cmake/mlir"
cmake --build /path/to/ask-build
cmake --install /path/to/ask-build --prefix /path/to/ask-sdk
```

安装目录包含 `bin/ask-opt`、`include/ask/`、编译与运行时共享库、Core 静态库及 `lib/cmake/ASK/`。默认下载的版本、来源和 SHA-256 保存在依赖记录中；也可显式选择同系列稳定版 SDK。CMake 检查 LLVM/MLIR 的版本与安装前缀一致，构建报告记录实际版本。独立消费 Compiler/Runtime 无需继续保留 LLVM SDK。

<a id="wheel-install"></a>

## 3. 消费安装后的 C++ 接口

```cmake
find_package(ASK CONFIG REQUIRED COMPONENTS Compiler Runtime)
target_link_libraries(my_framework PRIVATE ASK::Compiler ASK::Runtime)
```

配置调用方项目时传入 `-DCMAKE_PREFIX_PATH=/path/to/ask-sdk`。只执行已有产物的项目可以仅请求 `Runtime`，不会因此查找 LLVM/MLIR。直接操作 MLIR 的项目则请求 `Core`，并把匹配 LLVM SDK 加入搜索路径。

可以单独构建 Runtime 的 SDK 消费测试：

```bash
cmake -S /path/to/ask-source/tests/cpp \
  -B /path/to/runtime-consumer -G Ninja \
  -DCMAKE_PREFIX_PATH=/path/to/ask-sdk -DASK_TEST_COMPONENT=Runtime
cmake --build /path/to/runtime-consumer
ctest --test-dir /path/to/runtime-consumer --output-on-failure
```

该测试通过断言检查 PTX 执行和资源复用，运行需要兼容的 NVIDIA GPU；仅构建不需要 GPU。`ASK_TEST_COMPONENT=Compiler` 或 `Core` 可选择另外两类消费测试。完整接口见[用户 API](用户API.md)，默认 CPU 检查与可选 GPU 检查见[测试体系](06-工程结构与测试体系.md#ctest-targets)。

<a id="cuda-and-adapters"></a>

## 4. CUDA 工具与第三方编译器

自有 CUDA 降级属于 ASK 核心；调用方配置 `llc` / `ptxas` 路径并负责工具执行和产物缓存。ASK Runtime 通过 `libcuda.so.1` 使用驱动，不依赖 `libcudart.so`。

第三方 DSL 的编译环境、worker 进程与版本策略由调用方维护。ASK 提供标准化请求、[协议 Schema](../schemas/)和通用执行接口；仅外部 kernel 的图不需要 ASK 自有代码生成工具。FugaTensor 自带 Triton worker，安装要求见 [FugaTensor 安装说明](../../fugatensor/docs/安装.md)。

<a id="framework-install"></a>

## 5. 与 FugaTensor 连接

先安装 ASK 原生 SDK，再在 FugaTensor 构建时通过 `CMAKE_PREFIX_PATH` 指向它。FugaTensor 自己构建 nanobind 扩展，直接链接 `ASK::Compiler` 和 `ASK::Runtime`；它的 Python 用户 API、图转换、外部编译器调用及磁盘缓存均留在自己的包内。

FugaTensor wheel 携带所需编译器和运行时共享库，不依赖另一个 ASK Python 包；运行环境无需 ASK 源码或 LLVM 开发 SDK。自有 CUDA 的 `llc` / `ptxas` 与第三方编译环境仍由调用方单独配置。两个仓库的跨仓链接仅供源码浏览，不参与库查找。
