# 05. 常驻运行时与多级缓存

返回核心思想：[常驻运行时与双层缓存](核心思想.md#ask-runtime-cache) · 相关细节：[外部编译器适配与边界内联](04-外部编译器适配与边界内联.md) · [图优化与自有代码生成](03-图优化与自有代码生成.md) · [FugaTensor 多后端执行](../../fugatensor/docs/architecture/04-ASK桥接与多后端执行.md)

无论计算图走的是[自有 CUDA 降级](03-图优化与自有代码生成.md#owned-cuda)还是 [Triton 值边界融合](04-外部编译器适配与边界内联.md#triton-fusion)，最终产出的都是标准的 `CUDAKernel`（包含 `cubin` 机器码与 `invocation` ABI v2 启动说明）。本章介绍 ASK 如何用零编译期 CUDA Toolkit 头文件依赖的 C++ 驱动层管理常驻显存、异步流同步、外部张量零拷贝接入以及跨进程双层缓存。

<a id="execution-session"></a>

## 1. 动态驱动加载与常驻 `ExecutionSession`

ASK 的 C++ 运行时库 `ask_runtime`（见 `include/ask/Runtime/CUDA.h`、`lib/Runtime/CUDA.cpp` 与 `bindings/runtime.cpp`）在构建期**不需要安装 CUDA Toolkit 头文件或链接 `libcudart.so`**：

- **按需 `dlopen("libcuda.so.1")`**：仅在用户真正创建 `ExecutionSession` 或调用 GPU 执行接口时才动态解析 CUDA Driver API 符号。在没有 NVIDIA 驱动的纯 CPU 开发机或 CI 容器上，ASK 依然可以完整编译、准备 IR、导出并检查 NVPTX LLVM IR。
- **Primary Context 与非阻塞 Stream**：每个 `ExecutionSession(device=0)` 保留指定显卡的 primary context（`cuDevicePrimaryCtxRetain`），并创建一条专属的非阻塞 CUDA stream（`CU_STREAM_NON_BLOCKING`）。
- **模块驻留与硬件门禁**：`kernel.prepare(session)` 将 `cubin` 加载为驻留 `CUmodule` / `CUfunction`（同一 `session` 内按 `cubin` 内容摘要自动去重复用，命中计入 `session.stats["module_hits"]`）。加载前会核对当前显卡的计算能力是否满足产物的目标 `arch`、动态共享内存上限以及 `required_element_types`（例如在低于 `sm_80` 的显卡上拒绝加载含 `bf16` 的模块）。

```python
from ask import ExecutionSession

with ExecutionSession(device=0) as session:
    exe = kernel.prepare(session)
    x = session.from_host(values, shape=(2, 8), dtype="f32")
    y = session.tensor((2, 8), "f32")
    for _ in range(100):
        done = exe.submit(x, y)   # 热路径：零模块重载、零显存分配、零主机拷贝
    done.wait()
    host_out = y.to_host()
```

<a id="device-tensor-and-cai"></a>

## 2. `DeviceTensor` 与 `__cuda_array_interface__` 零拷贝互操作

`ExecutionSession` 管理两类设备缓冲区，统一由 `DeviceTensor` 封装：

1. **自有显存张量**：通过 `session.tensor(shape, dtype)` 或 `session.from_host(values, shape=..., dtype=...)` 在当前会话 stream 上分配和拷入；支持零元素空张量（`nbytes == 0`，无需物理分配设备指针即可安全进出多端口 kernel）和零维标量张量。`DeviceTensor` 自身也实现了标准 `__cuda_array_interface__` v3（携带当前会话 `stream` 指针），可直接零拷贝传给外部生态。
2. **外部零拷贝借用（`session.from_cuda_array(obj)`）**：直接消费外部框架或另一个 `ExecutionSession` 暴露的 `__cuda_array_interface__`（v2 或 v3）：
   - 严格校验 `typestr`（包括 `|b1`、`<i4`、`<i8`、`<f4`、`<f2` 以及 `bf16` 描述）、连续行主序 `strides`、非只读属性（当作为输出端口时）以及设备归属。
   - **自动跨流同步**：若生产者描述符提供了不同于当前会话的 `stream` 句柄，导入或每次提交前会在生产者 stream 上记录 `CUevent`，并在当前会话 stream 上执行 `cuStreamWaitEvent`，无需阻塞 CPU 主机线程即可保证 GPU 读写顺序。
   - **宿主生命周期安全延长**：借用的 `DeviceTensor` 持有外部 Python 宿主对象引用；提交异步 kernel 后，会话后台引用队列会一直保留该 Python 对象，直到对应的完成 `CUevent` 在 GPU 上真正结束，彻底杜绝 Python `del` / GC 提前释放外部显存导致的悬挂指针访问。

<a id="async-events"></a>

## 3. 热路径校验、别名防护与异步 `Event`

在高频循环中调用 `exe.submit(in_tensor, out_tensor)` 或多端口 `exe.submit_many(inputs, outputs)` 时：

- **提交前轻量校验**：C++ 绑定层直接核对每个端口的所属 `session`、元素类型、形状字节数以及输入/输出缓冲区**不发生显存区间重叠（aliasing）**；校验失败绝不递增 `session.stats["launches"]`。
- **线程安全并发提交**：会话内部对驱动状态加细粒度互斥保护，耗时等待操作释放 Python GIL，支持多线程并发向同一 `ExecutionSession` 提交任务或读取 `session.stats`。
- **显式同步边界**：`submit` / `submit_many` 立即返回 `Event` 对象而不阻塞主机；调用 `event.wait()`、`session.synchronize()` 或 `tensor.to_host()` 时才等待对应 GPU 工作完成。关闭会话（`session.close()` 或退出 `with` 块）会自动同步在途任务并有序释放缓存的模块与事件池。

> [!NOTE]
> `CUDAKernel.run(values)` 仍保留为单输入单输出、同 shape/dtype 的一步式同步列表验证入口（内部临时走一次拷入、执行与拷出），适合写简短单测；真实框架引擎（如 [FugaTensor 的 `Engine`](../../fugatensor/docs/architecture/04-ASK桥接与多后端执行.md#engine-lifecycle)）全程使用常驻 `ExecutionSession` 与 `submit_many`。

<a id="two-tier-cache"></a>

## 4. IR 与可执行产物双层持久缓存

在 `Compiler.compile_cuda(..., cache_dir=...)`（实现见 `python/ask/gpu.py`）中，编译耗时最重的两个阶段分别由两层独立的磁盘持久缓存加速：

| 缓存层级 | 命中时跳过的阶段 | 缓存键（SHA-256）组成部分 | 状态查询位置 |
| --- | --- | --- | --- |
| **第一层：IR Cache** | 外部适配器 worker 编译（如 Triton JIT）、边界校验、LLVM 内联与 `--optimize-llir` | 准备并规范化后的 ASK IR、目标架构与开关、ASK 构建指纹、已启用适配器的安装与策略指纹 | `kernel.cache["status"]` / `kernel.report["ir_cache"]` |
| **第二层：Executable Cache** | `llc`（LLVM IR → PTX）与 `ptxas`（PTX → `cubin`） | 最终 LLVM IR 全文、代码生成参数（`arch`、`ptx_version`、`fp_contract`）、`llc` 与 `ptxas` 二进制文件指纹 | `kernel.codegen["executable_cache"]` / `kernel.report["executable_cache"]` |

两层缓存写入均采用“写临时文件 + 内容哈希校验 + 原子 `replace`”，读取时重新核对 `cubin_sha256` 与元数据完整性：

- 即使上层清除了内存里的 JIT 函数表，只要磁盘 `cache_dir` 仍在，再次编译同一张图会直接双层 `hit`，毫秒级返回可直接 `prepare(session)` 的 `CUDAKernel`。
- 一旦升级了 LLVM SDK、`ptxas`、Triton 版本或重新编译了 ASK，工具链指纹自动变化，旧缓存安全失效，不会加载到不兼容的陈旧产物。
