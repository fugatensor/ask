# 03. 图优化与自有代码生成

返回核心思想：[图优化与自有代码生成](核心思想.md#ask-owned-codegen) · 相关细节：[ASK IR 与数值语义](01-ASK-IR与数值语义.md) · [外部编译器适配与边界内联](04-外部编译器适配与边界内联.md) · [常驻运行时与多级缓存](05-常驻运行时与多级缓存.md)

当计算图中不包含 `ask.external` 时，ASK 完全依靠自有管线完成图级优化、CPU 目标文件生成和原生 CUDA kernel 降级。本章说明各阶段的优化边界与 ABI 设计。

<a id="graph-passes"></a>

## 1. 高层图优化（`lib/Transforms/Optimize.cpp`）

`compiler.optimize(module)`（或 `ask-opt --optimize`）在完成 `prepare` 校验后，按顺序运行三项确定性优化，并在 `report["optimization"]` 中汇报各项统计：

1. **严格保精度的常量与类型折叠（`fold_constants`）**：
   - 折叠标量 `ask.constant` 上的 `ask.add`、`ask.mul` 与 `ask.cast`，以及输入为 `ask.splat(c)` 的逐元素常量运算（结果直接归约为新的 `ask.splat(folded_c)`）。
   - 整数遵循精确的 32/64 位二补数回绕；浮点运算在 `llvm::APFloat` 的目标精度（`IEEEsingle` / `IEEEhalf` / `BFloat`）下按单步 RNE 执行；浮点转整数执行与运行时完全一致的饱和截断。
   - **禁止破坏舍入的浮点代数重结合**：对于运行时张量 `x`，不会把 `(x + c1) + c2` 合并成 `x + (c1 + c2)`，也不会把 `x * 0.0` 直接替换成 `+0.0`（因为 `NaN * 0.0 = NaN`、`-1.0 * 0.0 = -0.0`），确保常量折叠后的结果与未折叠直接执行逐位一致。
2. **死代码消除（`eliminate_dead_code`）**：
   - 删除不贡献于 `func.return` 且无副作用（`effects = "none"`）的死算子。声明了潜在副作用的 `ask.external` 会被安全保留。
   - `ask.mark` 已在 `prepare` 阶段完成追踪提取并擦除，因此挂在死分支上的追踪标记不会人为阻止死代码消除。
3. **多输出逐元素融合分组（`fuse_elementwise`）**：
   - 将形状兼容、连通的无副作用自有逐元素算子划入同一个 `ask.fusion_group`（记录在操作属性与 `report["optimization"]["fusion_groups"]` 中）。即使某个中间值同时作为函数返回值和下游算子输入（如 `return t, t * 2`），也能留在同一融合组内单次遍历写出，无需退化为两次循环。

<a id="host-codegen"></a>

## 2. Host CPU 共享循环代码生成（`lib/Lowering/Host.cpp`）

`ask-opt --emit-llvm` 与 `--emit-object` 面向本机 CPU（如 x86-64）编译纯自有 ASK 图：

- **共享循环融合落实**：按 `fusion_groups` 把同一形状的逐元素链合并到同一个 `i64` 线性下标循环里，中间值全程留在 LLVM SSA 寄存器中，只有最终函数输出才写回内存缓冲区；零维标量（`shape = ()`，共 1 个元素）与零元素空张量（`numel = 0`，循环 0 次直接返回）自然统一处理。
- **简洁的 C ABI**：生成的函数名与 MLIR `func.func` 同名，物理参数依次为所有输入缓冲区指针加所有输出缓冲区指针（均一律使用 `noalias` 指针，要求调用方输出缓冲区与输入互不重叠）。编译报告 `report["inputs"]` / `report["outputs"]` 明确给出每个端口的 `shape`、`dtype` 和字节数，上层（如 [FugaTensor 的 `HostBackend`](../../fugatensor/docs/architecture/04-ASK桥接与多后端执行.md#host-backend)）只需 `cc -shared` 链接并用 `ctypes` 调用。
- **主机 `bf16` 硬件检查**：在生成目标文件前检查本机 CPU 是否具备原生 `bf16` 转换支持（汇报在 `--capabilities` 的 `host_bf16_hardware_supported` 中）；不支持的主机在编译含 `bf16` 的图时会明确拒绝，避免链接期缺失软浮点符号或静默走非标准路径。

<a id="owned-cuda"></a>

## 3. 自有 CUDA 降级（`lib/Lowering/CUDA.cpp`）

**纯自有 GPU 计算图不需要安装或调用 Triton。** 在 `core`（`ASK_THIRD_PARTY_COMPILERS=none`）构建下，`Compiler.compile_cuda(module, target={"backend": "cuda", "arch": 86}, ...)` 直接走 ASK 自有 CUDA 降级管线：

- **直接生成 NVPTX 原生 LLVM IR**：输出 `target triple = "nvptx64-nvidia-cuda"` 模块与 `define ptx_kernel void @<entry>(...)`，使用 `addrspace(1)` 全局显存指针。
- **自适应 32/64 位线程索引**：通过 `@llvm.nvvm.read.ptx.sreg.{ctaid,ntid,tid}.x` 计算一维全局线性线程号 `idx = blockIdx.x * blockDim.x + threadIdx.x`。当张量元素总数在 32 位有符号整数范围内时使用开销更低的 32 位索引算术；超大张量自动切换为 64 位索引。
- **异构多端口与边界情况**：支持单张图同时接收多个张量/标量输入、一次写出多个不同 dtype 的输出端口（例如在单次 kernel 启动中同时把 `x` 转换到全部 6 种目标类型），支持非整块大小（`idx < N` 尾块掩码保护）以及零元素空张量。
- **严格的浮点与架构约束**：
  - 生成的浮点算术不附加 `contract` / `fast` 标志，配合 `llc -fp-contract=off` 保证 `a * b + c` 按独立乘法和加法两次 RNE 执行，与参考值和 Host 后端严格对齐。
  - 若图中任何输入、输出或中间值出现 `bf16`，同时在编译期要求 `arch >= 80` 并在产物 `required_element_types` 中登记 `"bf16"`，由 [CUDA 运行时](05-常驻运行时与多级缓存.md#execution-session)加载时再次核对物理显卡的计算能力。

<a id="llir-cleanup"></a>

## 4. 原生 LLVM IR 清理（`lib/LLIR/Optimize.cpp`）

无论是自有降级生成的 LLVM IR，还是[外部编译器融合内联](04-外部编译器适配与边界内联.md#boundary-inliner)后的模块，都会经过 ASK 的原生 LLVM IR 清理管线（亦可由 `ask-opt --optimize-llir` 独立触发）：

- 运行标准 LLVM 函数内联收尾、控制流简化（SimplifyCFG）、指令合并（InstCombine）、死指令与未引用内部辅助函数清理，并剥离编译期临时使用的边界元数据。
- 对 `call asm`（尤其是带 `sideeffect` 或目标寄存器约束的内联 PTX）严格保持原样，绝不跨未知内联汇编乱序移动访存或误删同步指令（如 `bar.sync`）。
