# ASK 独立安装

返回文档目录：[ASK 文档](README.md) · 返回核心思想：[构建与绑定](核心思想.md#ask-frontend-build) · 相关细节：[构建参数与版本契约](02-前端接入与构建配置.md#version-contract)

ASK 独立构建并交付 `ask-compiler` Python 包。FugaTensor 必须依赖 ASK，但两者分别构建，通过包版本与接口契约连接。运行已安装的包不要求保留 ASK 源码，也不要求相邻目录存在另一份仓库。本文使用显式路径，不约定两个仓库的相对位置。

<a id="requirements"></a>

## 1. 先区分安装、构建与执行

当前依赖锁和 CI 面向 Linux x86-64，Python 包要求 Python 3.10+。wheel 中的 Python ABI、操作系统和架构必须匹配目标环境；本机生成的 Linux wheel 尚不代表任意发行版通用的 manylinux 包。

| 用途 | 额外需要的组件 |
| --- | --- |
| 安装兼容的 ASK wheel，准备或优化图 | wheel 已含 `ask._native` 和伴生 `ask-opt`；不需要 LLVM SDK、ASK 源码或第三方 Python 包。 |
| 将 Host `.o` 链接成可调用动态库 | 系统 C 编译器/链接器，如 `cc`。ASK 的对象代码生成已在包内。 |
| 从 ASK 源码或 sdist 构建 | C++17 工具链、Python 开发头、CMake 3.28+、Ninja、锁定的 LLVM/MLIR SDK；Python 构建依赖由 `pyproject.toml` 声明。 |
| 自有 CUDA 图编译与执行 | 匹配 ASK 锁的 LLVM `llc`、CUDA `ptxas`、NVIDIA 驱动和设备。SDK 可以放在独立工具目录。 |
| Triton 融合 | 带 Triton 适配器的 ASK 构建、Triton 3.7.1 的 worker 环境，再加上述 CUDA 工具与设备。 |

以下命令不假定包已经发布到 PyPI。先取得与目标环境兼容的 wheel，或按第 3 节从源码构建。示例中的 `/path/to/...` 均替换成实际路径。

<a id="wheel-install"></a>

## 2. 从 wheel 安装并检查

```bash
python3 -m venv /path/to/ask-env
/path/to/ask-env/bin/python -m pip install /path/to/wheelhouse/ask_compiler-*.whl
/path/to/ask-env/bin/python -m pip check
```

wheel 目录中应只有要安装的那一份 ASK wheel。无需设置 `PYTHONPATH`、`ASK_OPT` 或指向源码的工具路径。在任意工作目录检查安装结果：

```bash
/path/to/ask-env/bin/python -I - <<'PY'
from importlib.metadata import version
from pathlib import Path
import sys
import ask
from ask import Compiler, Module, TensorType

compiler = Compiler()
caps = compiler.capabilities()
assert ask.__version__ == version("ask-compiler") == caps["ask_version"]
assert Path(ask.__file__).resolve().is_relative_to(Path(sys.prefix).resolve())
assert Compiler(compiler.executable).capabilities() == caps
module = Module()
t = TensorType((4,), "i32")
graph = module.graph("identity", inputs={"x": t}, results=[t])
graph.return_(graph.inputs["x"])
assert compiler.prepare(module).report["phase"] == "prepared"
print(ask.__file__)
print(compiler.executable)
print(caps["third_party_compilers"])
PY
```

`-I` 排除当前目录和 `PYTHONPATH` 对模块导入的影响。最后一行是该包实际启用的适配器列表；默认核心 wheel 输出 `[]`。详细的隔离安装、Host 编译和数值执行检查见 [CI 验证](06-工程结构与测试体系.md#continuous-integration)。

<a id="source-install"></a>

## 3. 从任意位置的源码或 sdist 构建

源码目录可以是独立 checkout，也可以是已解压的 `ask_compiler-0.1.0.tar.gz`。确认目录中包含 `pyproject.toml`、`CMakeLists.txt`、`cmake/*.lock.json` 和 `tools/fetch_deps.py`：

```bash
cd /path/to/ask-source
python3 tools/fetch_deps.py
/path/to/ask-env/bin/python -m pip install .
```

`fetch_deps.py` 将校验后的 LLVM/MLIR 与 nanobind 放在这个源码目录的 `.deps/`，CMake 自动发现它们。`pip` 默认在隔离构建环境中安装锁定的 Python 构建依赖，并生成包含原生扩展的核心包。完成安装后，可以按第 2 节在源码目录之外验证。

SDK 也可以放在与任何仓库都无关的位置：

```bash
python3 /path/to/ask-source/tools/fetch_deps.py --destination /path/to/ask-deps
# 将该变量设为上一步输出的 LLVM SDK 目录，不是 ask-deps 的父目录。
llvm_sdk=/path/to/ask-deps/llvm-1f126a6d-ubuntu-x64-1
/path/to/ask-env/bin/python -m pip install /path/to/ask-source \
  -Ccmake.define.LLVM_DIR="$llvm_sdk/lib/cmake/llvm" \
  -Ccmake.define.MLIR_DIR="$llvm_sdk/lib/cmake/mlir"
```

SDK 的版本和修订必须匹配该份源码的锁文件，不能用任意系统 LLVM 替换。安装后的 CPU 路径不再读取这份源码或 SDK；CUDA 代码生成仍需要保留可用的 `llc`，C++ SDK 消费也需要匹配的 LLVM/MLIR 开发文件。生成可转交的 sdist/wheel 见 [分发产物](02-前端接入与构建配置.md#version-contract)。

<a id="cuda-and-adapters"></a>

## 4. 独立配置 CUDA 与可选 Triton

自有 CUDA 属于核心包，不必安装 Triton。调用 `Compiler.compile_cuda(...)` 时显式传入 `llc="/path/to/llvm/bin/llc"` 与 `ptxas="/path/to/cuda/bin/ptxas"`，并提供目标 `arch`；运行时通过 `libcuda.so.1` 使用 NVIDIA 驱动。工具和运行目录都不需要位于 ASK 源码树。

Triton 需要在构建时启用适配器；向核心包所在环境单独安装 `triton` 不会改变 ASK 的能力。可以在已有 SDK 的源码目录构建：

```bash
python3 -m venv /path/to/triton-env
/path/to/triton-env/bin/python -m pip install -r /path/to/ask-source/adapters/triton/requirements.lock
/path/to/ask-env/bin/python -m pip install /path/to/ask-source \
  -Ccmake.define.ASK_THIRD_PARTY_COMPILERS=triton \
  -Ccmake.define.ASK_TRITON_PYTHON_EXECUTABLE=/path/to/triton-env/bin/python
```

若 SDK 位于独立目录，继续传入第 3 节的 `LLVM_DIR` / `MLIR_DIR`。从带适配器的 wheel 安装则不需要源码构建这一步。运行融合时，worker 使用包内资源：

```python
from pathlib import Path
import ask
from ask import Compiler, CompilerEnvironment

assert "triton" in Compiler().capabilities()["third_party_compilers"]
worker = Path(ask.__file__).resolve().parent / "share/ask/adapters/triton/worker.py"
assert worker.is_file()
compilers = {"triton": CompilerEnvironment(
    python="/path/to/triton-env/bin/python", worker=str(worker))}
# 将 compilers 传给 Compiler.compile_cuda(..., compilers=compilers, llc=..., ptxas=...)。
```

保留整个安装包中的适配器资源目录，worker 同目录的 `fusion.py` 与 `dependencies.lock.json` 参与导出和版本校验，不应只复制单个 `worker.py`。

<a id="framework-install"></a>

## 5. ASK 与 FugaTensor 分别构建

两个项目分别产出 wheel，再安装到同一运行环境：

1. ASK 的构建环境获取锁定 SDK，独立生成 `ask_compiler-*.whl`，见 [分发产物构建](02-前端接入与构建配置.md#version-contract)。
2. FugaTensor 的构建环境只构建自己的原生图分析扩展和 Python 包，生成 `fugatensor-*.whl`；不要求安装 ASK，也不读取 ASK 源码、头文件或 LLVM SDK。
3. 运行环境安装两个兼容的 wheel。FugaTensor 当前声明必需依赖 `ask-compiler==0.1.0`，安装后执行 `pip check`，再运行 CPU 或 GPU 验收。

FugaTensor 的安装引导脚本消费已经构建好的 ASK 包，不负责构建 ASK。修改 ASK 时，在 ASK 自己的构建环境重新产出并安装 wheel；只修改 FugaTensor 时，无需重建 ASK。完整命令见 [FugaTensor 独立安装](../../fugatensor/docs/安装.md)。
