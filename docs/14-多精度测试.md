# 用同一张图测试多种精度

[返回顶层设计](核心思想.md#ask-c) · [类型与数值规则](10-上层框架接入.md#dtype-path) · [GPU 路径](12-GPU融合与IR缓存.md)

图只定义一次，测试时替换 dtype。输入数据和预期结果也跟着 dtype 变化，但不重新抄写一份算子链或 Triton DSL。这样增加一种精度时，会自动经过已有的形状、边界、融合和缓存检查。

## 2. 怎样增加一张图或一种精度

`build_module(dtype=..., external=True)` 构造 ASK P → Triton F → ASK Q。`external=False` 把中间计算也生成为 ASK 算子，供 host 路径使用。输入类型、常量类型、外部签名与语义声明都从同一个 dtype 得到。

`GraphCase` 只保存形状、常量、BLOCK、warp 数等参数。基础矩阵包含单元素、尾部掩码、多维形状、多站点、较长表达式和溢出；浮点类型还经过小数、特殊值和舍入测试。整数不参加仅有浮点含义的用例。

例如同一张 `ask-rounding` 图在 f32、f16 和 bf16 下使用各自的一个 ULP 构造乘加。图中的乘法、加法没有复制；只有数值尺度变化。`F-contract-enabled` 和 `F-contract-disabled` 也共用图，只改变原编译器的固定选项。

增加图形配置时，向 `GRAPH_CASES` 加一项。增加精度时，先接通生产代码中的类型链，再补测试格式参数和输入边界值，已有图不需要复制。确实需要新算子结构时，在图构造器里定义一次，再让各 dtype 使用它。

## 3. 预期结果不能跟着实现一起错

参考计算不调用 ASK 的数值编码器，也不读取生成的 LLVM 或 PTX 来决定答案。有限数先转换成精确有理数，再按目标格式做最近偶数舍入。每个 ASK 加乘后都舍入；只有 F 明确允许乘加收缩时，才对乘加整体舍入一次。

比较要求有限结果相等，并另外比较零的符号；这些格式的有限数都能被 Python binary64 精确表示，因此这相当于检查目标格式的值位。NaN 比较类别，不要求 payload。无穷、非正规数和溢出都有专门样本，不用放宽误差阈值掩盖错误。

参考函数另有固定答案的测试，例如 f16 的 `65520` 舍入到无穷、最小非正规数的一半舍入到零，以及 FMA 得到非零残差而分步乘加得到零。生产编码器还独立检查全部 f16 / bf16 位模式和直接舍入边界。

## 4. 怎样运行

在启用 Triton 的构建及兼容 GPU 上，用新的缓存和输出目录运行：

```bash
PYTHONPATH=python python3 examples/triton_fused_gpu.py \
  --ask-opt build/triton/bin/ask-opt \
  --triton-python /path/to/triton/python \
  --triton-worker adapters/triton/worker.py \
  --llc .deps/llvm-1f126a6d-ubuntu-x64-1/bin/llc \
  --ptxas /path/to/triton/backends/nvidia/bin/ptxas \
  --cache-dir build/new-precision-cache \
  --output-dir build/new-precision-results \
  --dtypes i32 f32 f16 bf16
```

`--cases tail multiple-sites ask-rounding` 选择图，`--dtypes f16 bf16` 选择精度；其余参数不变。`--extended` 加上大形状、更多启动配置和单因素缓存失效用例。旧的 `--float` / `--low-precision` 仍可使用。

运行前先列出有效组合和跳过原因；全部组合都不适用时直接报错。每个有效组合执行冷缓存和热缓存两次。两次都重新生成 cubin 并在 GPU 上运行，检查输出、dtype、ShapeSnapshot、入口、缓存状态及二进制摘要。`validation.json` 保存计划数量、完成数量、跳过记录、按 dtype 的比较数量及每次运行记录。完成数量必须等于计划，不能把少跑或零次执行算作通过。

bf16 不支持的设备走单独的拒绝测试：模拟 compute capability 7.5，确认抛出明确错误，而且没有创建 context、加载模块、分配设备内存或 launch。实际支持 bf16 的 GPU 负责数值验证；两种测试不能互相替代。通用 host 后端也用同一张 bf16 图验证明确拒绝，不以软件模拟冒充硬件支持。

本次在 RTX 3080 上跑完四种精度的基础矩阵：43 个有效组合，各执行冷、热两次，共 86 次。i32 跳过 5 个仅适用于浮点的用例。另用 `--dtypes f16 bf16 --cases same-shape changed-ask-constant changed-F-DSL changed-shape shape-2x3x17 wide-block` 完成 24 次专项执行。两组共比较 9134 个结果，缓存命中与未命中各 55 次，全部通过。
