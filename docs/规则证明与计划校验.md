# SUKA 规则证明与执行计划校验

<a id="plan-proof"></a>

## 1. 逻辑缓冲区可用性

ASK 在 `Session::prepareProgram` 中将公开输入、步骤读写端口和公开输出交给 [SUKA PASS 库](https://github.com/fugatensor/suka)。PASS 使用 `rules/plan_availability.suka` 的可用性规则：公开输入在首步前可用，已可用的缓冲区沿步骤顺序保持可用，步骤输出在该步之后可用。每次读取都须证明缓冲区在该步开始前可用；公开输出须在末步后可用。

结构检查仍由 ASK 执行，包括索引范围、输入唯一性、单一生产者、步骤端口与 kernel ABI 的匹配。SUKA 返回 `PASS` 后才创建 `PreparedProgram`；`FAIL`、`UNKNOWN` 和规则错误均拒绝该计划。SUKA 的推理资源上限适用于此处，超过上限的计划按 `UNKNOWN` 拒绝。

证明只在准备计划时执行，位于 Session 锁之外。证明完成后运行时重新检查会话状态；逐次 `submit` 不重复证明。

<a id="reuse-boundary"></a>

## 2. 显存复用边界

SUKA 提供容量、设备、时间区间与完成事件等事实的复用规则接口。ASK 当前在完成事件释放工作区后跨提交复用同一计划的中间缓冲区；事件状态、公开输出的所有权和在途 GPU 资源仍由 ASK 原生运行时管理。当前未按计划内活跃区间合并不同逻辑缓冲区。

图切分、算子融合和 IR 改写可以按候选变换生成待证事实，再接入对应规则。现阶段这些策略仍由 ASK 的现有优化与切分器决定。

<a id="build-dependency"></a>

## 3. 构建依赖

`cmake/suka.lock.json` 固定 SUKA 仓库地址和提交 SHA。CMake 构建时通过 `FetchContent` 获取该提交，将 `Suka::Pass` 静态链接进 `ASK::Runtime` 共享库。开发时可指定本地源码：

```bash
cmake --preset core -DASK_SUKA_SOURCE_DIR=/path/to/suka
cmake --build --preset core
```

已安装的 `ASK::Compiler` 与 `ASK::Runtime` 使用者只链接 ASK SDK；直接构建 ASK 源码时须能获取锁定的 SUKA 提交，或提供本地源码目录。
