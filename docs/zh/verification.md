# ASK PASS 执行计划静态校验

<a id="plan-proof"></a>

## 1. 准备计划时校验

`ASK::Pass` 是 ASK 自有的 C++ 静态校验库，接口与实现位于 [`lib/Pass/`](../../lib/Pass/)。校验器直接读取执行计划、缓冲区大小和槽位映射，检查结构约束与整数边界。

`Session::prepareProgram` 核对端口绑定和 kernel ABI，生成内部缓冲区的槽位映射，再调用 `checkAllocationPlan`。校验器检查索引、单一生产者、公开端口、映射完整性，以及以下数值关系：

| 目标 | 计划中的数据 | 检查条件 |
| --- | --- | --- |
| 每次读取可用 | 缓冲区的产生边界、读取边界 | `产生边界 <= 读取边界` |
| 公开输出可用 | 输出索引与各缓冲区的生产者 | 索引有效，缓冲区有唯一生产者或属于公开输入 |
| 槽位容量足够 | 缓冲区字节数、槽位容量 | `字节数 <= 容量` |
| 同槽生存期分离 | 槽位归属、产生步骤、最后使用步骤 | 相邻缓冲区满足 `前者最后使用 < 后者产生` |

Graph 模式还检查前驱索引严格小于当前步骤、前驱唯一，并通过依赖可达性确认每次读取发生在生产者完成之后。同槽相邻缓冲区要求旧生产者及全部读取步骤都能沿依赖边到达新生产者；未被读取的输出和库 scratch 仍包含生产者写访问。

公开输入的产生边界为 `0`，步骤 `i` 的输出产生于边界 `i + 1`，读取发生在对应步骤前。公开输出在最终边界可用，由合法索引和生产者完整性检查保证。缓冲区大小、槽位容量和边界使用 `size_t`，校验器直接比较计划中的原始数值。

校验在 Session 锁外执行，通过后创建不可变 `PreparedProgram`。内部结果为 `Pass` 或 `Fail`；数值条件失败时按读取、容量和相邻生存期列出诊断。准备接口以 `ASK execution plan validation failed` 为前缀抛出 `CUDAError`。

## 2. 槽位分配与执行

ASK 按生产步骤遍历内部缓冲区，槽位容量取其所有缓冲区字节数的最大值。普通 stream 模式复用生存期已结束的槽位；Graph 模式只复用当前节点祖先中已经完成全部访问的槽位。独立分支各自保留活跃存储。公开输入输出使用独立存储，同一步骤中的输入和输出保持不同槽位。

`checkAllocationPlan` 独立检查每个内部缓冲区恰好分配一次、槽位索引有效、每个槽位有使用者。它将各槽位的缓冲区按生产步骤排序：stream 检查相邻生存期严格分离，Graph 检查前一个缓冲区全部访问到后一个生产者的依赖路径。相邻占用者有序即可保证整个槽位中的访问有序。

每个在途提交持有独立工作区，每个槽位对应一个 `DeviceBuffer`。完成事件保留工作区，完成后复用。准备阶段将参数分类为冻结值、内部地址和公开端口地址；工作区创建时写入冻结值和内部地址，每次提交更新公开端口地址。执行循环直接使用已准备的参数和启动描述。

kernel 生产者须遵守声明的端口契约：读取 `inputs`、写入 `outputs`，访问限制在声明缓冲区内，端口地址的使用随该步骤完成而结束。运行时通过单 stream 顺序提交，或按冻结的依赖关系构建 CUDA Graph 节点。

槽位分配降低内部显存需求，静态校验器确认候选映射合法。图级常量折叠、DCE、融合分组与步骤切分由 ASK 的编译优化模块完成，见[图优化](codegen.md#graph-passes)。

## 3. 成功校验缓存

新计划通过线性遍历检查产生与读取边界，按槽位收集内部缓冲区，再排序检查相邻生存期。Graph 校验从待验证节点反向搜索祖先，检查数据和共享槽位的顺序要求；全部要求满足后结束搜索。校验使用本次调用的临时向量，调用结束后释放。

成功结果保存在有界的进程缓存中。键包含完整计划结构、各序列长度、缓冲区大小、槽位容量、全部分配项、调度模式和依赖边，按完整值比较。相同计划再次准备时复用成功结果；缓存最多保存 64 个键，键内容的累计长度上限为 65,536 个 `size_t` 元素，并按写入顺序淘汰。

缓存查询和静态校验都发生在计划准备阶段。`PreparedProgram` 执行时复用已确定的映射和参数；每次传入的公开缓冲区在提交入口检查设备、大小、可写性与别名。

<a id="build-dependency"></a>

## 4. 构建依赖

`ASK::Pass` 由本仓 `lib/Pass/Pass.cpp` 构建，`ASK::Runtime` 私有链接该静态库。安装包使用者通过 `ASK::Runtime` 消费校验后的原生执行计划。构建使用标准预设：

```bash
cmake --preset core
cmake --build --preset core
```
