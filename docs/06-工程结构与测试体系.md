## 1. 仓库目录结构

```text
ask/
├── CMakeLists.txt / CMakePresets.json / pyproject.toml
├── cmake/                  # LLVM / nanobind 锁文件、可选适配器白名单与 CMake 包导出模板
├── tools/
│   ├── fetch_deps.py       # 拉取与校验锁定版 LLVM/MLIR SDK 和 nanobind 源码
│   └── ask-opt.cpp         # 原生命令行编译驱动
├── include/ask/            # 公共 C++ 头文件（IR、Frontend、Transforms、Lowering、LLIR、Adapters、Runtime）
├── lib/                    # 公共 C++ 实现（ask_core、ask_compilers、ask_runtime）
├── bindings/               # nanobind 进程内 Python 扩展（ask._native：编译器桥接与常驻 CUDA 会话）
├── python/ask/             # Python SDK（IR 构造器、Compiler、双层缓存驱动、运行时封装）
├── adapters/
│   ├── registry.json       # 允许构建的第三方编译器名录
│   └── triton/             # Triton 3.7.1 适配器（worker、AST/标记融合、C++ 边界校验与专属测试）
├── examples/               # Python 与独立 C++ 接入示例
├── tests/                  # 单元测试、物理 GPU 测试、IR 夹具与共享数值参考库
└── docs/                   # 架构与工程文档
```

`.deps/`、`build/` 和编译运行缓存由 `.gitignore` 排除在版本库之外，依赖版本通过 `cmake/*.lock.json`、`adapters/*/dependencies.lock.json` 与 `tools/fetch_deps.py` 锁定。

## 2. 五个 CTest 测试集与运行方式

执行 `ctest --preset core`（前 4 项）或 `ctest --preset all`（全部 5 项）时运行以下目标：

| CTest 名称 | 入口位置 | 覆盖范围 |
| --- | --- | --- |
| `ask-compiler-adapter` | `tests/cpp/test_compiler_adapter.cpp` | C++ `CompilerAdapter` 注册表、白名单隔离与未知编译器拒绝。 |
| `ask-boundary-inline` | `tests/cpp/test_boundary_inline.cpp` | C++ 通用 LLVM 值边界内联核心（多参数、多站点、定长向量、非法 helper 与支配违规回滚）。 |
| `ask-unit` | `tests/test_*.py`（7 个模块） | 纯 CPU 单元测试：SDK 与单步 RNE 常量、`ask` IR 正反例校验与高层图优化、Host CPU 代码生成执行、自有 CUDA 降级与启动契约离线校验、缓存并发/损坏恢复与 CAI 描述符校验、6 种精度边界参考值，以及 `fetch_deps.py` 解压与 CMake 白名单测试。 |
| `ask-gpu` | `tests/gpu/test_gpu_*.py`（2 个模块） | 物理 NVIDIA GPU 测试（缺少驱动或 `ptxas` 时跳过）：`test_gpu_native.py` 验证自有 CUDA 全精度、6×6 转换、异构多端口、ABI v2 共享内存、零拷贝重复提交与并发流；`test_gpu_triton.py`（启用 `triton` 构建时）验证 `ASK → Triton → ASK` 融合、FMA 隔离、双层缓存命中与跨会话 `__cuda_array_interface__` 串联。 |
| `ask-triton` | `adapters/triton/tests/test_*.py`（4 个模块） | 启用 `triton` 适配器时注册：检验 `worker.py` 导出协议、AST 静态融合判定、Python 策略与旧产物迁移，以及不依赖物理 GPU 的 `ask-opt --fuse-external` LLVM 融合与防篡改校验。 |

单独运行某组测试：

```bash
# 运行纯 CPU 单元测试
PYTHONPATH=build/core/python:python:tests ASK_OPT=build/core/bin/ask-opt \
  ASK_BOUNDARY_INLINE_BIN=build/core/ask-boundary-inline-test \
  python3 -m unittest discover -s tests -p "test_*.py" -v

# 运行 GPU 硬件测试（core 测自有 CUDA，all 同时测自有 CUDA + Triton 融合）
ctest --preset all -R ask-gpu --output-on-failure
```

`tests/gpu/` 不放置 `__init__.py`，使顶层 `unittest discover -s tests` 仅发现 7 个纯 CPU 单测模块，物理 GPU 编译执行留给 `ask-gpu`。

## 3. 共享多精度测试矩阵与独立数值参考

`tests/support/` 提供各后端共用的数值参考与图矩阵：

1. **精确数值参考（`tests/support/pointwise.py`）**：用 Python 任意精度整数实现 IEEE-754 单步最近偶数舍入（RNE）、次正规数（subnormal）sticky bit、`fma` 单次舍入对比、32/64 位二补数回绕以及饱和 `cast_reference`。测试样本覆盖 `2**60 + k`（检验 64 位整数高位与低位精度）、`f16`/`bf16` 半 ULP 舍入边界、`-0.0`、`±inf`、`NaN` 以及非整块尾元素（如 `size = 129`）。
2. **矩阵规划器（`plan_matrix`）**：同一套图拓扑定义（多维形状、多标记站点、`F` 开启/关闭浮点收缩、混合精度 `f32` 中间累加等）在 Host CPU、自有 CUDA 和 Triton 融合测试间复用，按 dtype 与图拓扑正交去重。
