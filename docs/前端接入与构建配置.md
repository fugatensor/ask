# 前端接入与构建配置

ASK 提供 C++ 组件 `ASK::Compiler`、`ASK::Runtime`、`ASK::Core` 和命令行工具 `ask-opt`。FugaTensor 的原生绑定直接链接 ASK 共享库，向用户提供 Python API。

<a id="build-workflow"></a>

## 1. 依赖获取、构建与安装

构建使用 C++17、CMake 3.28+、Ninja 和同一安装中的 LLVM/MLIR 23.1.x 稳定版。`cmake/llvm.lock.json` 记录 Linux x86-64 SDK 23.1.4 的来源和摘要。ASK 的执行计划校验实现位于 `lib/Pass/`。依赖获取和工程检查脚本使用 Python 标准库。

```bash
python3 tools/fetch_deps.py
cmake --preset core
cmake --build --preset core
ctest --preset core --output-on-failure
cmake --install build/core --prefix /path/to/ask-install
```

获取脚本支持 `--only llvm`，检查 SHA-256、归档路径和软链，将获取记录写入 `.deps/<dir>/.ask-sdk.json`。CMake 自动查找 `.deps/` 中的 SDK；也可通过 `-DLLVM_DIR` / `-DMLIR_DIR` 指定同系列稳定版。LLVM 和 MLIR 须来自同一版本、同一安装。安装布局见[安装说明](安装.md)。

<a id="compiler-selection"></a>

## 2. 核心配置与外部编译器

`core` 预设构建 CPU/CUDA 降级和设备运行时。`ASK_TARGET_BACKENDS=host` 启用 Host 对象代码生成，`none` 关闭它；两种配置都保留 CUDA LLVM 降级。`ASK_ENABLE_CUBLASLT` 控制 Runtime 的库提供者，构建和动态加载要求见[CUDA 工具](安装.md#cuda-and-adapters)。

默认 CTest 运行 Compiler、Core、Pass 和 Primitives 测试。配置 `-DASK_TEST_CUDA=ON` 后增加 GPU 运行时测试，并在启用 cuBLASLt 时增加 matmul 矩阵；执行需有可用的驱动和设备。

调用方管理第三方编译器的 worker、运行环境和产物缓存。ASK 检查 `ask.external`，生成分区计划，再调度 cubin/PTX。FugaTensor 提供了 Triton worker；协议见[外部产物接口](外部产物与执行接口.md)。

## 3. Compiler 与 Runtime 接口

```cmake
find_package(ASK 0.1.0 EXACT CONFIG REQUIRED COMPONENTS Compiler Runtime)
target_link_libraries(my_framework PRIVATE ASK::Compiler ASK::Runtime)
```

`ASK::Compiler` 的公开头文件是 `ask/Frontend/CompilerAPI.h`。`ask::compiler::prepare`、`partition`、`codegen` 接收 ASK MLIR 字符串和具名选项，分别返回 `PrepareResult`、`PartitionResult`、`CodegenResult`。结果通过独立字段提供 IR、形状快照、外部请求、执行计划、步骤源码和目标 ABI/产物，`diagnosticsJSON` 用于阶段、溯源和统计信息。接口仅使用 C++17 标准库类型，具体字段见[编译接口](用户API.md#compiler-api)。

每次请求使用独立的 MLIR context，解析、优化和降级在该 context 内完成。失败抛出 `std::runtime_error`。`namespace ask` 中的 `prepareJSON`、`partitionJSON`、`codegenJSON` 返回 `{ir, reportJSON}`，CLI 同样提供完整 JSON 报告。

`ASK::Runtime` 的公开头文件是 `ask/Runtime/CUDA.h`，提供 `Session`、`PreparedProgram`、`DeviceBuffer`、`Kernel` 和 `Event`，支持顺序提交和 CUDA Graph replay。调用示例见[用户 API](用户API.md)。

<a id="cpp-sdk"></a>

## 4. 直接操作 MLIR 的 Core 接口

需要自定义 MLIR 构图或变换的宿主链接 `ASK::Core`，并提供与 ASK 实际构建版本匹配的 LLVM/MLIR SDK：

```cmake
find_package(ASK CONFIG REQUIRED COMPONENTS Core)
target_link_libraries(my_frontend PRIVATE ASK::Core)
```

`ask/Frontend/Compiler.h` 提供 `prepareSource`、`partitionSource` 和 `codegenSource`，返回含 LLVM JSON 对象的 `PreparedSource`。已有 MLIR 模块可直接调用 `prepareModule` / `optimizeModule`；这两个接口会修改模块，需要事务行为时由调用方克隆后提交。静态形状、准备流程与优化行为由[Core 测试](../tests/cpp/frontend.cpp)验证。

报告使用 `ask::reportJSON(result.report, result.floatPaths)` 序列化，保留外部配置中的浮点词法类型与负零。`floatPaths` 供序列化器使用。Compiler 和 CLI 共用该入口。

## 5. `ask-opt` 命令行参数

| 参数 | 用途 |
| --- | --- |
| `--capabilities` | 输出构建版本、目标后端和各后端支持的类型 |
| `--prepare` | 校验、静态形状推导、提取并擦除溯源标记 |
| `--optimize` | 准备后执行常量折叠、DCE 和自有逐元素融合分组 |
| `--no-constant-fold` / `--no-dce` / `--no-fusion` | 关闭对应的图优化 |
| `--partition` | 生成自有/外部/库步骤、逻辑缓冲区、依赖和 `step_sources`；支持 `--no-optimize` |
| `--emit-llvm` / `--emit-object` | 生成 Host LLVM 文本或对象文件；对象文件必须通过 `-o` 指定路径 |
| `--emit-cuda-llvm` | 配合 `--cuda-arch`、`--cuda-block-size`、`--cuda-ptx-version` 生成 CUDA LLVM 文本 |
| `--check-llir` / `--optimize-llir` | 验证或清理原生 LLVM IR |
| `--report-json FILE` | 将准备、分区或 ABI 报告写入文件 |

FugaTensor 默认调用共享库完成编译和执行；调用方使用 `llc` / `ptxas` 将 CUDA LLVM IR 转成 PTX/cubin。

<a id="version-contract"></a>

## 6. 版本与共享库

| 字段 | 来源与要求 |
| --- | --- |
| ASK 发布版本 | 根目录 `VERSION`，当前 `0.1.0`；CMake、共享库版本与 capabilities 共用 |
| C++ 包兼容性 | `ASKConfigVersion.cmake` 使用 `ExactVersion`；调用方使用匹配版本和兼容的 C++ 工具链 |
| Core 依赖 | LLVM/MLIR 须匹配 ASK 实际构建版本，且来自同一安装 |
| 构建身份 | `build_id` 记录构建目录、ASK 与 LLVM 构建信息和 Host 开关；编译缓存以实际共享库内容摘要区分构建 |
| 数据协议 | ASK IR/执行计划为 v1，外部 worker/规范化 CUDA invocation 为 v2，版本分别演进 |

安装产物包括 `libask_compiler.so`、`libask_runtime.so`、`libask_core.a`、公开头文件、CMake targets、`ask-opt` 和 LLVM 默认依赖记录。编译缓存应记录实际代码生成库的摘要，以区分同版本的不同构建；`ask::compilerLibraryPath()` 返回已加载的 Compiler 共享库路径。

共享库使用 C++ 标准库 ABI，调用方应采用兼容工具链。验证方式见[CI 与安装验收](工程结构与测试体系.md#continuous-integration)。
