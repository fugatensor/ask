# ASK、FugaTensor、Rin 跨项目审查报告

审查日期：2026-11-04。本报告保存 Rin 接入阶段的审查、修复与测量记录。当前 ASK 使用自有 C++ 静态校验器，构建和运行接口见[计划校验](规则证明与计划校验.md)；替换依据与落地验证见[成本评估](Rin成本与验证价值评估.md#delivery)。

该阶段的依赖为 FugaTensor → ASK → Rin：FugaTensor 负责张量、自动微分和第三方编译编排，ASK 负责数值编译与设备执行，Rin 负责通用规则推理。审查将证明和参数准备成本集中到计划准备阶段，精简跨层接口，并修复独立 SDK 安装与通用证明器的边界问题。

<a id="boundaries"></a>

## 测量版本的职责与构建依赖

| 项目 | 负责的内容 | 构建接入 |
| --- | --- | --- |
| FugaTensor | Fuga IR、自动微分、Python API、Triton worker、产物与磁盘缓存 | 通过安装后的 `ASK::Compiler` / `ASK::Runtime` 构建原生扩展 |
| ASK | MLIR/LLVM 编译、分区、kernel ABI、槽位分配、单 stream / Graph 执行 | 编译器使用 LLVM/MLIR；私有 `ASK::Pass` 包含 Rin 头文件 |
| Rin | 符号规则、结构化事实、整数比较、存在量词和证明状态 | C++17 单头文件；独立 CLI；显式开启的可选 C ABI |

ASK 的领域规则保留在 `rules/pass/`；Rin 的接口由 `Term`、`Fact`、`Obligation`、`Program` 组成。设备、缓冲区和槽位语义由 ASK 定义。FugaTensor wheel 携带配套 ASK 共享库。第三方冷编译的 worker 探测和依赖快照也保留在 FugaTensor：冷缓存依次启动身份探测、编译和编译后复核三个子进程，分别负责缓存键、生产者回执和依赖变化检查。worker 内部的 `probe` 与编译处于同一进程。现有依赖变化反例测试覆盖了复核的作用；进一步合并子进程需要将完整前后身份纳入编译回执。

修复了 Runtime 导出文件归属 Core 的安装错误，为 Compiler 和 Runtime 分别安装自己的头文件、目标和 package config。实测分别只安装 Compiler、Runtime 后，外部 CMake 工程均可构建并运行测试。动态依赖检查确认 Runtime 使用标准 C/C++ 库，Fuga 原生扩展使用配套 ASK 库。

## Rin 的实际作用与修改

原实现确实在 `prepareProgram` 中检查整份计划，非法读取和槽位冲突能够阻止执行。同时存在三项冗余：

- `checkReuse` 和单候选规则只有测试调用，已删除。
- 容量与生存期先由 ASK 比较成真假，再作为事实交给 Rin；现改为提交原始数值，由 `less` / `less_equal` 完成规则中的比较。
- 基线已经静态链接 Rin，但 C++ 包装仍经过 C ABI、复制字符串，并逐计划生成和解析规则文本；现直接包含头文件，固定规则解析一次，按结构化事实求证。

ASK 使用三条固定规则覆盖可用性、容量与生存期。成功证明以完整计划结构、序列长度、缓冲区大小、槽位容量及全部分配项为键缓存；最多 64 项，并限制键内容总量。缓存与求证只出现在计划准备阶段。

槽位分配算法原先就能将四步串行链的三个内部逻辑缓冲区放入两个物理槽位。Rin 的作用是检查候选映射的合法性。本轮保留该显存规模、数值 IR 和 kernel 步骤数，新增收益来自证明准备、缓存和启动参数复用。

通用证明器的独立审查还发现：结构化接口中的用户符号可碰撞存在量词生成的见证名称。见证已使用独立内部身份，并加入回归断言；CLI 和可选 C ABI 共用同一证明核心。

<a id="launch"></a>

## cubin 参数与执行边界

公开 C++ 接口继续使用 `Session::load`、`PlanStep` 和 `prepareProgram`。布局计算与 CUDA 参数数组由 ASK 管理，上层按逻辑缓冲区和标量填写计划。

准备阶段检查物理 kernel ABI、启动配置、端口与计划，并将参数分成冻结值、内部地址和公开端口地址。工作区建立时一次构造参数存储与启动描述；提交时仅更新包含公开端口的步骤。Graph 更新只访问这部分节点。参数存储随每个工作区持有，按物理参数数量线性增长，以常驻主机存储换取提交时的分配和拷贝减少。

删除了执行阶段对已证明内部槽位的重复检查，以及逐参数的 scalar/null/buffer 分支和数组重建。提交入口保留对本次传入缓冲区的设备、大小、可写性与别名检查，完成事件管理在途工作区。

FugaTensor 将三次重复契约校验合并为准备入口的一次校验，统一使用 `parameter_types`，删除兼容参数 `expected_parameters` 和测试专用 `_parameters` 生产方法。混合标量、null 指针和 Graph 地址变更直接通过公开加载与提交接口测试。

## 测量结果

环境为 WSL/Linux、GCC 14.2、Release `-O3 -DNDEBUG`、NVIDIA RTX 3080，CUDA 驱动报告 615.65.06。旧实现从 ASK `39f9117`、Rin `c92a99c`、FugaTensor `d52be36` 提取到独立临时目录，采用同等优化编译。测量代码独立于生产代码，完成后删除。

计划证明使用四种链长度和两槽分配；首次调用包含该进程的必要初始化，旧版重复调用取五次均值，新版缓存取 1,000 次均值。单位为微秒：

| 步骤 | 旧版重复证明 | 新版首次证明 | 新版缓存命中 |
| ---: | ---: | ---: | ---: |
| 4 | 179.2 | 448.1 | 0.36 |
| 16 | 1,569.1 | 680.6 | 0.58 |
| 64 | 21,564.9 | 2,775.5 | 1.94 |
| 150 | 117,027.0 | 6,631.7 | 4.98 |

短计划首次调用包含固定规则初始化；150 步首次证明耗时约为旧版的 1/17.6。重复准备相同计划时直接复用完整证明结果。

CUDA 计时使用每个 kernel 处理四个 i32 的串行链，预热 30 次，每轮 500 次提交，旧版和新版交替运行五轮，再取各轮中位数的中位数。公开地址固定，计时分别覆盖 `submit` 和 `submit` 加事件等待。

单位为微秒：

| 提交方式 | 步骤 | 旧版提交 | 新版提交 | 旧版提交并等待 | 新版提交并等待 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 普通 stream | 1 | 13.95 | 13.16 | 46.36 | 46.00 |
| 普通 stream | 4 | 37.74 | 37.93 | 74.82 | 75.74 |
| 普通 stream | 16 | 145.72 | 139.02 | 252.68 | 249.27 |
| 普通 stream | 64 | 657.19 | 713.03 | 988.32 | 1,015.44 |
| CUDA Graph | 1 | 11.68 | 12.67 | 40.62 | 42.20 |
| CUDA Graph | 4 | 12.52 | 12.37 | 47.94 | 45.51 |
| CUDA Graph | 16 | 15.10 | 12.79 | 61.40 | 61.07 |
| CUDA Graph | 64 | 28.12 | 12.93 | 116.07 | 107.76 |

64 步 Graph 的提交耗时下降约 54.0%，提交并等待下降约 7.2%。普通 stream 的结果随规模有升有降，64 步提交并等待在本轮上升约 2.7%；收益集中在多步骤 Graph 和计划准备。

独立统计热提交的 C++ 堆分配次数：1/4/16/64 步的旧版分别为 27/36/72/216 次，新版均为 22 次。这里统计完整提交调用；参数模板与内部地址在工作区创建时完成初始化。

FugaTensor 的独立准备微基准采用相同 PTX 包和替代原生加载器，以线程 CPU 时间隔离 Python 契约及文件校验成本，七轮、每轮 1,000 次：中位数由 334.2 降至 240.7 微秒，下降 28.0%。该项测量范围为 Python 准备阶段。
