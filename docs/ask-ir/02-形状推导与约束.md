# 形状推导：把每个结果的尺寸算清楚，再开始降级

[返回顶层设计：A 层](../核心思想.md#ask-a) · [ASK IR 目录](README.md) · [A 层总体说明](../01-A层高级IR与区域规划.md)

本文规定拟实现的 ASK IR 形状推导流程。ASK IR 是 A 层的 MLIR `ask` dialect，用来具体表示 `SemanticModule`；B/C 层的 LLIR 仍然是原生 LLVM IR。操作和类型的完整定义见[结构、类型与操作](00-结构类型与操作.md)。

继续使用 `P: t=x+1 → F: u=t*2 → Q: y=u+3`。现在输入 x 有 10 个 i32 元素。形状推导要回答的是：t、u、y 是否也各有 10 个元素，哪些声明能证明这一点，以及哪一步发现矛盾。它不需要运行 F，也不需要知道这些元素以后由几个线程处理。

## 1. 先分清输入事实、待检查的声明和未知尺寸

本次编译请求给出 x 的具体形状 `[10]`。入口类型、操作属性和外部语义注册再提供其他信息。比如 F 的规则声明“输出形状与输入相同”，Q 的加法要求两个输入形状相同。这些信息共同决定结果，不能只挑一个看起来方便的结果类型。

构图和推导过程中允许 `tensor<?xi32>`。它表示 rank 已知为 1，但这一维还没有确定；不是长度为零，也不是任意长度都已经可以执行。首版不接受未知 rank，所有参与降级的张量在冻结前都必须有具体尺寸。

两个类型都写成 `tensor<?xi32>`，不表示其长度相等。给每个尚无来源关系的未知维度分配不同变量，例如 `d_x_0` 和 `d_z_0`；只有操作语义或已核对的输入约束，才能把它们联系起来。MLIR 的 `RankedTensorType` 能表达已知 rank 和动态维度，但不会因此替 ASK 证明两个 `?` 相等。[MLIR RankedTensorType](https://mlir.llvm.org/docs/Dialects/Builtin/#rankedtensortype)

操作显式写出的结果类型也是需要检查的声明。例如 F 写 `tensor<10xi32>`，不是 F 实际返回 10 个元素的独立证明。已有规则若推出 `[9]`，应报冲突，不能优先相信显式类型。入口形状则要与本次编译特化绑定；运行时仍须确认调用实参符合这份特化。

标量 i32、`index` 和 rank 为零的 `tensor<i32>` 分别处理。前两者不是张量，后者的形状为 `[]`、元素数量为 1。`!ask.token` 只表示效果顺序，不加入张量维度推导；有状态 `ask.external` 的 token 输入输出也不参与广播或形状相等检查。

## 2. 用 ShapeEnv 保存推导过程，不把表达式塞进每个类型

MLIR 类型保存 rank、元素类型和已经确定的维度。尚未写成具体维度的关系放进 `ShapeEnv`，由它管理每个张量逻辑值的状态：

```text
ShapeEnv[(ValueId, semantic_revision)] = ShapeState {
  dims: DimExpr[]
  constraints: ConstraintId[]
  provenance: FactId -> Source
}
```

`dims` 的长度就是 rank。`DimExpr` 可以是非负整数、来自某个输入轴的变量，或规则产生的表达式。首版只实现常量求值、等式传播及本篇操作需要的简单乘积、整除和范围检查；不能化简的表达式留着，不猜一个尺寸。

`constraints` 指向这些表达式必须满足的关系，例如两个轴相等、reshape 前后元素数相等、slice 不越界。`provenance` 记录事实来自哪个入口特化、操作属性、形状规则版本或等式传播。诊断需要它说明“9 从哪里来，10 又从哪里来”，冻结时也要知道用了哪些前提。

这里的 `ValueId` 是逻辑值身份，`SSARef` 才定位某个 MLIR SSA 定义。`ask.mark` 的输入与结果是两个不同的 SSA 定义，`traceIdentity` 将它们关联到同一个逻辑 `ValueId`，因此复用一份 `ShapeState`。两个 SSA 类型从构图起就必须相同，后续细化时一起更新。不能通过给两个定义重复分配同一个 SSA 编号实现这件事；标记自身也不能断言新形状。详见[标记算子与追踪](01-标记算子与追踪.md)。

reshape、transpose 和 slice 产生新的逻辑值与形状记录。以后即使它们与输入共用一个 buffer，也不能共用输入的 `ValueId`；存储是否相同与逻辑形状是否相同是两回事。

尺寸计算使用数学整数或带溢出检查的算术。本例张量内容按 i32 回绕，尺寸不回绕。每一维先检查非负和类型表示范围；算元素数量、描述符和分配大小时再检查各自的范围。形状 `[0, M]` 的元素数为零，但 M 自身仍须合法；不能先做溢出的乘法，再碰巧乘零。

## 3. 每种操作怎样产生结果和约束

### 常量、splat 与逐元素运算

`ask.constant` 产生标量，形状分析只读取被用作形状参数的编译期常量。普通数据常量 1、2、3 不应被误当成张量维度。

`ask.splat(scalar, shape)` 将标量填到给定形状，结果元素类型来自标量，维度来自显式 shape。标量数值本身不必已知，例如把一个运行时 i32 标量填成长度 10 的张量，结果形状仍然是 `[10]`。目标形状包含零时，没有需要填入的元素。

`ask.add` 和 `ask.mul` 不隐式广播。两个标量要求标量类型相同；两个张量要求元素类型、rank 和各维尺寸相同，结果沿用这个形状。标量与张量混用先写 `ask.splat`，需要扩展张量轴先写 `ask.broadcast`。例如 `[10] + [1]` 不能直接通过。

如果两个输入当前分别为 `[d]` 和 `[10]`，规则产生要求 `d == 10`。它可以帮助约束推导，却不能冒充已经取得输入的具体长度；入口特化或其他已知事实仍须在冻结时使这个要求成立。若具体输入后来给出 `[9]`，必须报错。

### 显式 broadcast

`ask.broadcast` 明确给出目标形状和输入轴到输出轴的对应。轴对应必须覆盖每个输入轴，输出位置不能重复且必须在范围内。一个输入轴映射到输出轴后，尺寸必须相等，或者输入尺寸为 1；没有对应输入轴的输出轴按重复扩展解释。

例如把 `[2, 1]` 映射到 `[2, 5, 3]`，指定输入轴 `0 -> 0`、`1 -> 2`，得到输出索引 `(i,j,k)` 对应输入 `(i,0)`。推导必须检查这些明确的轴，而不是从右侧自动补齐。

零长度也按这条规则处理：`1 -> 0` 合法，结果为空，不读取输入元素；`0 -> 0` 合法；`0 -> 1` 和 `0 -> 5` 不合法。不能用 `max(input_dim, output_dim)` 代替检查，否则 `1 -> 0` 会被错误改成 1。

### reshape

`ask.reshape` 保持逻辑元素数量，结果形状来自目标维度列表。例如 `[10] -> [2,5]` 需要检查 `10 == 2*5`；是否可以不复制内存，要在后续布局和 buffer 处理中判断。

构图 API 可以在目标列表中接受最多一个 `-1`，表示待推导维度；进入规范形状记录后用变量表示，不能把负数写成实际 tensor 维度。这里 0 就是零长度，不表示“复制输入同位置维度”。

设输入元素数为 E，除未知轴外的目标维度乘积为 K。当 K 大于零时，先检查 E 能被 K 整除，再得到未知轴 `E/K`。例如 `[10] -> [2,-1]` 得到 `[2,5]`，`[10] -> [3,-1]` 则矛盾。

K 为零时单独处理：E 非零就是矛盾；E 也为零时，`0*d = 0` 不能唯一确定 d。比如 `[0,4] -> [0,-1]` 应要求调用方给出该维度，不能默认取 0 或 1。没有 `-1` 的 `[0,4] -> [0,7]` 则满足元素数相等。

### transpose 与 slice

`ask.transpose` 的 `perm` 必须是输入轴的完整排列。约定 `out[j] = in[perm[j]]`，因此输入 `[2,5]`、`perm=[1,0]` 推出 `[5,2]`。重复轴、漏轴或越界轴直接报错，不留到 lowering 再猜。

首版 `ask.slice` 使用与输入 rank 相同的 `offsets/sizes/strides`，三者均须在降级前具体，stride 为正，size 非负，不做隐式裁剪。每个结果维度等于对应 size。size 大于零时，检查 `0 <= offset` 且 `offset + (size-1)*stride < input_dim`；size 为零时，允许 `0 <= offset <= input_dim`，不求一个并不存在的最后元素地址。

所有轴分别检查，地址表达式运算也必须防溢出。首版负 stride 返回不支持，不能先取绝对值继续编译；未来加入反向切片时再定义它的范围和元素顺序。

### reduce

`ask.reduce` 的 axes 必须唯一且在范围内，`keepdims` 决定删去这些轴还是把它们替换为 1。例如 `[2,5]` 沿轴 1 归约，结果为 `[2]`；开启 keepdims 后为 `[2,1]`。归约全部轴且不保留维度得到 rank 为零的 tensor，不是自动变成标量。空 axes 表示不减少任何轴。

输出形状能算出来，不等于归约数值有定义。若某个输出元素要归约的元素数为零，操作语义必须规定单位元或初值，例如 sum 的零；没有空域结果定义的归约应拒绝这种输入。输出本身没有元素时不会计算归约值，但仍检查语义注册中明确要求的输入前提。累加类型和结果元素类型由归约语义决定，不能由形状推导顺手改动。

## 4. 外部 F 通过语义注册给出规则，不执行内核来猜

图入口收到上层已经生成的基础 ASK IR。上层用 `ask.external` 标明交给第三方编译器的边界，并提交该编译器的 DSL 片段及实现引用；形状规则则来自上层注册、带版本的语义或 shape contract。本例 F 的规则只需返回“唯一张量输出与唯一张量输入同形状、同元素类型”。ASK 在编译这段 DSL 之前完成形状推导并冻结结果，不运行 DSL、不调用 Triton，也不读取设备来猜形状。

冻结后，编译驱动才按 `ask.external` 的实现引用把 DSL 路由给对应导出器。返回的 `port_map`、物理签名和特化信息用于核对：这份产物能否按已确定的形状和端口调用。它们不反过来定义图的形状；若与快照冲突，就报告产物或绑定不匹配，不能从 LLVM IR 指针反猜尺寸、覆盖快照后继续执行。

规则接口按纯函数设计：

```text
infer_shape(op, operand_facts, shape_parameters,
            declared_result_types, semantics_snapshot)
  -> {result_expressions, required_constraints, sources}
```

相同输入和规则版本必须得到相同结果。回调不能修改 IR、分配输出 buffer、发起外部编译或读取张量数据。缺少尺寸时返回部分表达式和缺失原因；发现具体矛盾时返回定位到操作和轴的诊断。工作队列由 ASK 管理，回调不递归调用整个推导器。

没有自动推导规则时，可以提供显式输出类型和已注册、带版本的形状检查规则。检查规则接收输入特化、声明的输出尺寸和形状参数，确认这组尺寸是该操作允许的实例。显式类型本身不能替代这一步；没有可检查的规则，首版停止降级。

这仍不等于自动证明任意外部代码实现了语义。注册方保证实现与语义对应，接入测试验证代表性输入；调用前再检查实参尺寸与冻结记录相符。声明输出 10 个元素但真实代码写 11 个，是外部实现错误，不能指望从裸指针参数中找出真实形状来修补。

依赖张量内容的输出长度，例如按输入数值筛选后得到的精确长度，不属于首版静态 shape。不能运行一次 F，把那次结果长度当成所有输入的形状，也不能把容量上界当成实际长度。需要时由上层分段处理，或另行定义“固定容量加有效长度”的不同算子语义。

## 5. 用工作队列传播，直到没有新事实

计算图本身没有图级循环，可以先按拓扑顺序遍历。之所以仍使用工作队列，是因为同一维度可能连接多个使用者，结果类型或形状相等约束也可能提供反向信息。一个新事实到来后，需要重新检查受它影响的操作，不必重跑全图。

初始化时从本次输入特化、静态类型和形状属性建立事实；声明的结果类型另外登记为待核对条件。每个未知轴分配自己的变量，再为各操作建立维度到使用规则的依赖索引。

```text
enqueue operations in topological order
while worklist is not empty:
    op = pop(worklist)
    delta = infer_shape(op, current_facts, registry_snapshot)
    delta = normalize_and_deduplicate(delta)
    changed, contradiction = merge(delta)
    if contradiction:
        return diagnostic_with_origins(contradiction)
    enqueue rules that depend on changed facts
```

`merge` 只增加有来源的事实。常量相等可以直接核对；显式的等式约束可以合并维度变量；reshape 的乘积等式只有满足前面列出的条件才能解出未知量。把两个变量加入同一个等式类，只说明程序要求它们相等，不表示任意实际输入已满足要求。

同一条规范化约束重复出现时不重新入队。未知变成确定表达式、表达式变成常量，都属于进展；不能让回调每次生成一个新的等价变量或不断扩大表达式，造成无穷工作队列。对规则调用次数和表达式大小设预算，预算耗尽返回未完成及剩余依赖，不能把“没有继续推导”当成成功。

静态图没有循环，不意味着能求解任意符号方程。首版不建立通用非线性求解器；无法判断的等式保留为未解决。未来符号维度仍来自调用形状参数，不因此引入根据张量内容执行的图级 while 或分支。

MLIR 提供 `InferTypeOpInterface` 和 `InferShapedTypeOpInterface` 作为操作推导类型或形状的入口。ASK 可以用它们暴露本地推导结果，但这里的约束来源、工作队列和冻结检查是 ASK 要实现的部分，接口本身不会自动完成这些工作。[MLIR Shape Inference](https://mlir.llvm.org/docs/ShapeInference/)

MLIR 的 `shape` dialect 提供形状计算及相等条件等操作，可供后续实现复用；首版并不要求把 `ShapeEnv` 全部物化成这一 dialect。尤其 `shape.broadcast` 使用自己的对齐规则，不能直接替代本篇显式轴映射的 `ask.broadcast`；`shape.assuming` 也不能用来绕过尚未证明的尺寸要求。[MLIR Shape dialect](https://mlir.llvm.org/docs/Dialects/ShapeDialect/)

## 6. 推导完成后，再把具体类型写回 IR

假设某个结果原来是 `tensor<?xi32>`，推导得到 `[10]`。先检查这个结果的所有现有声明是否与 `[10]` 相容，再准备 `tensor<10xi32>`。已有类型若为 `tensor<9xi32>`，这是错误，不是允许自动改成 10 的机会。

类型写回会影响定义—使用关系两端。`ask.mark` 的输入和结果必须一起细化；`ask.add` 的相等要求要重新检查；函数返回类型与返回值、函数参数与本次特化也要一致。不能只对一个 SSA result 调用 `setType`，就认为所有使用者已经满足自己的 verifier。

首版可以在模块副本中批量细化。通过 MLIR rewriter 创建替代操作或通知原地修改，并维护旧 `SSARef` 到新 `SSARef` 的对应；检查所有受影响的使用者、函数签名和返回值之后，再整体提交。模式内部的修改应经过 `PatternRewriter`，以便重写驱动获知变更。[MLIR Pattern Rewriting](https://mlir.llvm.org/docs/PatternRewriter/)

若类型细化改变了图的类型/形状约定，提交时更新 `semantic_revision`，推导状态和来源记录一起重绑定到该版本，随后再冻结快照。不能发布语义版本为 r+1 的图，再把 r 版本的形状表当作当前结果。单纯收集推导事实不反复递增语义版本。

`ir_revision` 另外记录具体结构变化。插入或清除合法的 identity marker 不改变逻辑计算、端口与形状，只更新 IR revision、SSARef 和追踪记录；已有不可变 `ShapeSnapshot` 可按原 semantic_revision 继续使用。若改动确实改变语义版本，则必须重新核对并生成新快照和摘要，不能原地修改已冻结的对象。

后续图改写也必须说明形状影响：改 transpose 的 perm、reshape 的目标维度、slice 参数或外部语义版本，都会使依赖结果失效。只保留相同 `ValueId` 不能保住旧答案。重新接线后还要重建相关规则依赖，不能让工作队列继续沿已删除的 use 推导。

## 7. 通过冻结检查，才能把形状交给 lowering

固定点只表示当前规则没有更多结论。进入 lowering 前还要检查全部待执行张量的 rank 和尺寸具体、必要约束成立、显式类型与推导结果一致、输入特化已绑定，并检查元素数量与本次目标描述符能表示的范围。尺寸已知但超出实现或目标范围，应报不支持该尺寸，不应回绕后生成一个小分配。

至少分开以下结果，调用方才能知道接下来补什么：

| 结果 | 例子 | 处理 |
|---|---|---|
| 已确定 | x 的 `[10]` 经 F 同形状规则得到 u 的 `[10]` | 可写回类型并冻结 |
| 尚缺输入 | x 的维度变量没有本次特化值 | 要求具体形状；本轮不降级 |
| 无法唯一推导 | reshape 的 `0*d=0` | 要求显式尺寸，不选默认值 |
| 规则未支持或预算耗尽 | 某个外部形状关系没有可用算法 | 报告缺失规则或预算，本轮不降级 |
| 约束矛盾 | add 两侧为 `[9]` 和 `[10]` | 报错并指出两侧来源 |
| 记录过期 | 图已改，ShapeEnv 仍绑定旧 revision | 重新分析，不读取旧结论 |

通过后生成不可变的 `ShapeSnapshot`：

```text
ShapeSnapshot {
  semantic_revision
  shape_rule_versions
  shape_bindings          // ValueId -> rank, concrete dims, element_type
  input_specialization
  checked_constraints    // 约束 ID 与事实来源
  snapshot_digest
}
```

`shape_rule_versions` 包含内建规则与外部语义形状规则的版本。`shape_bindings` 给 lowering 提供具体循环界、逻辑结果尺寸与参数检查信息；它必须与当前 MLIR 类型逐项一致。`input_specialization` 用于检查本次调用，`checked_constraints` 用于解释为何接受，摘要用于把这份记录与后续产物及缓存绑定。

冻结不是把可变 `ShapeEnv` 指针交出去。修改形状或更换输入特化后，要重新推导和生成快照；旧产物继续引用旧快照，不能被原地改写。

之后的链条是 `ShapeSnapshot -> PortBinding/BufferBinding -> LLVM 调用说明`。tensor 降成指针以后，逻辑尺寸从这条链保留，不从 `ptr` 的类型猜回。布局、stride、分配字节数与目标地址空间在后续具体绑定时检查；形状相同不证明布局相同。详见[降级与信息保留](03-降级与信息保留.md)及 [B 层](../03-B层多源降级与低层归一化.md)。

`BoundaryMap` 是之后按需建立的元素与低层访问映射，可以没有。正常执行需要的形状与调用信息已经保存在上述路径中，不能等融合分析成功才补齐它们。

## 8. 把 10 个元素的例子顺着算一遍

下面是构图顺序的伪代码，不规定 MLIR 文本打印语法。标量 1 和 3 先显式铺成张量；F 的语义注册项说明逐元素乘二及同形状输出。

```text
x     = graph_input(tensor<10xi32>)
one   = ask.constant(1 : i32)
ones  = ask.splat(one, shape=[10])
t     = ask.add(x, ones)
tm    = ask.mark(t, mark_id="m_P_out", value_id="v_t",
                 port_id="P.out", role="output")
u     = ask.external(tm, semantics=mul2_v1, implementation=fixed_F)
three = ask.constant(3 : i32)
threes= ask.splat(three, shape=[10])
y     = ask.add(u, threes)
```

先得到 `shape(x)=shape(ones)=[10]`。add 检查两个输入各轴相等，确定 t 为 `[10]`。tm 的 SSA 定义不同，但与 t 指向同一个逻辑值，所以沿用同一份形状记录；这个标记没有增加任何新尺寸假设。

F 的纯形状回调读取 tm 的 `[10]`，给出 u 的 `[10]`。再由 Q 的 add 检查 u 与 threes，得到 y 的 `[10]`。所有数据结果最终为 `tensor<10xi32>`；标量常量仍为 i32，不能把它们改成长度 1 的 tensor。

如果构图时 u 的显式类型写成 `tensor<9xi32>`，在 F 的结果检查处就能报告“规则给出 10，声明给出 9”，同时指出 F 与该声明的位置；不必等 Q 失败，更不能去运行 F 测量输出。

冻结后，降级从快照得到 t/u 的长度 10。它可以选择循环，也可以选择带尾部掩码的分块实现；例如宽度 4 时最后一组只处理 2 个元素。这种处理宽度不改变逻辑 shape，后续若把宽度改成 8，仍应保留 `[10]`，只使对应的低层访问映射失效。

## 9. 验证每条规则究竟拦住什么错误

规则单元测试直接喂类型、属性和输入特化，不运行内核。基础用例覆盖同形 add/mul、scalar 经 splat、零元素张量、rank 为零的张量和 mark 前后相同形状。反例让 `[10]` 与 `[1]` 直接相加失败，避免隐式广播重新混入实现。

broadcast 要覆盖 `1 -> 0`、`0 -> 0` 与非法 `0 -> 1`，检查实现没有用 max 代替规则；reshape 覆盖整除失败和零乘积多解；transpose 检查重复轴；slice 检查零 size、末元素越界和地址计算溢出；reduce 区分有单位元与无空域定义。这些用例分别针对不同错误，不能只测最终 y 的数值。

传播测试让两个独立的 `?` 保持独立，再加入明确等式和具体输入，检查事实如何收敛。交换无依赖操作的遍历顺序，应得到同样的结果与冲突结论。重复调用纯规则不应增加等价约束，达到预算时也不能返回一个伪造的具体尺寸。

外部规则测试验证两件事：推导期间不会执行 F；显式输出类型不能绕过形状检查规则。规则版本变化后旧快照不能命中，未知或有状态 external 的 token 也不能被误计为张量输入轴。

最后做降级交接测试：细化类型、删除或克隆 mark、改写 slice 后，SSA 引用和 revision 仍相符；从保存的快照读回 `[10]`，检查生成的调用说明和 buffer 绑定保留这个长度。关闭可选追踪和融合时同样通过。完整 IR 例子与验证安排见[示例与验证](04-示例与验证.md)。
