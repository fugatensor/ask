# 03. 图优化与自有代码生成

返回核心思想：[图优化与自有代码生成](核心思想.md#ask-owned-codegen) · 相关细节：[ASK IR 与数值语义](01-ASK-IR与数值语义.md) · [外部编译器适配与边界内联](04-外部编译器适配与边界内联.md) · [常驻运行时与多级缓存](05-常驻运行时与多级缓存.md)

不含 `ask.external` 的计算图直接通过 ASK 自有管线完成高层图优化、CPU 目标文件生成或 CUDA kernel 降级。

<a id="graph-passes"></a>

## 1. 高层图优化（`lib/Transforms/Optimize.cpp`）

`compiler.optimize(module)`（或 `ask-opt --optimize`）在完成 `prepare` 校验后按顺序运行三项变换，并在 `report["optimization"]` 中输出统计：

1. **常量与类型折叠（`fold_constants`）**：
   - 折叠标量 `ask.constant` 上的 `ask.add`、`ask.mul` 与 `ask.cast`，以及输入为 `ask.splat(c)` 的逐元素常量运算（归约为 `ask.splat(folded_c)`）。
   - 整数遵循 32/64 位二补数回绕；浮点运算在 `llvm::APFloat` 目标格式（`IEEEsingle` / `IEEEhalf` / `BFloat`）下按单步 RNE 执行；浮点转整数执行饱和截断。
   - 不对含运行时张量的浮点表达式做重结合或代数化简（如不把 `(x + c1) + c2` 合并为 `x + (c1 + c2)`，也不将 `x * 0.0` 替换为 `+0.0`），保留各步舍入及 `NaN`、`-0.0` 语义。这里不承诺不同硬件产生相同的 NaN payload。
2. **死代码消除（`eliminate_dead_code`）**：
   - 逆序遍历单基本块，删除结果无使用者的自有纯操作（`constant`、`splat`、`cast`、`add`、`mul`），连带清理变得无用的前驱。`ask.external` 保守保留，即使声明为 `effects = "none"`；其它副作用声明目前会在校验时被拒绝。
   - `ask.mark` 已在 `prepare` 阶段提取并擦除，不会阻碍死分支消除。
3. **多输出逐元素融合分组（`fuse_elementwise`）**：
   - 按基本块顺序，将相邻且形状一致的自有张量 `splat` / `cast` / `add` / `mul` 划组，至少两个操作才标记 `ask.fusion_group`；纯标量计算可穿插其间，形状变化或 `ask.external` 等非自有操作会截断分组。操作属性及 `report["optimization"]["fusion_groups"]` 记录结果，同时作为函数返回值和下游操作数的中间值（如 `return t, t * 2`）可在共享循环内写出。

<a id="host-codegen"></a>

## 2. Host CPU 共享循环代码生成（`lib/Lowering/Host.cpp`）

`ask-opt --emit-llvm` 与 `--emit-object` 将纯自有 ASK 图降级为本机 CPU 代码：

- **共享循环生成**：按 `fusion_groups` 将同形状的逐元素链合并到同一个 `i64` 线性下标循环中，中间值保留在 LLVM SSA 寄存器，仅函数输出写回内存；0-D 标量（1 个元素）与空张量（`numel = 0`）走同一套逻辑。
- **C ABI**：生成函数与 MLIR `func.func` 同名。参数依次为全部输入、全部输出：标量输入按值传递，张量输入和所有输出使用指针。输出指针带 `noalias`，须与所有输入及其它输出缓冲区不重叠；输入之间可共享存储。`report["abi"]["functions"]` 中各函数的 `inputs` / `outputs` 给出 `kind`、`shape`、`dtype`、`element_bytes` 与物理参数序号，上层（如 [FugaTensor 的 `HostBackend`](../../fugatensor/docs/architecture/04-ASK桥接与多后端执行.md#host-backend)）据此分配缓冲区，通过 `cc -shared` 链接后用 `ctypes` 调用。
- **主机 `bf16` 检查**：生成目标文件前检查本机 CPU 是否具备原生 `bf16` 转换支持（对应 `--capabilities` 中的 `host_bf16_hardware_supported`），不支持时拒绝编译含 `bf16` 的图。

<a id="owned-cuda"></a>

## 3. 自有 CUDA 降级（`lib/Lowering/CUDA.cpp`）

在 `core`（`ASK_THIRD_PARTY_COMPILERS=none`）构建下，纯自有 GPU 图直接通过 `Compiler.compile_cuda(module, target={"backend": "cuda", "arch": 86}, ...)` 编译，不依赖 Triton：

- **NVPTX 原生 LLVM IR**：生成 `target triple = "nvptx64-nvidia-cuda"` 模块与 `define ptx_kernel void @<entry>(...)`，使用 `addrspace(1)` 全局显存指针。
- **64 位 grid-stride 循环**：读取 `@llvm.nvvm.read.ptx.sreg.{ctaid,tid}.x` 后扩展为 `i64`，按编译时固定的 block size 计算起始下标。grid 的 x 维最多为 65535，每次迭代增加 `grid.x * block_size`，因此大张量不要求按元素数无限扩大 grid。
- **多端口与边界处理**：支持多张量/标量输入、异构形状与 dtype 的多输出端口、非整块尾元素掩码保护（`idx < N`）以及空张量。
- **浮点与架构检查**：
  - 浮点指令不附加 `contract` / `fast` 标志，配合 `llc -fp-contract=off` 保证 `a * b + c` 按独立乘法和加法两次 RNE 执行。
  - 图中输入、输出或中间值包含 `bf16` 时，编译期要求 `arch >= 80`，并在产物 `required_element_types` 中记录 `"bf16"` 供 [CUDA 运行时](05-常驻运行时与多级缓存.md#execution-session)加载时核对物理显卡能力。

<a id="llir-cleanup"></a>

## 4. 原生 LLVM IR 清理（`lib/LLIR/Optimize.cpp`）

`ask-opt --optimize-llir` 对读入的原生 LLVM IR 执行清理；[外部编译器融合内联](04-外部编译器适配与边界内联.md#boundary-inliner)也会调用同一实现。自有 Host/CUDA 降级不会自动调用这项清理，后续目标代码生成由各自 LLVM 后端处理。

- 按顺序执行 InstCombine、SimplifyCFG、ADCE，跳过带 `optnone` 的函数；不启用通用函数内联、循环变换、向量化或模块级未引用函数删除。
- 移除已失效的 ASK 追踪元数据和指令级 ASK 附件，保留 `ask.abi`、`ask.shape_snapshot` 等模块接口元数据，并在报告中列出未验证的其它 ASK 命名元数据。
- 优化前后验证 LLVM 模块，并检查目标信息与对外函数 ABI 不变。内联 PTX 按其 LLVM `sideeffect`、操作数和约束语义参与优化；没有副作用且结果未使用的汇编可以被删除。
