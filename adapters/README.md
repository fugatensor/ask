# 第三方编译器适配器

每个第三方编译器的导出 `worker`、Python 策略、C++ 原生边界校验、CMake 构建规则、依赖锁文件和专属测试都集中隔离在 `adapters/<id>/` 目录下，不在公共编译或运行时核心里散落品牌分支。

- [registry.json](registry.json) 是中央显式白名单，仅记录允许构建的编译器 ID 到子目录名的映射。
- 构建时通过 `ASK_THIRD_PARTY_COMPILERS` 选择 `none`、`all` 或具体 ID 列表，CMake 只加载被选中目录的构建规则并生成静态注册表；未选中的适配器不会因为当前机器装了同名 Python 包而自动激活。
- 通用 CUDA 设备会话与内核启动属于目标后端（`lib/Runtime/`），只消费标准化的 `invocation` v2 执行契约，不归属任何单个编译器适配器。

当前已落地的适配器：[Triton 3.7.1](triton/README.md)。完整的插件注册接口、跨进程导出协议、通用 LLVM 值边界内联与 FMA 隔离机制见 [04. 外部编译器适配与边界内联](../docs/04-外部编译器适配与边界内联.md)，常驻执行与缓存机制见 [05. 常驻运行时与多级缓存](../docs/05-常驻运行时与多级缓存.md)。
