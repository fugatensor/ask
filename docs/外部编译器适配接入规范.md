# 外部编译器适配接入规范

返回核心思想：[外部产物与执行接口](核心思想.md#external-execution) · 相关细节：[可执行产物边界](外部产物与执行接口.md#binary-artifact) · [多 Kernel 执行计划](图切分与多Kernel执行计划.md#complex-external)

调用方实现并启动一个独立 worker。Worker 调用第三方编译器并提取执行信息；ASK 原生编译器生成标准化请求，调用方据此校验和缓存产物，再将二进制、端口绑定与启动配置交给 ASK Runtime。FugaTensor 已提供通用编排，Triton 用户通过 `ft.triton.environment(...)` 选择 worker 环境。接入其它编译器无需修改 ASK C++、注册构建目标或实现 Python 适配器基类。

<a id="adapter-contract"></a>

## 1. 进程接口

Worker 提供两个命令：

```text
worker --probe --request /path/to/request.json
worker --request /path/to/request.json --output /path/to/artifact.json
```

`--probe` 同时收到请求文件，可据源码和编译选项计算所用依赖的指纹。它向 stdout 输出 JSON，至少包含 `producer: {name, version}` 和非空字符串 `adapter_version`；生产者安装、被引用模块、依赖锁等会影响编译结果的内容也应通过指纹放入该 JSON。调用方应将整个探测结果纳入缓存键，并核对实际产物的 `producer` 与探测结果一致；FugaTensor 的通用编排执行这项检查。

编译命令读取请求文件，成功后写完整响应 JSON 并返回 0。失败时返回非零状态，诊断写入 stderr；调用方不能把失败视为另一种成功产物。Worker 应使用临时文件原子替换输出，避免留下半成品。Python worker 可使用独立解释器，宿主进程无需导入第三方编译器包。

<a id="worker-protocol"></a>

## 2. 请求协议 v2

请求来自 ASK 图准备报告的 `external_requests`，由调用方交给 worker。编译器 ID、图节点 ID 和函数名用于路由与报告，不传给 worker。协议字段如下：

| 字段 | 含义 |
| --- | --- |
| `protocol_version` | 整数 `2`。 |
| `source` / `entry` | 源码快照与入口名称，由 worker 解释。 |
| `signature` | 参数到 ABI 类型的映射。张量使用 `*i1`、`*i32`、`*i64`、`*fp32`、`*fp16` 或 `*bf16`；按值标量类型见下文。 |
| `source_bindings` | 与 `signature` 同名。指针绑定 `input:N` / `output:N`，端口编号连续且一一对应；标量直接绑定布尔、整数或有限浮点值。 |
| `constants` / `fixed_options` | 递归 JSON 编译期常量和固定选项，支持 null、布尔、整数、有限浮点、字符串、数组和对象，具体含义由 worker 定义。 |
| `target` | 显式 CUDA 目标，包含 `backend`、`arch`，可携带 `warp_size`。 |
| `grid` | 三个正整数，表示固定启动网格。 |
| `port_shapes` | 每个逻辑输入输出的具体形状，来自 ASK 图校验结果。 |

标量支持 `i1`（布尔）、`i8/i16/i32/i64`、`u8/u16/u32/u64`、`fp16/bf16/fp32/fp64`。`source_bindings = {"x": "input:0", "n": 1024, "scale": 0.5, "y": "output:0"}` 配合对应签名即可传入普通 kernel 标量参数；它们由 CUDA 启动 ABI 按值传递，区别于编译期 `constants`。整数按位宽检查，不截断或绕回；浮点按目标格式 RNE 编码。

这些启动值在图构造时冻结，随请求参与缓存和编译包身份；修改值需要重新构造调用，`PreparedProgram` 提交时只接受张量缓冲区，不覆盖冻结标量。编译期配置中的整数范围为 `[-2^63, 2^64-1]`。机器可读定义见 [external-compiler-request-v2.schema.json](../schemas/external-compiler-request-v2.schema.json)。实际张量内容不进入编译请求。

<a id="artifact-contract"></a>

## 3. 最小响应

响应必须恰好包含以下字段：

```json
{
  "protocol_version": 2,
  "format": "cubin",
  "payload": "<base64 编码的 cubin>",
  "entry": "kernel_entry",
  "target": {"backend": "cuda", "arch": 80, "warp_size": 32},
  "producer": {"name": "example", "version": "1.0"},
  "launch": {"grid": [1, 1, 1], "block": [128, 1, 1], "shared_bytes": 0},
  "arguments": ["input:0", {"type": "i32", "value": 1024}, "output:0"],
  "required_element_types": ["f32"]
}
```

`format = "ptx"` 时 `payload` 是 PTX 文本。`target` 必须与请求一致，`launch.grid` 必须等于请求网格；`block` 和 `shared_bytes` 来自实际编译结果。`arguments` 按物理参数顺序排列：每个张量端口恰好出现一次；标量写成仅含 `type`、`value` 的对象，类型、编码值和出现次数必须与请求一致；未使用且允许为空的指针可写 `"null"`。上例要求请求中有一个 `i32` 启动参数绑定 `1024`。

`required_element_types` 声明需要运行时校验的张量元素类型，调用方将它与端口类型合并后传给 `Session::load`。内部指令的架构要求由生产者按 `target` 编译保证，ASK 不逆向分析产物中的全部计算类型。

FugaTensor 的 [`normalize_artifact`](../../fugatensor/src/fugatensor/_ask/adapters.py) 根据请求构造 `port_map` 和 invocation v2，再校验产物并转换为原生计划。其它调用方可实现同一规则。响应不需要 LLVM IR、边界标记、编译器私有对象或重复的张量形状描述。机器可读定义见 [external-kernel-artifact-v2.schema.json](../schemas/external-kernel-artifact-v2.schema.json)。

## 4. 缓存与支持范围

FugaTensor 每次外部编译缓存查找前都执行带请求的 `--probe`；编译后再次探测，确认依赖身份没有在编译期间变化。缓存键覆盖完整请求、探测结果、worker/解释器文件摘要、环境变量和调用方编排实现；缓存命中仍校验产物。Worker 需要把自身导入的辅助模块和第三方依赖变化反映到 probe，不能只报告一个固定版本字符串。ASK C++ SDK 不维护这层文件缓存或 worker 进程。

当前支持普通 CUDA kernel 的静态连续多输入、多输出端口、指针与标量混合参数、固定启动配置和动态共享内存。需要非空 scratch、集群/协作启动或张量描述符的编译器产物，应明确拒绝；不得把实际资源需求伪装成 `null`。完整边界见 [可执行产物与端口](外部产物与执行接口.md#binary-artifact)。

<a id="conformance"></a>

## 5. 接入验证

新增 worker 至少验证：多端口与不同形状的请求、混合标量位宽与参数顺序、cubin/PTX 响应编码、动态共享内存、缓存命中与依赖变化、worker 失败、损坏产物、目标/端口不匹配，以及物理 GPU 数值结果。CPU 协议测试和设备执行测试分开记录；跳过设备测试不表示 kernel 已验证。

FugaTensor 的 [Triton worker](../../fugatensor/src/fugatensor/_triton_worker.py) 是调用方实现示例。其 Triton 版本和资源限制由 FugaTensor 维护，ASK 不锁定第三方编译器或要求其 LLVM 版本与 ASK 一致。
