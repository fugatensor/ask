# 外部产物与执行接口

返回核心思想：[外部产物与执行接口](核心思想.md#external-execution) · 相关细节：[外部算子声明](ASK-IR与数值语义.md#external-declaration) · [Worker 协议](外部编译器适配接入规范.md#worker-protocol) · [图切分与调度](图切分与多Kernel执行计划.md)

ASK 将每个 `ask.external` 保留为独立 kernel。调用方用第三方编译器生成 cubin 或 PTX，验证产物契约后，将二进制和启动描述交给 ASK C++ Runtime。第三方代码无需导出与 ASK 版本匹配的 LLVM IR。

<a id="external-execution"></a>

## 1. 图边界与职责

高层 `ask.semantics` 定义输入输出类型及形状规则，`ask.implementation` 保存源码、编译配置和逻辑端口绑定。原生编译器检查图并生成标准化请求；切分器在外部节点两侧划定边界，自有区域继续执行常量折叠、DCE 和逐元素融合。

例如 `P: t = x + 1 → F: 外部 kernel → Q: y = u + 3` 形成三个步骤。`t`、`u` 留在设备缓冲区，并把指针交给下一步骤；中间没有主机拷贝。Graph replay 可减少计划提交成本，但不改变各 kernel 的代码和融合边界。

ASK 维护请求与产物协议、图分区、原生 ABI 检查及设备调度。worker 进程调用、第三方版本策略、产物解析与磁盘缓存属于调用方；FugaTensor 的通用编排位于 `src/fugatensor/_ask/`，Triton 专属编译位于 [`_triton_worker.py`](../../fugatensor/src/fugatensor/_triton_worker.py)。两者均不参与 ASK 构建。

<a id="binary-artifact"></a>

## 2. 可执行产物与端口

Worker 协议接受 `cubin` 的 base64 二进制或 `ptx` 文本，并描述入口、目标架构、生产者、启动配置、物理参数顺序与所需元素类型，详见 [artifact 契约](外部编译器适配接入规范.md#artifact-contract)。

调用方根据 ASK 标准化请求中的 `signature`、`source_bindings`、`port_shapes` 构造统一 invocation v2，核对文件摘要和张量端口，再把实际字节交给 `Session::load`。适配器无需重复构造整套张量 ABI，也不返回 Python 编译对象、设备句柄或主机路径。PTX 在加载时由 CUDA 驱动 JIT。

执行边界使用静态连续行主序张量，支持六种 ASK 元素类型和多输出。协议支持 1–64 个物理参数；指针连接 `input:N`、`output:N` 或显式 `null`，标量按声明的 ABI 类型编码为字节。原生运行时按驱动报告检查参数数量、偏移和宽度，并在启动前检查线程数、共享内存、设备归属和存储别名。

`PlanArgument` 保存逻辑缓冲区索引或冻结标量字节，`PlanStep` 保存 kernel、grid、block、共享内存及输入输出集合。C++ 原生入口不接受 Python 对象；调用方负责将形状和 dtype 换算为字节数并验证完整的上层张量契约。

当前没有非空 scratch、描述符或协作/集群启动契约。外部产物保留生产者的数值策略，ASK 自有计算保持独立舍入和确定性转换。

<a id="worker-interface"></a>

## 3. 调用方配置 Worker

worker 的编译器 ID 对应 `ask.implementation.compiler`。调用方显式指定 worker 可执行文件，或第三方 Python 解释器与脚本路径；ASK 不扫描 entrypoints，也不设置编译器构建白名单。

FugaTensor 使用 `ft.triton.environment(python=...)` 配置自带 worker，接入方式见[上层执行说明](../../fugatensor/docs/architecture/ASK桥接与多后端执行.md#cuda-and-triton)。其他框架可以独立实现同一[请求/响应协议](外部编译器适配接入规范.md)。

只含外部步骤的图无需自有代码生成工具；混合图中的 owned 步骤仍由调用方执行 `llc` / `ptxas`。缺失 worker、非法请求、编译失败、损坏产物和 ABI 不匹配均应报错，不以其他计算路径掩盖。
