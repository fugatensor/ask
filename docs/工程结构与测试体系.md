# 工程结构与测试体系

<a id="repo-layout"></a>

## 1. 目录职责

```text
ask/
├── include/ask/           # 编译门面、MLIR/LLVM 与原生 Runtime 公共接口
├── lib/
│   ├── IR/               # ask dialect 与操作校验
│   ├── Frontend/         # 准备、能力报告、图切分及编译门面
│   ├── Transforms/       # 折叠、DCE、自有逐元素融合
│   ├── Lowering/         # 自有 Host/CUDA LLVM 降级
│   ├── LLIR/             # LLVM 导入、清理与数值辅助
│   ├── Pass/             # 执行计划、分配槽位与复用规则接口
│   └── Runtime/          # CUDA 计划、缓冲区、事件及 Graph replay
├── rules/pass/           # ASK PASS 规则源码
├── schemas/              # 执行计划与外部请求/响应 JSON 契约
├── cmake/                # LLVM/Rin 锁、组件导出与安装配置
├── tools/                # ask-opt、依赖获取与工程检查
├── tests/ir/             # CLI 与前端测试使用的 MLIR 输入
├── tests/fixtures/       # Runtime 使用的 PTX 输入
├── tests/cpp/            # Compiler/Core/Pass/Runtime 断言与独立 SDK 消费测试
└── docs/                 # 接口、设计与工程说明
```

FugaTensor 的 `cpp/` 绑定链接 ASK；图转换、worker 调用、磁盘缓存和编译包校验位于 `src/fugatensor/_ask/`。

`.deps/`、`build/`、`dist/`、虚拟环境和缓存不进入版本库；保留 `cmake/*.lock.json` 与依赖获取脚本。

## 2. 原生 CTest

`ctest --preset core --output-on-failure` 默认运行 CPU 检查，GPU 测试通过 `ASK_TEST_CUDA=ON` 启用。接口示例见[用户 API](用户API.md)。

| CTest 名称 | 入口 | 覆盖范围 |
| --- | --- | --- |
| `ask-core` | `tests/cpp/frontend.cpp` | Core 的静态图准备、形状与优化。 |
| `ask-compiler` | `tests/cpp/compiler.cpp` | 标准 C++ 编译门面、Host/CUDA 代码生成、非法输入拒绝、数值字面量和独立并发上下文。 |
| `ask-primitives` | `tests/cpp/primitives.cpp` | dtype × shape 的逐元素融合、索引变换、归约物化和 matmul 分区；复用 `support/primitive_graphs.h` 生成图。 |
| `ask-pass` | `tests/cpp/pass.cpp` | 按步骤数、字节数、槽位分配、延迟读取与容量生成矩阵，验证整份槽位计划；以全区间两两比较作独立参考。另覆盖公开端口隔离与非法候选。 |
| `ask-runtime` | `tests/cpp/runtime.cpp` | 物理 GPU 上的多步骤 PTX 执行、读前写计划拒绝、内部槽位分配、变动输入、工作区与 Graph 实例复用；仅 `ASK_TEST_CUDA=ON` 时注册。 |
| `ask-matmul` | `tests/cpp/matmul.cpp` | dtype × shape × batch × 转置 × stream/Graph，共 360 组；另检查变址、在途输出、混合步骤、精度与 scratch。要求 GPU 和已启用的 cuBLASLt。 |

```bash
cmake --preset core
cmake --build --preset core
ctest --preset core --output-on-failure

# 有兼容 GPU 的环境中额外执行。
cmake --preset core -DASK_TEST_CUDA=ON
cmake --build --preset core
ctest --preset core -R '^ask-(runtime|matmul)$' --output-on-failure
```

GPU 测试要求可用的驱动和设备；启用后缺少设备按失败处理。

## 3. FugaTensor 接入与端到端验证

[FugaTensor](../../fugatensor/README.md) 是推荐的接入示例：从 [Tensor API](../../fugatensor/docs/API/README.md) 组图，在 Fuga IR 中求导，再经[原生绑定](../../fugatensor/docs/architecture/ASK桥接与多后端执行.md)交给 ASK 编译和调度。

FugaTensor 的端到端测试覆盖图语义、缓存、CPU/CUDA 数值、外部 kernel 和多步骤计划。基础 API 测试从注册表生成算子组合，再与精度、形状和求导阶数交叉；CAI 契约独立交叉 dtype、shape 和 layout；运行和筛选方式见[测试矩阵](../../fugatensor/docs/测试.md)。

数值参考使用 Python 任意精度整数，覆盖单步 RNE、次正规数、整数回绕、饱和转换、大整数、负零、无穷、NaN 和非整块尾元素。新增组合复用该参考和 `plan_matrix`。外部算法公式由生产者测试，ASK 侧检查 ABI、资源寿命和步骤连接。

## 4. SDK 分发验证

SDK 分发检查包括配置构建、默认 CTest、安装到独立目录，以及从安装目录分别使用 Compiler、Runtime、Core。Compiler/Runtime 工程通过公开头文件链接 ASK 共享库；Core 另外配置与 ASK 构建版本匹配的 LLVM/MLIR SDK。

`python3 tools/run_ci_tests.py --build-dir build/core` 运行四个基础套件并检查结果报告，缺少套件或跳过测试均报错。加 `--cuda` 要求 GPU Runtime 套件；加 `--cublaslt` 同时要求 GPU Runtime 和 matmul 套件。

```bash
cmake --install build/core --prefix /path/to/ask-sdk
cmake -S tests/cpp -B /path/to/runtime-consumer -G Ninja \
  -DCMAKE_PREFIX_PATH=/path/to/ask-sdk -DASK_TEST_COMPONENT=Runtime
cmake --build /path/to/runtime-consumer
```

`ASK_TEST_COMPONENT` 可选 `Compiler`（默认）、`Runtime` 或 `Core`。Runtime 可在 CPU 环境构建，执行测试时需要 GPU；`ASK_TEST_CUBLASLT=ON` 增加安装包的矩阵乘法验证。FugaTensor 另行验证 wheel 的绑定、共享库打包和隔离安装。
