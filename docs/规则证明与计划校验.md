# ASK PASS 规则证明与执行计划校验

<a id="plan-proof"></a>

## 1. 逻辑缓冲区可用性

`ASK::Pass` 是 ASK 源码构建中的独立静态库，接口与实现位于 `lib/Pass/`，规则位于 [`rules/pass/`](../rules/pass/)。它调用 [SUKA](https://github.com/fugatensor/suka) 的通用证明接口。执行计划、显存复用和分配槽位的规则由 ASK 维护。

`Session::prepareProgram` 验证步骤索引、单一生产者、端口绑定与 kernel ABI，再为计划建立工作区槽位映射。`checkAllocationPlan` 同时检查映射结构并证明每次读取、公开输出、槽位容量和同槽生存期的可用性。公开输入在首步前可用，步骤输出在该步后可用；[`plan_availability.suka`](../rules/pass/plan_availability.suka) 只为查询所需的缓冲区和步骤边界实例化传递规则。

证明在 Session 锁外执行，返回后重新检查会话状态。只有 `Pass` 会创建 `PreparedProgram`；`Fail` 表示义务未证成，`Unknown` 表示达到推理上限，`Error` 表示规则或输入错误，三者均拒绝计划。每次 `submit` 使用已验证的不可变映射。

<a id="reuse-boundary"></a>

## 2. 整份显存分配计划

ASK 根据每个内部缓冲区的生产步骤与最后读取步骤生成确定性的槽位映射。按生产步骤遍历缓冲区，优先选择已经结束的槽位；同一槽位的上一个缓冲区必须在新缓冲区的生产步骤之前完成最后一次使用。同一步骤的读写不能共用存储。槽位容量取其中所有缓冲区字节数的最大值。

[`allocation_plan.suka`](../rules/pass/allocation_plan.suka) 对每个内部缓冲区验证容量，并对同一槽位中按生产步骤排序的相邻缓冲区验证严格不重叠。映射完整且生产顺序确定时，相邻生存期严格分离可推出该槽位内任意两个生存期不重叠。ASK 检查所有内部缓冲区恰好分配一次、槽位索引有效、公开端口不占内部槽位；任何义务未证成都拒绝整份映射。

每个在途提交持有独立工作区，每个槽位分配一个 `DeviceBuffer`。完成事件保留工作区和缓冲区，事件完成后工作区才能复用。公开输入与输出始终由调用方绑定或由 `run` 单独分配，不参与内部槽位共享。普通启动按单 stream 顺序执行；CUDA Graph 节点按步骤串联。

生存期建立在步骤端口契约上：kernel 只读取声明的 `inputs`，只写入声明的 `outputs`；步骤执行完后不得保留或继续使用端口地址，也不得经端口指针访问未声明的缓冲区。ASK 根据已验证的步骤顺序与大小比较生成事实；SUKA 组合事实并证明规则目标。外部 kernel 的实际访问范围须由其生产者与调用方保证，指针 ABI 本身无法证明这一点。

[`buffer_reuse.suka`](../rules/pass/buffer_reuse.suka) 另提供单个复用候选的策略检查接口。会话分配池仍由 ASK 的对象所有权和完成事件管理；运行时的计划内槽位映射使用整份 `checkAllocationPlan` 校验。

图切分、算子融合和 IR 改写仍由 ASK 的现有优化与切分器决定；其候选合法性规则尚未接入 `ASK::Pass`。

<a id="build-dependency"></a>

## 3. 构建依赖

`cmake/suka.lock.json` 固定 SUKA 仓库地址和提交 SHA。CMake 通过 `FetchContent` 获取通用 `Suka::Pass` 静态库，ASK 的 `ASK::Pass` 静态库包含本仓规则并链接它，`ASK::Runtime` 再吸收两者。`ASK::Pass` 是源码构建目标；已安装的 `ASK::Compiler` 与 `ASK::Runtime` 使用者只链接 ASK SDK。

在本地开发 SUKA 时指定源码目录：

```bash
cmake --preset core -DASK_SUKA_SOURCE_DIR=/path/to/suka
cmake --build --preset core
```
