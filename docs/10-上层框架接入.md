# 上层框架怎样提交 ASK IR

[返回顶层设计：A 层](核心思想.md#ask-a) · [ASK IR 定义](ask-ir/README.md) · [文档目录](README.md)

上层框架负责把自己的图转换为 ASK 操作，并提供外部片段的语义声明和 DSL。当前 Python SDK 把这些对象序列化为 MLIR，再通过子进程调用真实的 `ask-opt`；它不在 Python 中模仿 MLIR 的解析、验证或优化。

## 1. 先跑一个没有外部编译器的图

下面的完整例子生成 `y = (x + 1) * 2`。输入有 10 个 i32 元素，加法和乘法都按模 2³² 运算。显式 `splat` 把标量扩成张量；SDK 不猜广播规则。

```python
from pathlib import Path
from ask import Compiler, Module, TensorType

module = Module()
tensor = TensorType((10,), dtype="i32")
graph = module.graph("main", inputs={"x": tensor}, results=[tensor])

one = graph.splat(graph.constant(1), (10,))
t = graph.add(graph.inputs["x"], one, id="P", value_id="v_t")
two = graph.splat(graph.constant(2), (10,))
y = graph.mul(t, two, id="Q", value_id="v_y")
graph.return_(y)

Path("input.mlir").write_text(module.to_mlir(), encoding="utf-8")
compiler = Compiler("build/core/bin/ask-opt")
prepared = compiler.prepare(module)
print(prepared.ir)
print(prepared.report["shape_snapshot"])
```

`prepare` 接受 `Module` 或已有的 MLIR 文本。它把输入、输出和 JSON 报告放在独立临时目录，用参数数组启动编译器，然后读回结果并清理文件，不经过 shell。没有安装 `ask-opt` 时会报告缺少原生编译器，不会返回模拟结果。

同一个文件也可以直接交给 CLI：

```bash
build/core/bin/ask-opt input.mlir --prepare \
  -o prepared.mlir --report-json report.json
```

`PreparedModule.ir` 是验证和准备后的 ASK IR，`PreparedModule.report` 是编译器返回的 JSON 对象。这个对象没有“已执行”的含义，也不表示外部源码已经编译。

## 2. 在图中放入第三方片段

用 `module.semantics(...)` 声明逻辑输入输出、形状规则与效果，再用 `module.implementation(...)` 注册 DSL 和编译配置。`graph.external(...)` 同时引用这两份声明。语义声明由接入方负责正确提供；验证器检查类型、绑定与声明一致性，不会证明一段任意 DSL 等价于该声明。

```python
dynamic = TensorType((None,), "i32")
scale2 = module.semantics(
    "scale2_i32_v1", inputs=[dynamic], results=[dynamic],
    shape_rule="same_as", shape_operand=0, effects="none",
)
triton_scale2 = module.implementation(
    "triton_scale2", compiler="triton", source=triton_source,
    entry="scale2",
    signature={"t": "*i32", "u": "*i32"},
    source_bindings={"t": "input:0", "u": "output:0"},
    constants={"N": 10, "BLOCK": 128},
    options={"num_warps": 4},
    target={"backend": "cuda", "arch": 80, "warp_size": 32},
    grid=(1, 1, 1),
)
# 在 graph.return_ 之前插入：
u = graph.external(t, semantics=scale2, implementation=triton_scale2,
                   id="F", value_id="v_u")
```

这段是 API 用法片段；包含 DSL 全文和完整 P/F/Q 图的可运行程序是 [framework_frontend.py](../examples/framework_frontend.py)。`source` 必须是源码字符串，当前 SDK 不从 callable 猜源码或捕获变量。`signature` 只列运行参数，`constants` 单独列 constexpr；`source_bindings` 要覆盖每个逻辑输入和输出。

`none` 构建可以执行这个图的 `prepare`：检查符号引用、端口类型、形状和 DSL 描述，并把待编译请求放入报告。这里不会启动 Triton worker。真正编译 DSL 的入口再检查构建允许清单；系统中碰巧安装 Triton 不会自动启用它。外部 F 的 grid、编译选项和执行策略由实现声明给定，准备阶段不为融合重新选择这些参数。

## 3. 形状在哪里变成具体值

`TensorType((None,), "i32")` 表示已知 rank、尚未给出维度的张量。当前原生前端要求函数入口张量的每个维度具体，不能拿结果约束反推未知输入维度。

`same_as` 取指定输入的形状；`fixed` 取语义签名中已经具体的结果形状。默认情况下 SDK 会根据 `same_as` 给 external 填入已知形状；传入 `result_type=TensorType((None,))` 也可以把细化留给 native prepare。此时函数的结果声明须与返回值的当前 MLIR 类型一致，prepare 再一起细化结果与函数签名。

对于 `add`、`mul`，两个输入必须同 rank、同元素类型，已知维度不能冲突。暂时未知的轴由原生前端沿数据流细化；到准备完成时，所有用于计算的张量形状都必须具体。不支持自动广播、符号输入实例化或图级动态控制流。

`shape_snapshot` 保存具体形状和逻辑值身份。它独立于追踪标记：删除所有 `ask.mark` 后，结果仍包含这份快照。

## 4. 可选的标记怎样插入

```python
marked_t = graph.mark(t, mark_id="before_F", role="input", port_id="F.in")
u = graph.external(marked_t, semantics=scale2, implementation=triton_scale2,
                   id="F", value_id="v_u")
marked_u = graph.mark(u, mark_id="after_F", role="output", port_id="F.out")
```

`mark` 返回一个新的 SSA 值，但沿用输入的逻辑 `value_id` 和类型。它不执行 F 的计算，也不会成为需要保留的真实消费者。native prepare 核对逻辑身份和端口连接，把记录写入 `report["markers"]`，再用原值替换标记结果并删除标记。

内部追踪点使用 `role="value"`，可以不填 `port_id`。输入、输出标记必须指向实际连接的端口：单输入/输出可写 `F.in`、`F.out`，多端口使用 `F.in0`、`F.out0` 这样的索引形式。当前输入图的 `mark_id` 必须唯一。

没有标记也可以接入。标记保存的是追踪信息，不替代 `external` 声明、DSL 或调用参数，也不承诺经过外部优化后永久一一对应。完整规则见[标记算子与追踪](ask-ir/01-标记算子与追踪.md)。

## 5. 失败怎样返回框架

```python
from ask import CompilerError

try:
    prepared = compiler.prepare(module)
except CompilerError as error:
    print(error.diagnostics)  # 原生编译器的诊断文本
    print(error.returncode)   # 未启动或超时时可以是 None
```

SDK 对明显的构造错误提前抛出 `TypeError` 或 `ValueError`，例如跨图引用、重复操作 ID、广播请求、返回类型不一致。完整 MLIR 验证仍由原生编译器执行。解析失败、形状冲突、未知输入维度、错误的标记身份等都会终止本次准备，不能把损坏的图作为成功结果交给后端。

`Compiler(..., timeout=60)` 控制子进程超时。成功退出却缺失输出文件、报告不是 JSON 对象等协议错误也会抛出 `CompilerError`。报告内部字段由原生编译器定义，SDK 保留整个字典，方便框架检查新增信息。

## 6. 当前可用范围

| 项目 | 当前行为 |
|---|---|
| Python 客户端 | Python 3.10+，运行时只用标准库；不依赖 NumPy、PyTorch 或 Triton |
| 类型与计算 | i32 标量、rank 已知的 i32 tensor；constant、splat、wrapping add/mul |
| 图 | 单基本块，显式 return；入口形状具体 |
| 外部节点 | 单结果 SDK；语义和 DSL 描述、端口绑定验证；prepare 不编译 DSL |
| 追踪 | identity mark，提取记录后删除；无 runtime 标记 |
| 查询 | `Compiler.capabilities()` 调用 `ask-opt --capabilities` |
| 完整混合图执行 | 尚未实现；没有 GPU 执行或跨编译器融合保证 |

LLVM/MLIR 必须使用当前仓库锁定的同一工具链。原生 LLVM 导入、Triton 导出和 host lowering 的验收与 Python 图准备分开记录；不能仅凭 SDK 测试通过就认定外部 LLIR 已成功读入或运行。

安装、构建与测试命令见[仓库 README](../README.md)。更完整的接口规划见[第三方接入 API](08-第三方LLIR接入API.md)；本页以当前 `python/ask` 与 `ask-opt` 的实现为准。
