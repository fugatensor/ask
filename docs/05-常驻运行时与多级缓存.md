## 1. 动态驱动加载与常驻 `ExecutionSession`

C++ 运行时库 `ask_runtime`（`include/ask/Runtime/CUDA.h`、`lib/Runtime/CUDA.cpp`、`bindings/runtime.cpp`）构建期不依赖 CUDA Toolkit 头文件或 `libcudart.so`：

- **按需 `dlopen("libcuda.so.1")`**：仅在创建 `ExecutionSession` 或调用 GPU 执行接口时动态解析 CUDA Driver API 符号；无 NVIDIA 驱动的机器仍可正常完成 IR 准备、优化与 NVPTX LLVM IR 生成。
- **Primary Context 与非阻塞 Stream**：每个 `ExecutionSession(device=0)` 持有目标显卡的 primary context（`cuDevicePrimaryCtxRetain`）及一条非阻塞 CUDA stream（`CU_STREAM_NON_BLOCKING`）。
- **模块驻留与硬件能力校验**：`kernel.prepare(session)` 校验产物摘要后将 `cubin` 加载为驻留 `CUmodule` / `CUfunction`（同一 `session` 内按 `cubin` 字节及入口名复用，计入 `session.stats["module_hits"]`）。当前要求显卡与目标 `arch` 的主版本相同、次版本不低于目标，并核对 `required_element_types`（如低于 `sm_80` 时拒绝加载含 `bf16` 的模块）。加载后读取 kernel 资源限制，提交时检查线程数与动态共享内存是否超限。

```python
from ask import ExecutionSession

with ExecutionSession(device=0) as session:
    exe = kernel.prepare(session)
    x = session.from_host(values, shape=(2, 8), dtype="f32")
    y = session.tensor((2, 8), "f32")
    for _ in range(100):
        done = exe.submit(x, y)
    done.wait()
    host_out = y.to_host()
```

## 2. `DeviceTensor` 与 `__cuda_array_interface__` 零拷贝互操作

`ExecutionSession` 管理两类设备缓冲区，统一封装为 `DeviceTensor`：

1. **自有显存张量**：通过 `session.tensor(shape, dtype)` 分配，或通过 `session.from_host(values, shape=..., dtype=...)` 分配并拷入；支持空张量（`nbytes == 0`）与 0-D 标量。主机拷贝在返回前等待会话 stream 完成。除 `bf16` 外，`DeviceTensor` 暴露 `__cuda_array_interface__` v3（携带会话 `stream` 指针），可传给支持该协议的外部库。
2. **外部零拷贝借用（`session.from_cuda_array(obj)`）**：消费外部框架或另一 `ExecutionSession` 暴露的 `__cuda_array_interface__`（v2/v3）：
   - 校验 `typestr`（`|b1`、`<i4`、`<i8`、`<f4`、`<f2`）、连续行主序 `strides`、可写属性（作为输出端口时）以及设备归属。`bf16` 没有受支持的 CAI `typestr`，不会把 `uint16` 或 `void` 存储解释为 `bf16`；当前也没有 DLPack 导入导出接口。
   - **跨流同步**：若生产者描述符带有不同于当前会话的 `stream` 句柄，导入和后续访问前会在生产者 stream 上记录 `CUevent` 并在当前会话 stream 上调用 `cuStreamWaitEvent`。没有 `stream` 的 v2 描述必须显式传入 `producer_stream`；传 `None` 表示生产者已完成。外部生产者再次访问同一缓冲区前，调用方仍需等待 ASK 返回的事件或建立等价依赖。
   - **宿主对象保活**：借用的 `DeviceTensor` 持有外部 Python 对象引用；异步提交后，会话的待完成事件列表继续保留该引用。`reap()`、事件查询/等待及后续会话操作观察到事件完成后释放引用，没有后台回收线程。

<a id="async-events"></a>

## 3. 热路径校验、别名防护与异步 `Event`

调用 `exe.submit(in_tensor, out_tensor)` 或多端口 `exe.submit_many(inputs, outputs)` 时：

- **提交前校验**：Python 可执行对象核对各端口的元素类型、形状、字节数及可写性，并要求输出与所有输入及其它输出的显存区间不重叠；输入之间允许共享存储。会话与 C++ 运行时继续核对设备资源归属和启动限制；校验失败不增加 `session.stats["launches"]`。
- **并发提交**：会话内部对驱动状态加互斥锁，阻塞等待期间释放 Python GIL，支持多线程向同一 `ExecutionSession` 提交任务或读取 `session.stats`。
- **显式同步**：`submit` / `submit_many` 入队后返回 `Event`；`event.wait()`、`session.synchronize()` 及主机拷入/拷出操作会等待 GPU 完成。关闭会话（`session.close()` 或退出 `with` 块）会同步在途任务并清理会话持有的资源；仍被张量、kernel 或事件引用的原生资源按其对象生命周期释放。

`CUDAKernel.run(values)` 保留为单输入单输出、同 shape/dtype 的同步列表测试入口；上层框架运行时（如 [FugaTensor 的 `Engine`](../../fugatensor/docs/architecture/04-ASK桥接与多后端执行.md#engine-lifecycle)）使用常驻 `ExecutionSession` 与 `submit_many`。

<a id="two-tier-cache"></a>

## 4. IR 与可执行产物双层持久缓存

`Compiler.compile_cuda(..., cache_dir=...)`（`python/ask/gpu.py`）对编译链路提供两层磁盘缓存：

| 缓存层级 | 命中时跳过的阶段 | 缓存键（SHA-256）输入 | 状态字段 |
| --- | --- | --- | --- |
| **IR Cache** | 自有图优化与 CUDA 降级，或外部 worker 编译、边界校验、LLVM 内联及清理 | 提交的 ASK IR 原文摘要、形状快照、LLVM 修订、目标与编译选项、`ask-opt` / `llc` / `ptxas` 路径与二进制摘要、Python 编排代码指纹；外部路径还包括 DSL、适配器、生产者安装及环境指纹 | `kernel.cache["status"]` / `kernel.report["ir_cache"]` |
| **Executable Cache** | `llc`（LLVM IR → PTX）与 `ptxas`（PTX → `cubin`） | 最终 LLVM IR 摘要、产物契约、端口形状、代码生成参数、`llc` / `ptxas` 路径与二进制摘要、Python 代码生成代码及环境指纹 | `kernel.codegen["executable_cache"]` / `kernel.report["executable_cache"]` |

缓存命中前仍会执行图准备、契约检查和工具指纹计算，外部路径还会探测生产者环境。图键没有去除文本空白或规范化 SSA 名称，语义相同但文本不同的输入可能得到不同缓存项。

缓存写入使用进程/线程锁、临时目录和原子发布，读取时核对清单与每份产物的大小、SHA-256，损坏项会被重建。上层清空内存函数表或重启进程后，在这些键输入不变时仍可命中磁盘缓存；工具路径、二进制、环境或编排实现发生变化时可能重新编译。
